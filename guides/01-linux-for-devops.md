## এই গাইড কীভাবে ব্যবহার করবে

একদম নতুন হলে আগে অধ্যায় ০০ পড়ো। প্রতিটি কমান্ড কার্ডে আছে **নামের মানে**, **কমান্ডটা কী করে**, **sudo লাগবে কিনা**, প্রতিটি অপশনের আলাদা ব্যাখ্যা, একটা **বাস্তব production পরিস্থিতি** যেটা বলে দেয় কখন এটা ব্যবহার করবে, সরাসরি চালানো যায় এমন উদাহরণ, আর একটা **প্রো টিপ** যেটা সাধারণত আসল চাকরিতে মানুষ যে ভুল করে সেটা নিয়ে।

প্রতিটি কার্ডে বেসিক, ইন্টারমিডিয়েট বা অ্যাডভান্সড ট্যাগ আছে। Intermediate candidate হিসেবে বেসিক কার্ডগুলো যেন একদম অভ্যাস হয়ে যায়, ইন্টারমিডিয়েটগুলো একটা টেস্ট VM-এ হাতে-কলমে অনুশীলন করো, আর অ্যাডভান্সডগুলো এমনভাবে বোঝো যাতে ইন্টারভিউতে ব্যাখ্যা করতে পারো। শেষে incident playbook গুলো দেখো: "ওয়েবসাইট down, কী করবে?" ধরনের প্রশ্ন ইন্টারভিউয়াররা খুব পছন্দ করে।

> **নোট:** কমান্ড আর অপশন ইংরেজিতেই থাকবে, কারণ টার্মিনালে ঠিক এভাবেই টাইপ করবে। কোডের `#` comment ইংরেজিতে, তবে প্রতিটি কার্ডের নিচের টেবিলে সব কিছুর বাংলা ব্যাখ্যা আছে।

> ⚠️ **সতর্কতা:** `rm -rf`, `mkfs`, `dd`, `kill -9`, `iptables` আর `--delete`-এর মতো কমান্ড data নষ্ট করতে পারে বা তোমাকে সার্ভার থেকে লক করে দিতে পারে। আগে একটা ফেলে দেওয়ার মতো VM বা container-এ অনুশীলন করো, কখনো প্রথমেই production-এ নয়।

## ০০. শুরুর আগে: টার্মিনালের ভিত্তি

একদম নতুন হলে এই অধ্যায়টা আগে পড়ো। এখানে যা শিখবে, পরের প্রতিটি কমান্ডে সেটা বারবার কাজে লাগবে।

### ০.১ Terminal, Shell আর Prompt কী?

**Terminal** হলো সেই কালো জানালা যেখানে তুমি টাইপ করো। **Shell** (সাধারণত bash) হলো ভেতরের প্রোগ্রাম যেটা তোমার লেখা কমান্ড বুঝে চালায়। সার্ভারে GUI থাকে না, তাই DevOps-এর প্রায় সব কাজ shell-এ করতে হয়। প্রতিটি লাইনের শুরুতে যা দেখো সেটা **prompt**:

```text
rahim@web-prod-01:~$        # সাধারণ user
root@web-prod-01:/etc#      # root user (super user)
```

| চিহ্ন / অংশ | মানে |
|---|---|
| `rahim` | কোন user হিসেবে login আছ |
| `web-prod-01` | সার্ভারের নাম (hostname) |
| `~` বা `/etc` | এখন কোন ফোল্ডারে আছ; `~` মানে তোমার home ফোল্ডার |
| `$` | সাধারণ user |
| `#` | root user। এই চিহ্ন দেখলে সাবধান, এখন তুমি সবকিছু মুছে ফেলার ক্ষমতা রাখো |

### ০.২ একটা কমান্ডের গঠন

প্রায় সব Linux কমান্ড এই ছাঁচে লেখা হয়: **কমান্ড অপশন argument**

```text
ls  -lah  /var/log
|    |      |
|    |      +-- argument: কিসের উপর কাজ করবে (কোন ফোল্ডার)
|    +--------- option/flag: কীভাবে কাজ করবে
+-------------- command: কী কাজ করবে
```

| চিহ্ন / অংশ | মানে |
|---|---|
| `-l` | ছোট (short) অপশন: একটা ড্যাশ, একটা অক্ষর |
| `-lah` | কয়েকটা ছোট অপশন জুড়ে লেখা যায়: `-l -a -h`-এর সমান |
| `--all` | লম্বা (long) অপশন: দুটো ড্যাশ, পুরো শব্দ; `-a` আর `--all` একই কাজ করে |
| `-n 20` | কিছু অপশনের পরে একটা মান দিতে হয় |
| ফাঁকা জায়গা | কমান্ড, অপশন আর argument-এর মাঝে space দিতেই হবে |

Linux-এ বড় হাত আর ছোট হাতের অক্ষর আলাদা। `-f` আর `-F` একদম আলাদা কাজ করে, আর `File.txt` ও `file.txt` দুটো আলাদা ফাইল।

### ০.৩ সাহায্য কোথায় পাবে

```bash
man ls        # manual: ls-এর পুরো বই; q চাপলে বের হবে
ls --help     # ছোট সাহায্য
tldr tar      # উদাহরণসহ সংক্ষিপ্ত সাহায্য (ইনস্টল করতে হয়)
```

| কী | কাজ |
|---|---|
| Tab | অর্ধেক লিখে Tab চাপলে কমান্ড বা ফাইলের নাম নিজে পূর্ণ হয়; দুবার চাপলে বিকল্প দেখায় |
| Up arrow | আগের কমান্ড ফিরে আসে |
| Ctrl+C | চলমান কমান্ড থামাও |
| Ctrl+L | স্ক্রিন পরিষ্কার করো (clear) |
| Ctrl+R | আগের কমান্ডের মধ্যে খোঁজো |

### ০.৪ Path: ফাইলের ঠিকানা

Linux-এ সবকিছু একটা গাছের মতো সাজানো, যার শিকড় হলো `/` (root directory)। Windows-এর মতো C:, D: নেই।

| চিহ্ন / অংশ | মানে |
|---|---|
| `/` | সবকিছুর শুরু (root directory)। root user-এর সাথে গুলিয়ো না |
| `~` | তোমার home ফোল্ডার, যেমন `/home/rahim` |
| `.` | বর্তমান ফোল্ডার; `./deploy.sh` মানে "এই ফোল্ডারের deploy.sh চালাও" |
| `..` | এক ধাপ উপরের ফোল্ডার |
| `/var/log/nginx` | absolute path: `/` দিয়ে শুরু, যেকোনো জায়গা থেকে একই জিনিস বোঝায় |
| `logs/app.log` | relative path: বর্তমান ফোল্ডার থেকে হিসাব |

| ফোল্ডার | কী থাকে |
|---|---|
| `/etc` | configuration ফাইল (nginx, ssh, cron) |
| `/var/log` | log ফাইল |
| `/home` | সাধারণ user-দের ফোল্ডার |
| `/root` | root user-এর home |
| `/opt` | বাইরের বা নিজের বানানো অ্যাপ বসানোর জায়গা |
| `/tmp` | অস্থায়ী ফাইল; reboot-এ মুছে যেতে পারে |
| `/usr/bin` | সাধারণ প্রোগ্রাম (ls, grep) |
| `/proc`, `/sys` | kernel-এর তৈরি নকল ফাইল; সিস্টেমের live তথ্য |
| `/dev` | device ফাইল (disk, terminal)। `/dev/null` হলো "ডাস্টবিন" |

### ০.৫ sudo: super user do

Linux-এ দুই ধরনের user আছে। সাধারণ user শুধু নিজের ফাইল আর নিজের কাজ নিয়ন্ত্রণ করতে পারে। **root** হলো super user, সে সিস্টেমের সবকিছু করতে পারে। নিরাপত্তার জন্য আমরা সবসময় root হিসেবে login করি না। দরকার হলে একটা কমান্ডের সামনে `sudo` লিখি, যার মানে **s**uper **u**ser **do**: "এই একটা কমান্ড super user-এর ক্ষমতা দিয়ে চালাও"। প্রথমবার তোমার নিজের password চাইবে (root-এর নয়)।

```bash
cat /etc/shadow         # Permission denied
sudo cat /etc/shadow    # এবার চলবে
```

**কখন sudo লাগে:**

| পরিস্থিতি | উদাহরণ |
|---|---|
| System ফাইল এডিট | `/etc`-এর ভেতরের config: `sudo nano /etc/nginx/nginx.conf` |
| Software install | `sudo apt install nginx` |
| Service চালানো/থামানো | `sudo systemctl restart nginx` |
| User/group ম্যানেজ | `sudo useradd`, `sudo usermod` |
| অন্যের ফাইল/প্রসেস | `sudo chown`, `sudo kill <অন্য user-এর PID>` |
| Disk, network, firewall | `sudo mount`, `sudo ufw allow 443`, `sudo tcpdump` |
| 1024-এর নিচের port | 80 বা 443-এ listen করতে root অনুমতি লাগে |
| কিছু log পড়া | `sudo tail /var/log/auth.log` |

**কখন sudo লাগে না (এবং দেওয়া উচিত না):** নিজের home-এর ফাইল, `ls`, `cd`, `grep`, `ps`, `df`, `free`, `ping`, `curl`, `ssh`, `git`। অপ্রয়োজনে sudo দিলে ফাইলের owner root হয়ে যায় আর পরে তুমি নিজেই "Permission denied" পাবে।

| কমান্ড | মানে |
|---|---|
| `sudo !!` | আগের কমান্ডটা sudo দিয়ে আবার চালাও; sudo দিতে ভুলে গেলে কাজে লাগে |
| `sudo -i` | পুরো root shell খোলো (# prompt); কাজ শেষে `exit` দাও |
| `sudo -u postgres psql` | root নয়, postgres user হিসেবে চালাও |
| `sudo -l` | তুমি sudo দিয়ে কী কী চালাতে পারো দেখাও |

> ⚠️ **বড় ফাঁদ:** `sudo echo "x" > /etc/file` কাজ করে না। কারণ `>` (redirect) টা sudo করে না, তোমার নিজের shell করে। সঠিক উপায়: `echo "x" | sudo tee /etc/file`

### ০.৬ Pipe ( | ): এক কমান্ডের output আরেক কমান্ডে

`|` চিহ্নটা (keyboard-এ Enter-এর উপরে, Shift চেপে `\`) হলো **pipe**। এটা বাম পাশের কমান্ডের output-কে পাইপের মতো ডান পাশের কমান্ডের input-এ পাঠিয়ে দেয়। ছোট ছোট কমান্ড জুড়ে বড় কাজ করা Linux-এর মূল দর্শন।

```bash
cat access.log | grep " 500 " | wc -l
# ফাইল পড়ো -> 500 error-এর লাইন রাখো -> লাইন গোনো
```

**কখন pipe ব্যবহার করবে:**

| উদ্দেশ্য | উদাহরণ |
|---|---|
| Output ছাঁকতে (filter) | `ps aux \| grep nginx` |
| গুনতে | `ls /etc \| wc -l` |
| সাজাতে / top-N বের করতে | `du -sh /var/* \| sort -rh \| head` |
| লম্বা output পাতায় পাতায় দেখতে | `journalctl \| less` |
| এক কমান্ডের ফল দিয়ে অন্য কমান্ড চালাতে | `docker ps -q \| xargs docker stop` |

**কখন pipe লাগে না বা কাজ করে না:**

| পরিস্থিতি | ব্যাখ্যা |
|---|---|
| কমান্ড নিজেই ফাইল পড়তে পারে | `cat file \| grep error`-এর বদলে সরাসরি `grep error file` লেখো; অপ্রয়োজনীয় cat |
| কমান্ড input পড়ে না | `ls \| rm` কাজ করে না, কারণ rm stdin থেকে নাম নেয় না; এখানে `xargs` লাগে |
| Error output | pipe শুধু সাধারণ output (stdout) পাঠায়, error (stderr) না; দুটোই পাঠাতে: `cmd 2>&1 \| grep x` |
| ফাইলে রাখতে চাইলে | pipe নয়, redirect (`>`) ব্যবহার করো |
| Script-এ fail ধরা | pipe-এ শুধু শেষ কমান্ডের সফলতা গোনা হয়; মাঝেরটা fail ধরতে `set -o pipefail` |

### ০.৭ Redirection: output কোথায় যাবে

প্রতিটি কমান্ডের তিনটা স্রোত থাকে: input (0 = stdin), সাধারণ output (1 = stdout) আর error (2 = stderr)। Redirection দিয়ে এগুলোর দিক বদলানো যায়।

| চিহ্ন / অংশ | মানে |
|---|---|
| `> file` | output ফাইলে লেখো; ফাইল আগে থাকলে পুরো মুছে নতুন করে লেখা হয় |
| `>> file` | ফাইলের শেষে যোগ করো (append); log-এর জন্য এটা |
| `< file` | ফাইলকে input হিসেবে দাও |
| `2> err.log` | শুধু error ফাইলে |
| `2>&1` | error-কেও সাধারণ output-এর সাথে একই জায়গায় পাঠাও |
| `> /dev/null` | output ফেলে দাও (ডাস্টবিনে) |
| `&> file` | bash-এ output + error দুটোই ফাইলে (সংক্ষিপ্ত রূপ) |

```bash
./backup.sh >> /var/log/backup.log 2>&1    # cron-এ সবচেয়ে বেশি দেখা লাইন
```

### ০.৮ কমান্ড জোড়া লাগানো: `&&` `||` `;` `&`

| চিহ্ন / অংশ | মানে |
|---|---|
| `a && b` | a সফল হলে তবেই b চালাও: `nginx -t && systemctl reload nginx` |
| `a \|\| b` | a ব্যর্থ হলে b চালাও: `ping -c1 db \|\| echo "DB down"` |
| `a ; b` | ফলাফল যাই হোক, পরপর দুটোই চালাও |
| `a &` | a-কে background-এ চালাও, terminal সাথে সাথে ফেরত পাও |
| `$?` | শেষ কমান্ডের exit code। 0 = সফল, অন্য যেকোনো সংখ্যা = ব্যর্থ |

### ০.৯ Wildcard, Variable আর Quote

| চিহ্ন / অংশ | মানে |
|---|---|
| `*` | যেকোনো কিছু, যত অক্ষরই হোক; `*.log` = `.log` দিয়ে শেষ সব ফাইল |
| `?` | ঠিক একটা যেকোনো অক্ষর; `app?.log` = app1.log, app2.log |
| `{a,b}` | brace expansion: `file.{txt,bak}` = file.txt file.bak |
| `$VAR` | variable-এর মান: `echo $HOME` |
| `$(command)` | command substitution: ভেতরের কমান্ড চালিয়ে তার output এখানে বসাও: `echo $(date)` |
| `"..."` | double quote: ভেতরে `$VAR` কাজ করে, কিন্তু space-এ ভাঙে না |
| `'...'` | single quote: ভেতরের সবকিছু হুবহু লেখা, `$VAR`-ও না |
| `\` | পরের অক্ষরের বিশেষ অর্থ বাদ দাও; লাইনের শেষে দিলে কমান্ড পরের লাইনে চলবে |
| `# ...` | comment: shell এটা উপেক্ষা করে |

```bash
NAME="Rahim"
echo "Hello $NAME"    # Hello Rahim
echo 'Hello $NAME'    # Hello $NAME
```

### ০.১০ `ls -l`-এর output পড়তে শেখো

```text
-rwxr-xr--  1  deploy  www-data  4.0K  Oct 6 14:30  deploy.sh
```

| অংশ | মানে |
|---|---|
| `-` | ফাইলের ধরন: `-` = সাধারণ ফাইল, `d` = ফোল্ডার, `l` = symlink |
| `rwx` | owner-এর অনুমতি: r = read (পড়া), w = write (লেখা), x = execute (চালানো) |
| `r-x` | group-এর অনুমতি: পড়া আর চালানো, লেখা না |
| `r--` | others (বাকি সবাই): শুধু পড়া |
| `deploy` | owner (মালিক) |
| `www-data` | group |
| `4.0K` | size |
| `Oct 6 14:30` | শেষ কবে বদলেছে |

সংখ্যায়: r = 4, w = 2, x = 1। তিনটা যোগ করে প্রতিটি দলের জন্য একটা অঙ্ক হয়। উপরের `rwxr-xr--` = 7, 5, 4 = **754**।

### ০.১১ অপশনের অক্ষরগুলো সাধারণত কী বোঝায়

প্রতিটি ছোট অপশন আসলে একটা ইংরেজি শব্দের প্রথম অক্ষর। শব্দটা জানলে অপশন মুখস্থ করতে হয় না, নিজেই বুঝে যাবে। তবে মনে রাখো, একই অক্ষর আলাদা কমান্ডে আলাদা মানে হতে পারে (যেমন `rm -r` = recursive, কিন্তু `sort -r` = reverse)। নিচে সবচেয়ে কমন গুলো:

| অপশন | সাধারণ পূর্ণরূপ ও মানে |
|---|---|
| `-a` | all (সব) বা append (শেষে যোগ) বা archive (হুবহু কপি) |
| `-c` | count (গোনা) বা create (বানাও) বা check (পরীক্ষা) |
| `-d` | directory (ফোল্ডার) বা delimiter (বিভাজক) বা decode বা debug |
| `-e` | every (সব) বা expression বা edit |
| `-f` | force (জোর করে) বা file (ফাইল) বা follow (অনুসরণ) বা full |
| `-h` | human-readable (পড়ার মতো size) বা help |
| `-i` | interactive (জিজ্ঞেস করবে) বা ignore case বা in-place বা identity/interface |
| `-l` | long (বিস্তারিত) বা list (তালিকা) বা lines (লাইন) বা listen |
| `-n` | number (সংখ্যা) বা numeric (নামের বদলে সংখ্যা) বা no |
| `-o` | output (কোথায় বা কোন format-এ) |
| `-p` | parents বা port বা PID বা process |
| `-q` | quiet (চুপচাপ) |
| `-r` / `-R` | recursive (ভেতরের সবকিছু) বা reverse (উল্টো) বা remove |
| `-s` | silent বা summary বা size বা shell |
| `-t` | time বা type বা TCP বা target বা test |
| `-u` | user বা UDP বা unit বা unified |
| `-v` | verbose (বিস্তারিত বলো) বা invert (grep-এ) |
| `-x` / `-z` | extract (খোলো) / gzip (সংকোচন) বা zero |
| `-y` | yes (সব প্রশ্নে হ্যাঁ) |

### ০.১২ এই গাইডের কার্ড কীভাবে পড়বে

প্রতিটি কার্ডের শুরুতে **পূর্ণরূপ** (যেমন `cd` = **C**hange **D**irectory, বড় হাতের অক্ষরগুলো দিয়েই নাম তৈরি), তারপর **কী করে**, **বাস্তব পরিস্থিতি** (কখন ব্যবহার করবে), **sudo লাগবে?**, কোড, তারপর **অপশনের পূর্ণরূপ** টেবিলে প্রতিটি অপশনের প্রতিটি অক্ষর আলাদা করে (যেমন `-lah` = l + a + h), তারপর **আরও ব্যাখ্যা** টেবিলে চিহ্ন ও কৌশল, আর শেষে **প্রো টিপ**। কোডের ভেতরের `#` comment গুলো ইংরেজিতে রাখা হয়েছে, তাদের বাংলা ব্যাখ্যা নিচের টেবিলে পাবে।

## ০১. ফাইল, ডিরেক্টরি ও নেভিগেশন

সব DevOps কাজ এখান থেকেই শুরু: deployment খোঁজা, config-এর backup নেওয়া, disk পরিষ্কার করা আর release ম্যানেজ করা।

### ls

`🟢 বেসিক`

**পূর্ণরূপ:** `ls` = **L**i**S**t → তালিকা দেখাও

**কী করে:** ডিরেক্টরির ভেতরের ফাইল দেখায়, সাথে permission, size আর সময়।

> **বাস্তব পরিস্থিতি:** Deployment শেষ হয়েছে, কিন্তু অ্যাপ এখনও পুরনো ভার্সন দেখাচ্ছে। তুমি সার্ভারে SSH করে দেখছ নতুন release ফোল্ডারটা আসলে তৈরি হয়েছে কিনা, আর কোনটা সবচেয়ে নতুন।

**sudo লাগবে?** সাধারণত লাগে না। শুধু root-এর ফোল্ডার (যেমন `/root`) দেখতে লাগে।

```bash
ls -lah /var/www/app/releases/          # long list, human sizes, hidden files
ls -lt /var/www/app/releases/ | head    # newest first
ls -ld /var/www/app                     # info about the dir itself, not contents
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-lah` | `l` = long → লম্বা বিবরণ (permission, owner, size, তারিখ সহ) · `a` = all → সব, নামের শুরুতে `.` থাকা hidden ফাইলসহ · `h` = human-readable → মানুষের পড়ার মতো size (K, M, G) |
| `-lt` | `l` = long → লম্বা বিবরণ · `t` = time → সময় ধরে সাজাও, নতুন আগে |
| `-ld` | `l` = long → লম্বা বিবরণ · `d` = directory → ফোল্ডারের ভেতরে না ঢুকে ফোল্ডারটার নিজের তথ্য |
| `\| head` | head → মাথা, প্রথম ১০ লাইন দেখায় |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `ls` | শুধু ls দিলে বর্তমান ফোল্ডারের ফাইলের নাম দেখায় |
| `-l` | long format: প্রতিটি ফাইলের permission, owner, group, size আর তারিখ আলাদা কলামে দেখায় |
| `-a` | all: নামের শুরুতে `.` (ডট) থাকা hidden ফাইলও দেখায়, যেমন `.env`, `.git` |
| `-h` | human-readable: size-কে 4096-এর বদলে 4.0K, 1.2M, 3G এভাবে দেখায়; `-l`-এর সাথে কাজে লাগে |
| `-lah` | `-l`, `-a`, `-h` তিনটা অপশন একসাথে লেখা; ছোট অপশন এভাবে জোড়া লাগানো যায় |
| `-t` | time: সবচেয়ে নতুন modify হওয়া ফাইল আগে দেখায় |
| `\| head` | pipe: ls-এর output সরাসরি head কমান্ডে পাঠায়; head শুধু প্রথম ১০ লাইন দেখায়, তাই সবচেয়ে নতুন ১০টা পাবে |
| `-d` | directory: ফোল্ডারের ভেতরের জিনিস নয়, ফোল্ডারটার নিজের তথ্য দেখায় (তার permission, owner) |
| `# ...` | `#`-এর পরের লেখা comment; shell এটা উপেক্ষা করে, শুধু বোঝানোর জন্য লেখা |

> 💡 **প্রো টিপ:** `ls -ltr` দিলে সবচেয়ে নতুন ফাইলটা একদম নিচে, তোমার prompt-এর ঠিক উপরে দেখাবে।

### cd / pwd

`🟢 বেসিক`

**পূর্ণরূপ:** `cd` = **C**hange **D**irectory → ফোল্ডার বদলাও · `pwd` = **P**rint **W**orking **D**irectory → এখন যে ফোল্ডারে আছি সেটা দেখাও

**কী করে:** এক ডিরেক্টরি থেকে আরেকটায় যাওয়া আর তুমি এখন কোথায় আছ সেটা দেখা।

> **বাস্তব পরিস্থিতি:** 502 error ডিবাগ করার সময় তুমি বারবার `/etc/nginx/sites-available` (config) আর `/var/log/nginx` (log)-এর মধ্যে আসা-যাওয়া করছ, আর কোথায় আছ সেটা গুলিয়ে ফেলছ।

**sudo লাগবে?** লাগে না। `sudo cd` কাজই করে না, কারণ cd হলো shell-এর নিজস্ব (built-in) কমান্ড। Root ফোল্ডারে ঢুকতে হলে `sudo -i` দিয়ে root shell খুলতে হয়।

```bash
cd /etc/nginx/sites-available
cd /var/log/nginx
cd -        # jump back to the previous directory
pwd         # print current directory
cd ~        # home directory
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-` | previous → আগের ফোল্ডার |
| `~` | home → তোমার home ফোল্ডার |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `cd /path` | নির্দিষ্ট path-এ যাও; `/` দিয়ে শুরু মানে absolute path (একদম root থেকে) |
| `cd -` | আগের ফোল্ডারে ফিরে যাও, যেমন TV remote-এর "previous channel" |
| `cd ~` | `~` মানে তোমার home ফোল্ডার (`/home/তোমার_নাম`); শুধু `cd` দিলেও home-এ যায় |
| `cd ..` | এক ধাপ উপরের (parent) ফোল্ডারে যাও |
| `pwd` | বর্তমান ফোল্ডারের পুরো path দেখায় |
| `\|\| exit 1` | `\|\|` মানে "আগেরটা fail করলে এটা চালাও"; cd fail করলে script বন্ধ হবে |

> 💡 **প্রো টিপ:** Script-এ সবসময় absolute path বা `cd /path || exit 1` ব্যবহার করো, যাতে cd fail করলে script ভুল ডিরেক্টরিতে কমান্ড না চালায়।

### mkdir

`🟢 বেসিক`

**পূর্ণরূপ:** `mkdir` = **M**a**K**e **DIR**ectory → ফোল্ডার বানাও

**কী করে:** ডিরেক্টরি তৈরি করে, একবারে nested অনেকগুলো ফোল্ডারও।

> **বাস্তব পরিস্থিতি:** নতুন সার্ভারে Capistrano-style deployment layout বানাচ্ছ: releases, shared logs আর shared config ফোল্ডার।

**sudo লাগবে?** নিজের home-এ লাগে না। `/opt`, `/etc`, `/var`-এর মতো system ফোল্ডারে বানাতে লাগে: `sudo mkdir -p /opt/app`

```bash
mkdir -p /opt/app/{releases,shared/logs,shared/config}
mkdir -m 750 /opt/app/secrets      # create with specific permissions
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-p` | `p` = parents → মাঝের (parent) ফোল্ডার না থাকলে সেগুলোও বানাও |
| `-m` | `m` = mode → permission (mode) সেট করো, যেমন 750 |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-p` | parents: মাঝের ফোল্ডার না থাকলে সেটাও বানায়, আর আগে থেকে থাকলে error দেয় না |
| `{releases,shared/logs,...}` | brace expansion: shell এটাকে কয়েকটা আলাদা path-এ ভেঙে দেয়; একটা কমান্ডেই অনেকগুলো ফোল্ডার তৈরি হয় |
| `-m 750` | mode: তৈরি হওয়ার সময়ই permission 750 সেট করে (owner সব, group পড়া/ঢোকা, অন্যরা কিছু না) |

> 💡 **প্রো টিপ:** `-p` দিলে ফোল্ডার আগে থেকে থাকলেও error দেয় না, তাই বারবার চালানো যায় এমন (idempotent) provisioning script-এর জন্য নিরাপদ।

### cp

`🟢 বেসিক`

**পূর্ণরূপ:** `cp` = **C**o**P**y → কপি করো

**কী করে:** ফাইল ও ডিরেক্টরি কপি করে।

> **বাস্তব পরিস্থিতি:** Production-এর nginx.conf এডিট করার আগে তারিখসহ একটা backup নিতে হবে, যাতে nginx reload fail করলে কয়েক সেকেন্ডে আগের অবস্থায় ফিরতে পারো।

**sudo লাগবে?** `/etc`-এর মতো system ফাইল কপি করতে বা সেখানে লিখতে লাগে: `sudo cp -a ...`

```bash
cp -a /etc/nginx/nginx.conf /etc/nginx/nginx.conf.bak.$(date +%F-%H%M)
cp -r /opt/app/config /tmp/config-backup      # recursive copy
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-a` | `a` = archive → হুবহু কপি, permission, owner, সময় সব ঠিক রেখে |
| `-r` | `r` = recursive → ফোল্ডারের ভেতরের সবকিছুসহ |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `cp উৎস গন্তব্য` | প্রথমটা কোন ফাইল, দ্বিতীয়টা কোথায় কপি হবে |
| `-a` | archive: permission, owner, timestamp, symlink সব হুবহু রাখে; backup-এর জন্য সেরা |
| `$(date +%F-%H%M)` | command substitution: `$( )`-এর ভেতরের কমান্ড আগে চলে, তার output নামের মধ্যে বসে যায়; ফলে নাম হয় `nginx.conf.bak.2026-10-06-1430` |
| `%F` / `%H` / `%M` | date-এর format: `%F` = বছর-মাস-দিন, `%H` = ঘণ্টা, `%M` = মিনিট |
| `-r` | recursive: ফোল্ডার আর তার ভেতরের সবকিছু কপি করে; ফোল্ডার কপিতে লাগবেই |

> 💡 **প্রো টিপ:** `-a` (archive) ownership, permission আর timestamp ঠিক রাখে। শুধু cp দিলে owner root হয়ে যেতে পারে আর service ভেঙে যেতে পারে।

### mv

`🟢 বেসিক`

**পূর্ণরূপ:** `mv` = **M**o**V**e → সরাও বা নাম বদলাও

**কী করে:** ফাইল সরায় বা নাম বদলায়; একই filesystem-এ rename atomic হয়।

> **বাস্তব পরিস্থিতি:** একটা config generator `app.conf.tmp` লেখে। তুমি চাও service যেন কখনো অর্ধেক লেখা ফাইল না পড়ে, তাই temp ফাইলে লিখে atomic ভাবে আসল ফাইলের জায়গায় বসাচ্ছ।

**sudo লাগবে?** System ফোল্ডারে (`/etc/myapp`) ফাইল সরাতে লাগে।

```bash
generate_config > /etc/myapp/app.conf.tmp
mv /etc/myapp/app.conf.tmp /etc/myapp/app.conf     # atomic replace
mv -n old.log archive/                             # -n: never overwrite an existing file
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-n` | `n` = no-clobber → আগে থাকা ফাইল overwrite করবে না |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `mv পুরনো নতুন` | একই ফোল্ডারে দিলে নাম বদলায়, অন্য ফোল্ডারে দিলে সরায় |
| `generate_config > file` | উদাহরণের একটা কাল্পনিক কমান্ড; `>` মানে output টা ফাইলে লেখো (redirect) |
| `-n` | no-clobber: গন্তব্যে একই নামের ফাইল থাকলে overwrite করবে না |

> 💡 **প্রো টিপ:** Atomic mv শুধু একই filesystem-এর ভেতরে কাজ করে। আলাদা mount-এ গেলে সেটা copy + delete হয়ে যায়।

### rm

`🟢 বেসিক`

**পূর্ণরূপ:** `rm` = **R**e**M**ove → মুছে ফেলো · `xargs` = e**X**tended **ARG**ument**S** → input থেকে argument বানাও

**কী করে:** ফাইল ও ডিরেক্টরি মুছে ফেলে।

> **বাস্তব পরিস্থিতি:** releases ফোল্ডারে আজ পর্যন্ত সব deployment জমা আছে আর disk ভরে যাচ্ছে। তুমি শুধু সবচেয়ে নতুন ৫টা release রাখবে।

**sudo লাগবে?** অন্য user বা root-এর ফাইল মুছতে লাগে। `sudo rm -rf` অত্যন্ত বিপজ্জনক, দুবার path দেখে নিও।

```bash
ls -1dt /opt/app/releases/* | tail -n +6 | xargs -r rm -rf
rm -i important.conf       # ask before deleting
rm -rf /tmp/build-*        # force, recursive
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `ls -1dt` | `1` = one per line → প্রতি লাইনে একটা · `d` = directory → ফোল্ডারের ভেতরে ঢুকো না · `t` = time → নতুন আগে |
| `tail -n +6` | `n` = number of lines → লাইনের সংখ্যা, `+6` মানে ৬ নম্বর লাইন থেকে শেষ পর্যন্ত |
| `xargs -r` | `r` = no-run-if-empty → input খালি হলে কিছু চালাবে না |
| `rm -rf` | `r` = recursive → ফোল্ডারের ভেতরের সব · `f` = force → জিজ্ঞেস করবে না, error দেবে না |
| `rm -i` | `i` = interactive → প্রতিটি ফাইলের আগে জিজ্ঞেস করবে |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `ls -1dt .../*` | `-1` = প্রতি লাইনে একটা, `-d` = ফোল্ডারের ভেতরে না ঢুকে নামটাই, `-t` = নতুন আগে; `*` মানে সব ফাইল/ফোল্ডার |
| `\| tail -n +6` | ৬ নম্বর লাইন থেকে শেষ পর্যন্ত দেখাও; অর্থাৎ প্রথম ৫টা (নতুন ৫টা) বাদ |
| `\| xargs -r rm -rf` | xargs আগের তালিকাটা rm-এর argument বানিয়ে দেয়; `-r` মানে তালিকা খালি হলে কিছু চালাবে না |
| `-r` | recursive: ফোল্ডার আর তার ভেতরের সব মুছবে |
| `-f` | force: জিজ্ঞেস করবে না, ফাইল না থাকলেও error দেবে না |
| `-i` | interactive: প্রতিটি ফাইল মোছার আগে y/n জিজ্ঞেস করবে; নিরাপদ |
| `build-*` | wildcard: `build-` দিয়ে শুরু সব নাম |

> 💡 **প্রো টিপ:** `set -u` ছাড়া script-এ কখনো `rm -rf $DIR/` চালাবে না। DIR খালি হলে আসলে `rm -rf /` চলে যাবে।

### ln

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `ln` = **L**i**N**k → লিংক বানাও · `readlink` = READ LINK → লিংক কোথায় যায় পড়ো

**কী করে:** Hard link বা symbolic link তৈরি করে।

> **বাস্তব পরিস্থিতি:** Zero-downtime deployment: nginx `/opt/app/current` থেকে সার্ভ করে। তুমি নতুন release ফোল্ডারে deploy করে `current` symlink টা বদলে দাও। Rollback মানে শুধু symlink আগের জায়গায় ফিরিয়ে দেওয়া।

**sudo লাগবে?** `/opt`-এর মতো root-এর ফোল্ডারে link বানাতে লাগে।

```bash
ln -sfn /opt/app/releases/20261006-1430 /opt/app/current
readlink -f /opt/app/current      # which release is live?
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-sfn` | `s` = symbolic → symbolic link (shortcut-এর মতো) · `f` = force → আগের link থাকলে সরিয়ে দাও · `n` = no-dereference → আগের symlink-এর ভেতরে না ঢুকে সেটাকেই বদলাও |
| `readlink -f` | `f` = canonicalize (follow) → সব link অনুসরণ করে আসল পুরো path দেখাও |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-s` | symbolic link বানায়; `-s` না দিলে hard link হয় |
| `-f` | force: একই নামে আগে থেকে link থাকলে সরিয়ে নতুনটা বসায় |
| `-n` | আগের symlink টাকে ফোল্ডার না ভেবে সাধারণ ফাইলের মতো ধরে replace করে |
| `উৎস গন্তব্য` | প্রথমটা আসল ফোল্ডার, দ্বিতীয়টা link-এর নাম (`current`) |
| `readlink -f` | Symlink আসলে কোন আসল path-এ যাচ্ছে সেটা পুরোটা দেখায় |

> 💡 **প্রো টিপ:** `-n` থাকলে আগের symlink-কে ফাইলের মতো ধরে replace করে, ভেতরে নতুন link বানিয়ে ফেলে না।

### find

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `find` = FIND → খুঁজে বের করো

**কী করে:** নাম, size, বয়স, type, permission, owner দিয়ে ফাইল খোঁজে আর তাদের উপর কাজ করে।

> **বাস্তব পরিস্থিতি:** Monitoring alert দিচ্ছে `/var` ৯৫% ভরা। তোমাকে বড় ফাইলগুলো খুঁজে বের করতে হবে আর ৭ দিনের পুরনো application log মুছতে হবে।

**sudo লাগবে?** নিজের ফোল্ডারে লাগে না। পুরো `/` খুঁজতে sudo দাও, নইলে অনেক "Permission denied" আসবে।

```bash
find / -xdev -type f -size +500M -exec ls -lh {} \; 2>/dev/null
find /var/log/myapp -name "*.log" -mtime +7 -delete
find /var/www -type f -perm 0777          # security audit
find /etc -mmin -60                       # changed in last 60 minutes
find /opt/app -user root -not -path "*/node_modules/*"
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-xdev` | xdev = cross device (না) → অন্য disk বা mount-এ যাবে না |
| `-type f` | type → কী ধরনের জিনিস খুঁজবে · `f` = file → সাধারণ ফাইল (ফোল্ডারের জন্য `d` = directory) |
| `-size +500M` | size → আকার, `+500M` মানে 500 Megabyte-এর বেশি |
| `-exec ... {} \;` | exec = execute → প্রতিটি পাওয়া ফাইলের উপর কমান্ড চালাও |
| `ls -lh` | `l` = long → লম্বা বিবরণ · `h` = human-readable → পড়ার মতো size |
| `-name` | name → ফাইলের নাম মেলাও |
| `-mtime +7` | mtime = modification time → শেষ বদলের সময়, দিনে (+7 = ৭ দিনের বেশি আগে) |
| `-mmin -60` | mmin = modification minutes → শেষ বদলের সময়, মিনিটে (-60 = ৬০ মিনিটের মধ্যে) |
| `-delete` | delete → মুছে ফেলো |
| `-perm` | perm = permission → নির্দিষ্ট permission |
| `-user` | user → owner কে |
| `-not -path` | not → উল্টো (বাদ দাও) · path → এই path-এর সাথে মেলে এমন |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `/` বা `/var/log/myapp` | কোন ফোল্ডার থেকে খোঁজা শুরু হবে |
| `-xdev` | একটা disk/partition-এর বাইরে যাবে না |
| `-type f` | শুধু ফাইল (f); ফোল্ডারের জন্য `-type d` |
| `-size +500M` | 500 MB-এর বড়; `+` মানে বেশি, `-` মানে কম |
| `-exec ls -lh {} \;` | প্রতিটি পাওয়া ফাইলের উপর `ls -lh` চালাও; `{}` = পাওয়া ফাইলের নাম, `\;` = `-exec`-এর শেষ |
| `2>/dev/null` | error message (2)-কে `/dev/null`-এ ফেলে দাও (Linux-এর ডাস্টবিন); স্ক্রিন পরিষ্কার থাকে |
| `-name "*.log"` | নাম `.log` দিয়ে শেষ এমন ফাইল; quote দিতে হয় যাতে shell নিজে `*` বদলে না ফেলে |
| `-mtime +7` | ৭ দিনের বেশি আগে modify হয়েছে |
| `-delete` | পাওয়া ফাইলগুলো মুছে দাও; আগে `-delete` ছাড়া চালিয়ে তালিকা দেখে নিও |
| `-perm 0777` | ঠিক 777 permission আছে এমন ফাইল (সবাই লিখতে পারে = ঝুঁকি) |
| `-mmin -60` | শেষ ৬০ মিনিটের মধ্যে বদলেছে |
| `-user root -not -path` | owner root, কিন্তু node_modules-এর ভেতরের গুলো বাদ |

> 💡 **প্রো টিপ:** `-xdev` দিলে find একটা filesystem-এর মধ্যেই থাকে, `/proc` বা mount করা NFS share ঘাঁটে না।

### stat / file

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `stat` = **STAT**us → ফাইলের অবস্থা · `file` = FILE type → ফাইলের ধরন

**কী করে:** বিস্তারিত metadata (ঠিক কখন modify/change হয়েছে, inode, permission) দেখায় আর ফাইলের ধরন চেনে।

> **বাস্তব পরিস্থিতি:** আজ সকাল থেকে SSH login fail করছে। sshd_config শেষ কখন বদলানো হয়েছে সেটা জেনে config-management run-এর সাথে মিলিয়ে দেখতে চাও।

**sudo লাগবে?** সাধারণত লাগে না; পড়ার অনুমতি নেই এমন ফোল্ডারের ফাইলে লাগে।

```bash
stat /etc/ssh/sshd_config
file deploy.sh          # e.g. 'with CRLF line terminators' -> Windows file!
file /usr/bin/node      # ELF 64-bit, which architecture?
```

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `stat ফাইল` | Access, Modify, Change সময়, size, inode, permission দেখায় |
| `file ফাইল` | ভেতরের content দেখে ধরন বলে: text, script, ELF binary ইত্যাদি |
| CRLF | Windows-এর line ending; Linux-এ script-এর সমস্যা করে |
| ELF 64-bit | Linux-এর executable program-এর format, সাথে architecture (x86-64 বা ARM) |

> 💡 **প্রো টিপ:** Download করা টুল "exec format error" দিলে `file` দিয়ে ARM বনাম x86 binary-এর অমিল ধরা যায়।

## ০২. ফাইল দেখা ও যাচাই করা

Incident-এর সময় log আর config দ্রুত পড়তে পারাটাই মূল দক্ষতা।

### cat

`🟢 বেসিক`

**পূর্ণরূপ:** `cat` = con**CAT**enate → জোড়া লাগাও / দেখাও · `EOF` = **E**nd **O**f **F**ile → ফাইলের শেষ

**কী করে:** ফাইলের কনটেন্ট দেখায় বা heredoc দিয়ে ফাইল তৈরি করে।

> **বাস্তব পরিস্থিতি:** নতুন সার্ভারে কোন OS চলছে দেখতে হবে, তারপর provisioning script থেকে অ্যাপের জন্য একটা environment ফাইল বানাতে হবে।

**sudo লাগবে?** root-only ফাইল পড়তে লাগে (যেমন `sudo cat /etc/shadow`)। `/etc`-এ heredoc দিয়ে লিখতে root shell বা `sudo tee` লাগে।

```bash
cat /etc/os-release
cat <<'EOF' > /etc/myapp/app.env
DB_HOST=db.internal
LOG_LEVEL=info
EOF
```

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `cat ফাইল` | পুরো ফাইল স্ক্রিনে দেখায়; ছোট ফাইলের জন্য ভালো, বড় ফাইলে less ব্যবহার করো |
| `<<'EOF'` | heredoc শুরু: পরের লাইনগুলো EOF না আসা পর্যন্ত input হিসেবে যাবে |
| `> /etc/myapp/app.env` | redirect: output এই ফাইলে লেখো; ফাইল আগে থাকলে পুরো overwrite হবে |
| `EOF` | heredoc শেষ; যেকোনো শব্দ হতে পারে, শুরু আর শেষে একই হতে হবে |

> 💡 **প্রো টিপ:** Heredoc-এর delimiter quote করো (`'EOF'`), তাহলে ভেতরের `$VARIABLE` expand না হয়ে হুবহু লেখা হবে।

### less

`🟢 বেসিক`

**পূর্ণরূপ:** `less` = less (is more) → more কমান্ডের উন্নত রূপ, পাতায় পাতায় দেখাও

**কী করে:** বড় ফাইল পুরোটা memory-তে না তুলে পাতায় পাতায় দেখায়।

> **বাস্তব পরিস্থিতি:** ৪ GB-এর একটা application log-এ প্রথম "OutOfMemoryError" খুঁজতে হবে। Editor-এ খুললে সার্ভার আটকে যাবে।

**sudo লাগবে?** root-এর log ফাইল পড়তে লাগে: `sudo less /var/log/syslog`

```bash
less /var/log/myapp/app.log
# inside less: /OutOfMemory (search)  n (next)  G (end)  g (start)
less +F /var/log/myapp/app.log     # follow mode like tail -f, Ctrl+C to stop
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `+F` | `F` = Follow → নতুন লাইন আসলে live দেখাও |
| `G` / `g` | `G` = Go to end → শেষে যাও · `g` = go to start → শুরুতে যাও |
| `n` / `q` | `n` = next → পরের মিল · `q` = quit → বের হও |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `/শব্দ` | less-এর ভেতরে `/` লিখে শব্দ খোঁজো |
| `n` | পরের মিল (next) |
| `G` / `g` | G = ফাইলের শেষে, g = শুরুতে |
| `+F` | follow mode: নতুন লাইন আসতে থাকলে দেখাতে থাকে; Ctrl+C দিয়ে থামাও |
| `q` | less থেকে বের হও (quit) |

> 💡 **প্রো টিপ:** `less -S` দিলে line wrap বন্ধ হয়, লম্বা log line আর CSV দেখতে খুব সুবিধা।

### head / tail

`🟢 বেসিক`

**পূর্ণরূপ:** `head` = HEAD → মাথা, শুরুর অংশ · `tail` = TAIL → লেজ, শেষের অংশ

**কী করে:** ফাইলের শুরু বা শেষ দেখায়; `tail -f` নতুন লাইন live দেখায়।

> **বাস্তব পরিস্থিতি:** এইমাত্র service restart করেছ, এখন live log দেখে নিশ্চিত হতে চাও যে ঠিকমতো চালু হয়েছে আর traffic পাচ্ছে।

**sudo লাগবে?** `/var/log`-এর কিছু ফাইল শুধু root বা adm group পড়তে পারে, তখন `sudo tail` লাগে।

```bash
tail -f /var/log/nginx/access.log
tail -F /var/log/myapp/app.log      # survives log rotation
tail -n 200 app.log | grep ERROR
head -n 20 data.csv
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-f` | `f` = follow → ফাইলে নতুন লেখা আসলে দেখাতে থাকো |
| `-F` | `F` = Follow + retry → নাম ধরে ফলো করো, rotate হলেও নতুন ফাইল ধরো |
| `-n` | `n` = number of lines → কত লাইন |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-f` | follow: ফাইলে নতুন লাইন যোগ হলেই দেখাতে থাকে; Ctrl+C দিয়ে থামাও |
| `-F` | follow + নাম ধরে রাখা: log rotate হয়ে নতুন ফাইল এলেও সেটাই ফলো করে |
| `-n 200` | শেষ ২০০ লাইন; `head -n 20` = প্রথম ২০ লাইন |
| `\| grep ERROR` | pipe: ওই ২০০ লাইন grep-এ গেল, grep শুধু ERROR থাকা লাইন দেখায় |

> 💡 **প্রো টিপ:** logrotate দিয়ে rotate হওয়া log-এর জন্য `tail -F` (বড় হাতের F) ব্যবহার করো; `-f` পুরনো (নাম বদলানো) ফাইলটাকেই ফলো করতে থাকে।

### wc

`🟢 বেসিক`

**পূর্ণরূপ:** `wc` = **W**ord **C**ount → শব্দ/লাইন গোনা

**কী করে:** লাইন, শব্দ আর byte গোনে।

> **বাস্তব পরিস্থিতি:** ম্যানেজার জানতে চাইছে আজ সাইটে কতগুলো request এসেছে। access.log-এর প্রতিটি লাইন একটা request।

**sudo লাগবে?** Log ফাইল root-এর হলে sudo লাগে।

```bash
wc -l /var/log/nginx/access.log
grep -c " 500 " /var/log/nginx/access.log     # count lines matching
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `wc -l` | `l` = lines → লাইন গোনা |
| `grep -c` | `c` = count → মিলে যাওয়া লাইনের সংখ্যা |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-l` | lines: শুধু লাইনের সংখ্যা |
| `grep -c` | count: মিলে যাওয়া লাইনের সংখ্যা দেয় |
| `" 500 "` | দুপাশে space দেওয়া যাতে 1500 বা 5000-এর মতো সংখ্যা ভুল করে না মেলে |

> 💡 **প্রো টিপ:** `grep -c`, `grep | wc -l`-এর চেয়ে দ্রুত আর পড়তেও সহজ।

### diff

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `diff` = **DIFF**erence → পার্থক্য দেখাও

**কী করে:** দুটো ফাইল লাইন ধরে তুলনা করে।

> **বাস্তব পরিস্থিতি:** Staging-এ সব ঠিক চলছে কিন্তু production-এ কিছু route 404 দিচ্ছে। দুই সার্ভারের nginx config ফাইল কপি না করেই তুলনা করতে চাও।

**sudo লাগবে?** সাধারণত লাগে না।

```bash
diff -u staging.conf prod.conf
diff <(ssh web1 cat /etc/nginx/nginx.conf) <(ssh web2 cat /etc/nginx/nginx.conf)
diff -rq dir1/ dir2/        # which files differ in two trees
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-u` | `u` = unified → একীভূত format, `+` আর `-` চিহ্নে পার্থক্য |
| `-rq` | `r` = recursive → ফোল্ডারের ভেতরের সব · `q` = quiet (brief) → শুধু কোন ফাইল আলাদা সেটা বলো |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-u` | unified format: `-` চিহ্ন = প্রথম ফাইলে আছে, `+` চিহ্ন = দ্বিতীয় ফাইলে আছে |
| `<( ... )` | process substitution: কমান্ডের output-কে অস্থায়ী ফাইলের মতো ব্যবহার করে |
| `ssh web1 cat ...` | web1 সার্ভারে গিয়ে ফাইলটা পড়ে এনে দেয় |
| `-rq` | `-r` = ফোল্ডারের ভেতরে সব, `-q` = শুধু কোন ফাইল আলাদা সেটা বলো, বিস্তারিত না |

> 💡 **প্রো টিপ:** `<( )` হলো process substitution: এতে কমান্ডের output-কে ফাইলের মতো diff করা যায়।

## ০৩. টেক্সট প্রসেসিং ও লগ অ্যানালাইসিস

grep, awk আর sed কাঁচা log-কে উত্তরে পরিণত করে। Interviewer রা এই pipeline গুলো খুব পছন্দ করে।

### grep

`🟢 বেসিক`

**পূর্ণরূপ:** `grep` = **G**lobal **R**egular **E**xpression **P**rint → প্যাটার্ন খুঁজে মিলে যাওয়া লাইন দেখাও

**কী করে:** Pattern দিয়ে টেক্সট খোঁজে।

> **বাস্তব পরিস্থিতি:** User রা বলছে checkout fail করছে। তুমি app log-এ আশেপাশের লাইনসহ exception খুঁজছ, আর DB_HOST কোথায় configure করা আছে সেটাও খুঁজছ।

**sudo লাগবে?** পড়ার অনুমতি না থাকা log-এ লাগে।

```bash
grep -i "error" /var/log/myapp/app.log
grep -A 5 -B 2 "NullPointerException" app.log     # context lines
grep -rn "DB_HOST" /etc/myapp/                    # recursive, line numbers
grep -v "health-check" access.log                 # exclude noise
grep -E '" (5[0-9]{2}) ' access.log               # regex: 5xx errors
grep -l "password" -r /opt/app/config             # only filenames
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-i` | `i` = ignore case → বড়/ছোট হাতের অক্ষর আলাদা ধরবে না |
| `-A 5` | `A` = After → মিলের পরে ৫ লাইন |
| `-B 2` | `B` = Before → মিলের আগে ২ লাইন |
| `-rn` | `r` = recursive → ফোল্ডারের ভেতরের সব ফাইলে · `n` = line number → লাইন নম্বর দেখাও |
| `-v` | `v` = invert match → যেগুলো মেলে না সেগুলো দেখাও |
| `-E` | `E` = Extended regex → উন্নত regular expression |
| `-l` | `l` = files with matches (list) → শুধু ফাইলের নাম |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-i` | ignore case: ERROR, error, Error সব মিলবে |
| `-A 5` / `-B 2` | After/Before: মিলের পরে ৫ লাইন আর আগে ২ লাইনও দেখাও (context) |
| `-r` | recursive: ফোল্ডারের ভেতরের সব ফাইলে খোঁজো |
| `-n` | line number: কোন লাইনে মিলেছে দেখায় |
| `-v` | invert: যেগুলো মেলে না সেগুলো দেখাও (বাদ দেওয়ার জন্য) |
| `-E` | extended regex: জটিল প্যাটার্ন লেখা সহজ হয় |
| `5[0-9]{2}` | 5 তারপর যেকোনো ২টা digit: 500 থেকে 599 |
| `-l` | শুধু ফাইলের নাম দেখাও, লাইন না |

> 💡 **প্রো টিপ:** Traffic বিশ্লেষণের আগে `grep -v` দিয়ে load balancer-এর health-check লাইনগুলো বাদ দাও, noise কমবে।

### awk

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `awk` = **A**ho, **W**einberger, **K**ernighan → তিন স্রষ্টার নামের প্রথম অক্ষর · `uniq` = **UNIQ**ue → অনন্য

**কী করে:** কলাম ভিত্তিক প্রসেসিং: field বের করা, filter, যোগফল আর aggregate।

> **বাস্তব পরিস্থিতি:** সাইট ধীর। সন্দেহ হচ্ছে একটা IP (bot বা scraper) সার্ভারে চাপ দিচ্ছে। nginx access log থেকে top ১০ IP আর কতগুলো 5xx response হয়েছে বের করো।

**sudo লাগবে?** সাধারণত লাগে না।

```bash
awk '{print $1}' access.log | sort | uniq -c | sort -nr | head
awk '$9 >= 500 {count++} END {print count}' access.log
awk '{print $9}' access.log | sort | uniq -c | sort -nr      # status code summary
awk -F: '$3 >= 1000 {print $1}' /etc/passwd                # real users
df -h | awk 'NR>1 && $5+0 > 80 {print $6, $5}'             # disks over 80%
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `uniq -c` | `c` = count → কতবার এসেছে গোনা |
| `sort -nr` | `n` = numeric → সংখ্যা হিসেবে · `r` = reverse → উল্টো, বড় থেকে ছোট |
| `awk -F:` | `F` = Field separator → কলাম আলাদা করার চিহ্ন, এখানে `:` |
| `$1`, `$9` | `$` = field → কলাম নম্বর (১ম, ৯ম) |
| `NR` | Number of Records → এখন কত নম্বর লাইন |
| `END` | end → সব লাইন পড়া শেষ হলে |
| `df -h` | `h` = human-readable → পড়ার মতো size |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `'{print $1}'` | প্রতিটি লাইনের প্রথম কলাম প্রিন্ট করো; কলাম space দিয়ে আলাদা হয় |
| `\| sort \| uniq -c \| sort -nr \| head` | একের পর এক pipe: সাজাও, একই রকম গুলো গোনো, সংখ্যা ধরে বড় থেকে ছোট সাজাও, প্রথম ১০টা দেখাও; খুব জনপ্রিয় চেইন |
| `$9 >= 500` | শর্ত: ৯ নম্বর কলাম (status code) 500 বা বেশি হলে |
| `count++ ... END {print count}` | প্রতি মিলে count এক বাড়াও; সব লাইন শেষে (END) মোট সংখ্যা প্রিন্ট করো |
| `-F:` | field separator `:` (কোলন); `/etc/passwd`-এ কলাম কোলন দিয়ে আলাদা |
| `NR>1` | NR = লাইন নম্বর; প্রথম লাইন (header) বাদ দাও |
| `$5+0 > 80` | "85%"-কে সংখ্যা 85 বানাতে `+0` করা হয়, তারপর 80-এর সাথে তুলনা |

> 💡 **প্রো টিপ:** nginx-এর default combined format-এ `$1` হলো client IP, `$7` হলো path, `$9` হলো status code।

### sed

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `sed` = **S**tream **ED**itor → টেক্সট স্রোতের এডিটর

**কী করে:** Stream editor: find/replace, লাইন মোছা, নির্দিষ্ট অংশ দেখানো, ফাইল সরাসরি এডিট।

> **বাস্তব পরিস্থিতি:** ২০টা সার্ভারে script দিয়ে config ফাইলে অ্যাপের port 8080 থেকে 9090 করতে হবে, আর backup রাখতে হবে।

**sudo লাগবে?** `/etc`-এর ফাইল `-i` দিয়ে এডিট করতে লাগে: `sudo sed -i ...`

```bash
sed -i.bak 's/port: 8080/port: 9090/' /etc/myapp/config.yml
sed -n '1000,1100p' huge.log                  # print only a range of lines
sed -i '/^#/d; /^$/d' clean.conf              # remove comments and blank lines
sed -i 's|/old/path|/new/path|g' app.conf     # | as delimiter for paths
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-i` | `i` = in-place → ফাইলটাই সরাসরি বদলাও |
| `-i.bak` | `i` = in-place → সরাসরি বদলাও, আর পুরনোটা `.bak` নামে রাখো |
| `-n` | `n` = no auto-print (quiet) → নিজে থেকে কিছু প্রিন্ট করো না |
| `s///` | `s` = substitute → বদলাও |
| `g` | `g` = global → লাইনের সব মিল |
| `p` / `d` | `p` = print → প্রিন্ট করো · `d` = delete → মুছে দাও |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-i` | in-place: ফাইলটা সরাসরি বদলে দেয় |
| `-i.bak` | বদলানোর আগে পুরনোটা `.bak` নামে রেখে দেয় |
| `s/পুরনো/নতুন/` | substitute: পুরনো লেখা নতুন দিয়ে বদলাও; প্রতি লাইনে প্রথমটাই বদলায় |
| `g` | global: লাইনের সব মিল বদলাও |
| `-n '1000,1100p'` | `-n` = নিজে থেকে কিছু প্রিন্ট করো না, `p` = শুধু এই রেঞ্জ প্রিন্ট করো |
| `/^#/d; /^$/d` | `^#` = `#` দিয়ে শুরু লাইন, `^$` = খালি লাইন, `d` = delete; `;` দিয়ে দুটো কাজ আলাদা |
| `s\|...\|...\|g` | path-এ `/` থাকে, তাই `/`-এর বদলে `\|`-কে বিভাজক হিসেবে ব্যবহার করা হয়েছে |

> 💡 **প্রো টিপ:** প্রথমে `-i` ছাড়া চালিয়ে দেখো; output stdout-এ আসবে, আসল ফাইল এডিটের আগে যাচাই করতে পারবে।

### cut

`🟢 বেসিক`

**পূর্ণরূপ:** `cut` = CUT → কেটে নাও

**কী করে:** Delimiter বা character position দিয়ে কলাম বের করে।

> **বাস্তব পরিস্থিতি:** Security টিম audit-এর জন্য সার্ভারের সব username আর তাদের login shell-এর তালিকা চাইছে।

**sudo লাগবে?** লাগে না।

```bash
cut -d: -f1,7 /etc/passwd
cut -d',' -f2 users.csv
echo "$GIT_COMMIT" | cut -c1-7      # short commit hash for tags
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-d:` / `-d,` | `d` = delimiter → বিভাজক চিহ্ন (`:` বা `,`) |
| `-f1,7` / `-f2` | `f` = fields → কোন কোন কলাম |
| `-c1-7` | `c` = characters → কোন অক্ষর থেকে কোন অক্ষর |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-d:` | delimiter (বিভাজক) `:` কোলন |
| `-f1,7` | field: ১ আর ৭ নম্বর কলাম |
| `-c1-7` | character: ১ থেকে ৭ নম্বর অক্ষর |
| `echo "$GIT_COMMIT" \|` | variable-এর মান pipe দিয়ে cut-এ পাঠানো হচ্ছে |

> 💡 **প্রো টিপ:** cut একাধিক space-কে একটা delimiter হিসেবে ধরতে পারে না; space দিয়ে আলাদা output-এর জন্য awk ব্যবহার করো।

### sort / uniq

`🟢 বেসিক`

**পূর্ণরূপ:** `sort` = SORT → সাজাও · `uniq` = **UNIQ**ue → duplicate বাদ দাও বা গোনো

**কী করে:** লাইন sort করে আর duplicate গোনে বা বাদ দেয়।

> **বাস্তব পরিস্থিতি:** Website migration-এর পর যেসব URL সবচেয়ে বেশি 404 দিচ্ছে সেগুলো বের করতে চাও, যাতে ভাঙা link ঠিক করা যায়।

**sudo লাগবে?** লাগে না।

```bash
awk '$9==404 {print $7}' access.log | sort | uniq -c | sort -nr | head -20
sort -u hosts.txt              # unique sorted
sort -k5 -h report.txt         # sort by 5th column, human sizes (1K, 2G)
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `uniq -c` | `c` = count → কতবার এসেছে |
| `sort -nr` | `n` = numeric → সংখ্যা হিসেবে · `r` = reverse → বড় থেকে ছোট |
| `sort -u` | `u` = unique → duplicate বাদ |
| `sort -k5` | `k` = key → কোন কলাম ধরে সাজাবে (৫ নম্বর) |
| `sort -h` | `h` = human-numeric → 1K, 2M, 3G বুঝে সাজাও |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `uniq -c` | count: প্রতিটি লাইন কতবার এসেছে সেই সংখ্যা সামনে বসায় |
| `sort -n` | numeric: সংখ্যা হিসেবে সাজায় (নইলে 10 আগে আসে 9-এর) |
| `-r` | reverse: বড় থেকে ছোট |
| `-u` | unique: সাজানোর সময় duplicate বাদ |
| `-k5` | key: ৫ নম্বর কলাম ধরে সাজাও |
| `-h` | human: 1K, 2M, 3G-কে ঠিকমতো তুলনা করে |
| `head -20` | প্রথম ২০ লাইন |

> 💡 **প্রো টিপ:** uniq শুধু পাশাপাশি থাকা duplicate বাদ দেয়, তাই সবসময় আগে sort করো।

### tr

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `tr` = **TR**anslate → অক্ষর বদলাও

**কী করে:** Character বদলায় বা মুছে দেয়।

> **বাস্তব পরিস্থিতি:** এক সহকর্মী Windows-এ deploy.sh লিখেছে। চালালে `/bin/bash^M: bad interpreter` দেখাচ্ছে, কারণ ফাইলে CRLF line ending আছে।

**sudo লাগবে?** লাগে না।

```bash
tr -d '\r' < deploy.sh > deploy_fixed.sh
echo "$ENV" | tr '[:lower:]' '[:upper:]'      # prod -> PROD
cat /proc/1/environ | tr '\0' '\n'           # readable env of a process
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-d` | `d` = delete → এই অক্ষর মুছে দাও |
| `\r` / `\n` / `\0` | `\r` = carriage return → Windows-এর লাইন-শেষ চিহ্ন · `\n` = newline → নতুন লাইন · `\0` = null → শূন্য অক্ষর |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-d '\r'` | delete: `\r` (Windows-এর carriage return অক্ষর) মুছে দাও |
| `< deploy.sh` | input redirect: ফাইলটাকে tr-এর input হিসেবে দাও; tr নিজে ফাইল খুলতে পারে না |
| `[:lower:] [:upper:]` | ছোট হাতের সব অক্ষর বড় হাতের বানাও |
| `'\0' '\n'` | null অক্ষরকে newline বানাও, যাতে প্রতিটি variable আলাদা লাইনে দেখা যায় |

> 💡 **প্রো টিপ:** `dos2unix` ইনস্টল থাকলে সেটাও একই CRLF সমস্যা ঠিক করে।

### xargs

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `xargs` = e**X**tended **ARG**ument**S** → input-কে অন্য কমান্ডের argument বানাও

**কী করে:** Standard input থেকে কমান্ড বানিয়ে চালায়, চাইলে parallel-এ।

> **বাস্তব পরিস্থিতি:** servers.txt ফাইলে ৫০টা hostname আছে, একসাথে ১০টা করে সবগুলোর uptime দ্রুত দেখতে হবে।

**sudo লাগবে?** যে কমান্ড চালাচ্ছ সেটার উপর নির্ভর করে।

```bash
xargs -I{} -P10 ssh -o ConnectTimeout=5 {} 'hostname; uptime' < servers.txt
find /tmp -name "*.tmp" -print0 | xargs -0 rm -f     # safe with spaces
docker ps -q | xargs -r docker stop
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-I{}` | `I` = Insert (replace string) → `{}`-এর জায়গায় প্রতিটি input বসাও |
| `-P10` | `P` = Parallel (max-procs) → একসাথে ১০টা চালাও |
| `ssh -o` | `o` = option → ssh-এর একটা সেটিং দাও (ConnectTimeout) |
| `find -print0` | print0 = print with null → নামের পর null অক্ষর দাও |
| `xargs -0` | `0` = null separated → null দিয়ে আলাদা নাম পড়ো |
| `rm -f` | `f` = force → জোর করে |
| `xargs -r` | `r` = no-run-if-empty → খালি হলে চালাবে না |
| `docker ps -q` | ps = process status → চলমান container · `q` = quiet → শুধু ID |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-I{}` | placeholder: প্রতিটি input লাইন `{}`-এর জায়গায় বসবে |
| `-P10` | parallel: একসাথে ১০টা চালাও |
| `< servers.txt` | ফাইলটা input হিসেবে দাও |
| `-o ConnectTimeout=5` | ssh-কে বলা: ৫ সেকেন্ডে connect না হলে ছেড়ে দাও |
| `-print0` / `-0` | ফাইলনাম null অক্ষর দিয়ে আলাদা করে; নামে space থাকলেও ভাঙবে না |
| `-r` | input খালি হলে কমান্ড চালাবে না |
| `docker ps -q` | `-q` = quiet, শুধু container ID দেখায় |

> 💡 **প্রো টিপ:** `-r` (no-run-if-empty) দিলে কোনো argument না থাকলে কমান্ড চালায় না।

### tee

`🟢 বেসিক`

**পূর্ণরূপ:** `tee` = **T**-shaped pipe → T আকৃতির পাইপ: স্ক্রিন + ফাইল দুদিকে

**কী করে:** Output একসাথে ফাইলে আর স্ক্রিনে লেখে।

> **বাস্তব পরিস্থিতি:** `sudo echo ... >> /etc/hosts` দিলে "Permission denied" আসে, কারণ redirect তোমার নিজের user হিসেবে চলে। আবার একটা script-এর output দেখতে দেখতে log-ও রাখতে চাও।

**sudo লাগবে?** এটাই sudo + ফাইলে লেখার সঠিক উপায়: `echo ... | sudo tee -a /etc/hosts`

```bash
echo "10.0.1.15 db.internal" | sudo tee -a /etc/hosts
./deploy.sh 2>&1 | tee deploy-$(date +%F).log
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-a` | `a` = append → শেষে যোগ করো, মুছবে না |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `sudo tee` | tee root হিসেবে চলে, তাই root-এর ফাইলে লিখতে পারে |
| `-a` | append: ফাইলের শেষে যোগ করো; `-a` না দিলে পুরো ফাইল মুছে নতুন লেখা হবে |
| `2>&1` | error (2)-কেও normal output (1)-এর সাথে মেলাও, যাতে সেটাও log-এ যায় |
| `\| tee deploy.log` | স্ক্রিনে দেখাও এবং একই সাথে ফাইলে রাখো |

> 💡 **প্রো টিপ:** Redirect (`>`) তোমার shell করে, sudo না। tee চলে sudo-এর অধীনে, তাই লিখতে পারে।

### jq

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `jq` = **J**SON **Q**uery → JSON থেকে তথ্য বের করো · `curl` = **C**lient **URL** → web request পাঠাও

**কী করে:** Command line-এ JSON parse, filter আর transform করে।

> **বাস্তব পরিস্থিতি:** CI pipeline-কে health endpoint-এর JSON পড়তে হবে, আর cleanup script-এর জন্য AWS CLI output থেকে সব EC2 instance ID বের করতে হবে।

**sudo লাগবে?** লাগে না। ইনস্টল করতে লাগে: `sudo apt install jq`

```bash
curl -s http://localhost:8080/health | jq -r '.status'
aws ec2 describe-instances | jq -r '.Reservations[].Instances[].InstanceId'
kubectl get pods -o json | jq -r '.items[] | select(.status.phase!="Running") | .metadata.name'
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `curl -s` | `s` = silent → progress বা বাড়তি লেখা দেখাবে না |
| `jq -r` | `r` = raw output → quote ছাড়া আসল লেখা |
| `kubectl -o json` | `o` = output → কোন format-এ output (json) |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `curl -s` | silent: curl-এর progress bar দেখাবে না |
| `-r` | raw: quote ছাড়া আসল লেখা দেয় |
| `'.status'` | JSON-এর status নামের field |
| `.Reservations[].Instances[]` | `[]` মানে array-এর প্রতিটি উপাদানের ভেতরে যাও |
| `select(...)` | শর্ত মিললে রাখো, নইলে বাদ দাও |
| `\|` (jq-এর ভেতরে) | jq-এর নিজস্ব pipe: একটা filter-এর ফল পরেরটায় যায় |

> 💡 **প্রো টিপ:** `-r` দিলে quote ছাড়া raw string আসে; অন্য কমান্ডে value পাঠাতে এটাই দরকার।

## ০৪. পারমিশন ও মালিকানা

"Permission denied" production-এর সবচেয়ে কমন error গুলোর একটা। এগুলো মুখস্থ রাখো।

### chmod

`🟢 বেসিক`

**পূর্ণরূপ:** `chmod` = **CH**ange **MOD**e → permission বদলাও

**কী করে:** ফাইলের permission bit বদলায় (user/group/others-এর জন্য read=4, write=2, execute=1)।

> **বাস্তব পরিস্থিতি:** Jenkins `./deploy.sh` চালাতে গিয়ে "Permission denied" পাচ্ছে। আবার আলাদাভাবে SSH তোমার key "UNPROTECTED PRIVATE KEY FILE" বলে বাতিল করছে।

**sudo লাগবে?** নিজের ফাইলে লাগে না। অন্য user বা root-এর ফাইলে লাগে: `sudo chmod ...`

```bash
chmod +x deploy.sh
chmod 600 ~/.ssh/id_ed25519                   # private key: owner read/write only
chmod 700 ~/.ssh
chmod 644 /var/www/html/index.html
chmod -R u=rwX,g=rX,o= /opt/app               # X: execute only on directories
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `+x` | `x` = execute → চালানোর অনুমতি (`+` যোগ, `-` সরাও) |
| `-R` | `R` = Recursive → ভেতরের সবকিছুতে |
| `u` / `g` / `o` | `u` = user (owner) → মালিক · `g` = group → group · `o` = others → বাকি সবাই |
| `r` / `w` / `x` | `r` = read (4) → পড়া · `w` = write (2) → লেখা · `x` = execute (1) → চালানো |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `+x` | execute (চালানোর) অনুমতি যোগ করো; `-` দিলে সরানো হয় |
| সংখ্যা কীভাবে গুনবে | r = 4, w = 2, x = 1। যোগ করো: 7 = rwx, 6 = rw-, 5 = r-x, 4 = r--, 0 = কিছু না |
| `600` | তিনটা অঙ্ক = owner, group, others। 600 = owner পড়া-লেখা, বাকিরা কিছু না |
| `700` / `644` | 700 = শুধু owner সব পারে; 644 = owner পড়া-লেখা, বাকিরা শুধু পড়া |
| `-R` | recursive: ফোল্ডারের ভেতরের সবকিছুতে |
| `u=rwX,g=rX,o=` | u = user/owner, g = group, o = others; `o=` মানে others কিছুই পাবে না |
| `X` (বড় হাতের) | শুধু ফোল্ডারে বা আগে থেকে executable ফাইলে x দেয় |

> 💡 **প্রো টিপ:** সাধারণত: ফোল্ডার/স্ক্রিপ্টে 755, ফাইলে 644, secret-এ 600। Production-এ কখনো 777 নয়।

### chown

`🟢 বেসিক`

**পূর্ণরূপ:** `chown` = **CH**ange **OWN**er → মালিক বদলাও

**কী করে:** Owner আর group বদলায়।

> **বাস্তব পরিস্থিতি:** User রা ছবি upload করতে পারছে না; app log-এ `/var/www/app/storage`-তে "EACCES: permission denied"। ফাইলগুলো root হিসেবে কপি হয়েছিল, কিন্তু nginx/php চলে www-data হিসেবে।

**sudo লাগবে?** প্রায় সবসময় লাগে, কারণ ফাইলের মালিকানা অন্যকে দেওয়া শুধু root পারে।

```bash
chown -R www-data:www-data /var/www/app/storage
chown deploy: /opt/app/current       # user and that user's default group
ls -l /var/www/app/storage           # verify
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-R` | `R` = Recursive → ভেতরের সবকিছুতে |
| `ls -l` | `l` = long → বিস্তারিত তালিকা |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-R` | ফোল্ডারের ভেতরের সব ফাইলে |
| `www-data:www-data` | user:group। কোলনের আগে owner, পরে group |
| `deploy:` | কোলনের পরে কিছু না দিলে ওই user-এর নিজের default group বসে |

> 💡 **প্রো টিপ:** Service কোন user হিসেবে চলছে দেখতে: `ps aux | grep -E 'nginx|php-fpm'` চালিয়ে প্রথম কলাম দেখো।

### umask

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `umask` = **U**ser file-creation **MASK** → নতুন ফাইলের permission-এর মুখোশ

**কী করে:** নতুন তৈরি ফাইলের default permission mask।

> **বাস্তব পরিস্থিতি:** দুজন deploy user `/opt/shared` শেয়ার করে, কিন্তু একজনের বানানো ফাইল অন্যজন এডিট করতে পারে না, কারণ নতুন ফাইল 644 হয়ে তৈরি হচ্ছে।

**sudo লাগবে?** লাগে না; নিজের session-এর জন্য সেট হয়। `chmod g+s`-এ ফোল্ডারের owner না হলে sudo লাগে।

```bash
umask                    # show current, e.g. 0022
umask 002                # new files 664, dirs 775 (group-writable)
chmod g+s /opt/shared    # setgid: new files inherit the directory group
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `g+s` | `g` = group → group-এর জন্য · `s` = setgid (set group ID) → নতুন ফাইল ফোল্ডারের group পাবে |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `umask` | বর্তমান মান দেখায়, যেমন 0022 (group আর others লিখতে পারবে না) |
| `umask 002` | শুধু others-এর write কাটো, group লিখতে পারবে |
| `g+s` | setgid: এই ফোল্ডারে নতুন ফাইল ফোল্ডারের group পাবে |

> 💡 **প্রো টিপ:** Shared ফোল্ডারে setgid আর umask 002 মিলিয়ে ক্লাসিক "টিম ফোল্ডার" প্যাটার্ন।

### setfacl / getfacl

`🔴 অ্যাডভান্সড`

**পূর্ণরূপ:** `setfacl` = **SET** **F**ile **A**ccess **C**ontrol **L**ist → ACL সেট করো · `getfacl` = **GET** **F**ile **A**ccess **C**ontrol **L**ist → ACL দেখাও

**কী করে:** owner/group/others-এর বাইরে সূক্ষ্ম Access Control List।

> **বাস্তব পরিস্থিতি:** Monitoring agent (user "promtail")-কে `/opt/app/logs` পড়তে দিতে হবে, কিন্তু owner বদলানো বা app group-এ যোগ করা যাবে না।

**sudo লাগবে?** নিজের ফাইল না হলে লাগে।

```bash
setfacl -R -m u:promtail:rX /opt/app/logs
setfacl -d -m u:promtail:rX /opt/app/logs      # default ACL for new files
getfacl /opt/app/logs
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-R` | `R` = Recursive → ভেতরের সবকিছুতে |
| `-m` | `m` = modify → নিয়ম যোগ বা বদলাও |
| `-d` | `d` = default → ভবিষ্যতে তৈরি ফাইলের জন্যও |
| `u:promtail:rX` | `u` = user → কোন user · `r` = read → পড়া · `X` = execute (dirs) → ফোল্ডারে ঢোকা |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-R` | recursive |
| `-m` | modify: নতুন নিয়ম যোগ বা বদল |
| `u:promtail:rX` | user promtail-কে read আর (ফোল্ডারে) execute দাও |
| `-d` | default: পরে তৈরি হওয়া ফাইলেও নিয়মটা বসবে |

> 💡 **প্রো টিপ:** `ls -l`-এ permission-এর শেষে `+` (যেমন `drwxr-x---+`) মানে ACL সেট করা আছে।

### chattr / lsattr

`🔴 অ্যাডভান্সড`

**পূর্ণরূপ:** `chattr` = **CH**ange **ATTR**ibute → attribute বদলাও · `lsattr` = **L**i**S**t **ATTR**ibute → attribute দেখাও

**কী করে:** Filesystem attribute সেট করে, যেমন immutable (`+i`) বা append-only (`+a`)।

> **বাস্তব পরিস্থিতি:** কিছু একটা বারবার `/etc/resolv.conf` overwrite করে DNS ভেঙে দিচ্ছে, তুমি সাময়িকভাবে ফাইলটা লক করছ। আরেকবার root একটা ফাইল মুছতে পারছে না, পরে দেখলে সেটা immutable করা।

**sudo লাগবে?** chattr-এর জন্য লাগে: `sudo chattr +i ...`

```bash
chattr +i /etc/resolv.conf        # even root cannot modify/delete
lsattr /etc/resolv.conf
chattr -i /etc/resolv.conf        # unlock
chattr +a /var/log/audit.log      # append-only log
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `+i` / `-i` | `i` = immutable → অপরিবর্তনীয় (`+` চালু, `-` বন্ধ) |
| `+a` | `a` = append only → শুধু শেষে যোগ করা যাবে |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `+i` | immutable: কেউ (root-ও) বদলাতে বা মুছতে পারবে না |
| `-i` | immutable সরাও |
| `+a` | append-only: শুধু শেষে যোগ করা যাবে, পুরনো লেখা মোছা যাবে না |

> 💡 **প্রো টিপ:** root হয়েও `rm`-এ "Operation not permitted" এলে lsattr দেখো। Attacker রাও malware রক্ষা করতে `+i` ব্যবহার করে।

## ০৫. ইউজার, গ্রুপ ও অ্যাক্সেস

Service account আর least-privilege access ম্যানেজ করা DevOps-এর প্রতিদিনের দায়িত্ব।

### useradd / userdel

`🟢 বেসিক`

**পূর্ণরূপ:** `useradd` = USER ADD → user যোগ করো · `userdel` = USER **DEL**ete → user মোছো

**কী করে:** User account তৈরি বা মুছে ফেলে।

> **বাস্তব পরিস্থিতি:** তোমার Java অ্যাপ চালানোর জন্য login ছাড়া একটা service account দরকার (অ্যাপ কখনো root হিসেবে চালাবে না), আর নতুন টিম মেম্বারের জন্য সাধারণ account।

**sudo লাগবে?** সবসময় লাগে: নতুন user বানানো শুধু root পারে।

```bash
useradd -r -s /usr/sbin/nologin -d /opt/myapp myapp     # system account
useradd -m -s /bin/bash -G sudo rahim                   # human user
userdel -r olduser                                      # remove user and home directory
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-r` | `r` = system (reserved) account → service-এর জন্য account |
| `-s` | `s` = shell → login shell |
| `-d` | `d` = home directory → home ফোল্ডারের path |
| `-m` | `m` = make home → home ফোল্ডার তৈরি করো |
| `-G` | `G` = Groups → অতিরিক্ত group |
| `userdel -r` | `r` = remove home → home ফোল্ডারও মোছো |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-r` | system account: সাধারণ মানুষের জন্য নয়, service-এর জন্য |
| `-s /usr/sbin/nologin` | shell হিসেবে nologin: এই account দিয়ে কেউ login করতে পারবে না |
| `-d /opt/myapp` | home directory-এর path |
| `-m` | home directory আসলেই তৈরি করো |
| `-s /bin/bash` | login shell bash |
| `-G sudo` | অতিরিক্ত group: sudo group-এ থাকলে sudo চালাতে পারবে |
| `userdel -r` | user আর তার home ফোল্ডার দুটোই মুছে দাও |

> 💡 **প্রো টিপ:** Debian/Ubuntu-তে `adduser` হলো interactive, সহজ wrapper।

### usermod

`🟢 বেসিক`

**পূর্ণরূপ:** `usermod` = USER **MOD**ify → user বদলাও

**কী করে:** বিদ্যমান user বদলায়: group, shell, lock/unlock।

> **বাস্তব পরিস্থিতি:** Jenkins pipeline fail করছে: "permission denied while trying to connect to /var/run/docker.sock"। Jenkins-কে docker group-এ থাকতে হবে।

**sudo লাগবে?** সবসময় লাগে।

```bash
usermod -aG docker jenkins
systemctl restart jenkins             # group change needs a new session
usermod -L exemployee                 # lock account
usermod -s /usr/sbin/nologin ftpuser
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-aG` | `a` = append → যোগ করো (আগেরগুলো রেখে) · `G` = Groups → group |
| `-L` | `L` = Lock → account লক |
| `-s` | `s` = shell → login shell বদলাও |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-aG docker` | `-a` = append (যোগ করো), `-G` = group। `-a` ছাড়া দিলে আগের সব group মুছে যায়! |
| `systemctl restart jenkins` | নতুন group কার্যকর করতে service restart |
| `-L` | lock: account লক |
| `-s` | shell বদলাও |

> 💡 **প্রো টিপ:** `-G`-এর সাথে `-a` না দিলে আগের সব secondary group বদলে যায়। এভাবেই অনেকে কাউকে sudo থেকে বের করে ফেলে।

### id / groups / whoami

`🟢 বেসিক`

**পূর্ণরূপ:** `id` = **ID**entity → পরিচয়: uid, gid · `groups` = GROUPS → কোন কোন group · `whoami` = WHO AM I → আমি কে

**কী করে:** Identity, UID/GID আর group membership দেখায়।

> **বাস্তব পরিস্থিতি:** একজন user-কে group-এ যোগ করেছ কিন্তু তারপরও access পাচ্ছে না। চলমান session আসলে কী দেখছে যাচাই করছ।

**sudo লাগবে?** লাগে না। অন্য user হিসেবে পরীক্ষা করতে `sudo -u` লাগে।

```bash
id jenkins
groups
whoami
sudo -u www-data id
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `sudo -u` | `u` = user → এই user হিসেবে চালাও |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `id jenkins` | jenkins-এর uid, gid আর সব group দেখায় |
| `sudo -u www-data id` | `-u` = এই user হিসেবে চালাও; www-data কী দেখে তা জানা যায় |

> 💡 **প্রো টিপ:** Group membership login-এর সময় লোড হয়। নতুন group পেতে `newgrp docker` চালাও বা logout/login করো।

### sudo / visudo

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `sudo` = **S**uper **U**ser **DO** → super user (root)-এর ক্ষমতায় চালাও · `visudo` = VI + SUDOers → sudoers ফাইল vi এডিটরে নিরাপদে খোলো

**কী করে:** অন্য user হিসেবে কমান্ড চালায়; sudoers নিরাপদে এডিট করে।

> **বাস্তব পরিস্থিতি:** CI-এর "deploy" user-কে password ছাড়া nginx restart করতে দিতে হবে, কিন্তু পুরো root access দেওয়া যাবে না।

**sudo লাগবে?** visudo চালাতে sudo লাগে। `sudo -u` দিয়ে root ছাড়া অন্য user হিসেবেও চালানো যায়।

```bash
# /etc/sudoers.d/deploy  (edit with: visudo -f /etc/sudoers.d/deploy)
deploy ALL=(root) NOPASSWD: /usr/bin/systemctl restart nginx

visudo -cf /etc/sudoers.d/deploy      # syntax check
sudo -l -U deploy                      # what can deploy run?
sudo -u postgres psql                  # run as another user
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `visudo -cf` | `c` = check → syntax পরীক্ষা · `f` = file → কোন ফাইল |
| `sudo -l` | `l` = list → কী কী চালাতে পারবে তার তালিকা |
| `-U` | `U` = User → কোন user-এর তালিকা |
| `sudo -u` | `u` = user → কোন user হিসেবে চালাবে |
| `NOPASSWD` | no password → password চাইবে না |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `deploy` | নিয়মটা কোন user-এর জন্য |
| `ALL` | কোন host-এ প্রযোজ্য; ALL = সব জায়গায় |
| `=(root)` | কোন user হিসেবে কমান্ড চালাতে পারবে: root |
| `NOPASSWD:` | password চাইবে না; CI/CD automation-এর জন্য দরকার |
| `/usr/bin/systemctl restart nginx` | শুধু এই নির্দিষ্ট কমান্ড, এর বাইরে কিছু না; এটাই least privilege |
| `visudo -cf` | `-c` = check (syntax ঠিক আছে কিনা), `-f` = কোন ফাইল |
| `sudo -l -U deploy` | `-l` = list, deploy কী কী sudo দিয়ে চালাতে পারে দেখাও |
| `sudo -u postgres psql` | postgres user হিসেবে psql চালাও |

> 💡 **প্রো টিপ:** sudoers-এ syntax ভুল হলে সবাই sudo থেকে লক হয়ে যেতে পারে। সবসময় visudo ব্যবহার করো, এটা save-এর আগে যাচাই করে।

### passwd / chage

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `passwd` = **PASSW**or**D** → password সেট/বদল · `chage` = **CH**ange **AGE** → password-এর বয়স/মেয়াদ বদলাও

**কী করে:** Password সেট করে আর password-এর মেয়াদ নীতি ঠিক করে।

> **বাস্তব পরিস্থিতি:** Compliance audit (ISO 27001) অনুযায়ী প্রতি ৯০ দিনে password expire হতে হবে, আর একটা account-এর অবস্থা দেখতে হবে।

**sudo লাগবে?** নিজের password বদলাতে লাগে না। অন্যের জন্য বা chage-এ লাগে।

```bash
passwd rahim
passwd -l contractor          # lock
chage -M 90 -W 7 rahim        # max 90 days, warn 7 days before
chage -l rahim
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `passwd -l` | `l` = lock → লক করো |
| `chage -M` | `M` = Maximum days → সর্বোচ্চ কত দিন |
| `chage -W` | `W` = Warning days → কত দিন আগে সতর্ক করবে |
| `chage -l` | `l` = list → তথ্য দেখাও (এখানে l মানে list, lock না) |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `passwd -l` | lock: password দিয়ে login বন্ধ |
| `chage -M 90` | Maximum: ৯০ দিন পর password বদলাতেই হবে |
| `-W 7` | Warning: মেয়াদ শেষের ৭ দিন আগে সতর্ক করবে |
| `chage -l` | list: বর্তমান মেয়াদের তথ্য দেখাও (passwd -l-এর l = lock, এখানে l = list; গুলিয়ে ফেলো না) |

> 💡 **প্রো টিপ:** `passwd -l` দিয়ে লক করলেও SSH key দিয়ে login বন্ধ হয় না। Key-ও সরাও বা shell nologin করে দাও।

### w / who / last / lastb

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `w` = **W**ho + what → কে আছে, কী করছে · `who` = WHO → কে login আছে · `last` = LAST logins → শেষ login গুলো · `lastb` = LAST **B**ad logins → ব্যর্থ login গুলো

**কী করে:** এখন কে login আছে আর login-এর ইতিহাস দেখায়, ব্যর্থ চেষ্টাসহ।

> **বাস্তব পরিস্থিতি:** রাতে অদ্ভুত CPU spike হচ্ছে। Security review-তে দেখছ কে, কোথা থেকে login করেছে আর কতবার login fail হয়েছে।

**sudo লাগবে?** lastb-এর জন্য লাগে, কারণ ব্যর্থ login-এর ফাইল শুধু root পড়তে পারে।

```bash
w                       # who is on and what they are running
last -a | head -20
sudo lastb | head       # failed logins
last reboot             # when did the server reboot?
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `last -a` | `a` = address (host) last → host/IP শেষ কলামে দেখাও |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `last -a` | host/IP শেষ কলামে দেখাও |
| `\| head -20` | শুধু সাম্প্রতিক ২০টা |
| `last reboot` | সার্ভার কবে কবে restart হয়েছে |

> 💡 **প্রো টিপ:** Incident-এর সময় `last reboot` দ্রুত বলে দেয় সার্ভার হঠাৎ restart হয়েছিল কিনা।

## ০৬. প্রসেস ম্যানেজমেন্ট

সঠিক প্রসেস খুঁজে বের করা, নিয়ন্ত্রণ করা আর নিরাপদে বন্ধ করা।

### ps

`🟢 বেসিক`

**পূর্ণরূপ:** `ps` = **P**rocess **S**tatus → প্রসেসের অবস্থা

**কী করে:** চলমান প্রসেসের একটা snapshot দেখায়।

> **বাস্তব পরিস্থিতি:** সার্ভারে memory কম। Memory ব্যবহার অনুযায়ী sort করে দেখছ কোন প্রসেস দায়ী।

**sudo লাগবে?** লাগে না; সবার প্রসেস এমনিই দেখা যায়।

```bash
ps aux --sort=-%mem | head
ps -eo pid,ppid,user,%cpu,%mem,etime,cmd --sort=-%cpu | head
ps -ef | grep [j]ava          # [j] trick avoids matching grep itself
ps -fp 1234                   # details for one PID
ps auxf                       # process tree
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `aux` | `a` = all users → সব user-এর · `u` = user-oriented format → CPU%, MEM% সহ বিস্তারিত · `x` = without terminal → terminal ছাড়া চলা প্রসেসও |
| `--sort=-%mem` | sort → সাজাও (`-` মানে বড় থেকে ছোট, %mem = memory %) |
| `-eo` | `e` = every → সব প্রসেস · `o` = output format → কোন কলাম দেখাবে |
| `pid` / `ppid` / `etime` | pid = Process ID → প্রসেস নম্বর · ppid = Parent Process ID → parent-এর নম্বর · etime = elapsed time → কতক্ষণ চলছে |
| `-ef` | `e` = every → সব প্রসেস · `f` = full format → পুরো বিবরণ |
| `-fp` | `f` = full → পুরো বিবরণ · `p` = PID → নির্দিষ্ট PID |
| `auxf` | `f` = forest → গাছের মতো (parent-child) দেখাও |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `aux` | a = সব user-এর, u = user-friendly কলাম (CPU%, MEM%), x = terminal ছাড়া চলা প্রসেসও |
| `--sort=-%mem` | memory ধরে সাজাও; `-` মানে বড় থেকে ছোট |
| `-e` | every: সব প্রসেস |
| `-o pid,ppid,...` | output: কোন কোন কলাম দেখাবে নিজে ঠিক করো; ppid = parent-এর PID, etime = কতক্ষণ চলছে |
| `-ef` | সব প্রসেস, full format |
| `grep [j]ava` | কৌশল: এতে grep কমান্ড নিজে ফলাফলে আসে না |
| `-fp 1234` | নির্দিষ্ট PID-এর full তথ্য |
| `f` | forest: প্রসেস tree আকারে (কে কার child) |

> 💡 **প্রো টিপ:** etime দেখায় প্রসেস কতক্ষণ ধরে চলছে; restart আসলেই হয়েছে কিনা নিশ্চিত হতে কাজে লাগে।

### top / htop

`🟢 বেসিক`

**পূর্ণরূপ:** `top` = TOP processes → সবচেয়ে বেশি resource নেওয়া প্রসেস · `htop` = **H**isham's **TOP** → স্রষ্টা Hisham-এর উন্নত top

**কী করে:** CPU, memory, load আর প্রসেসের live, interactive ভিউ।

> **বাস্তব পরিস্থিতি:** PagerDuty alert: API সার্ভারে CPU 100%। এই মুহূর্তে কোন প্রসেস CPU খাচ্ছে দেখতে top খুলছ।

**sudo লাগবে?** দেখতে লাগে না; top থেকে অন্যের প্রসেস kill করতে লাগে।

```bash
top
# inside top: P = sort by CPU, M = by memory, 1 = per-core view,
#             c = full command, k = kill, q = quit
top -b -n 1 | head -20      # batch mode, for scripts or saving
htop                        # friendlier UI, if installed
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-b` | `b` = batch → batch mode, script/ফাইলের জন্য |
| `-n 1` | `n` = number of iterations → কতবার আপডেট (১ বার) |
| `P` / `M` / `1` / `c` / `k` / `q` | P = Processor → CPU ধরে সাজাও · M = Memory → memory ধরে · 1 = per CPU → প্রতিটি core আলাদা · c = command → পুরো কমান্ড · k = kill → মেরে ফেলো · q = quit → বের হও |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `P` / `M` | CPU / Memory ধরে সাজাও |
| `1` | প্রতিটি CPU core আলাদা দেখাও |
| `c` | পুরো কমান্ড দেখাও |
| `k` / `q` | kill / quit |
| `-b -n 1` | batch mode, একবার চালিয়ে বের হও; script বা ফাইলে রাখার জন্য |

> 💡 **প্রো টিপ:** top-এ `wa` হলো I/O wait। wa বেশি কিন্তু user CPU কম মানে সমস্যা disk-এ, CPU-তে নয়।

### kill / pkill / killall

`🟢 বেসিক`

**পূর্ণরূপ:** `kill` = KILL (send signal) → সিগন্যাল পাঠাও · `pkill` = **P**attern KILL → pattern দিয়ে kill · `killall` = KILL ALL → নাম মেলে এমন সব kill

**কী করে:** প্রসেসকে signal পাঠায় (TERM, KILL, HUP...)।

> **বাস্তব পরিস্থিতি:** একটা Celery worker আটকে আছে, job প্রসেস করছে না। প্রথমে ভদ্রভাবে বন্ধ হতে বলছ, দরকার হলে তবেই জোর করে kill। আবার downtime ছাড়া config reload-ও করছ।

**sudo লাগবে?** নিজের প্রসেসে লাগে না। অন্য user বা root-এর প্রসেসে লাগে।

```bash
kill 4521                           # SIGTERM (15): graceful
kill -9 4521                        # SIGKILL: last resort, no cleanup
kill -HUP $(cat /run/nginx.pid)     # reload config
pkill -f "celery worker"            # match the full command line
killall -u baduser                  # kill all processes of a user
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-9` | `9` = SIGKILL → জোর করে মেরে ফেলো |
| `-HUP` | HUP = HangUP signal → config আবার পড়ো |
| SIGTERM (15) | TERM = TERMinate → ভদ্রভাবে বন্ধ হও (default) |
| `pkill -f` | `f` = full command line → পুরো কমান্ডে মেলাও |
| `killall -u` | `u` = user → এই user-এর সব |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `kill 4521` | 4521 হলো PID। Default signal SIGTERM (15): "ভদ্রভাবে বন্ধ হও" |
| `-9` | SIGKILL: সাথে সাথে জোর করে মেরে ফেলো; শেষ উপায় |
| `-HUP` | hangup signal: অনেক service এটা পেলে config আবার পড়ে |
| `$(cat /run/nginx.pid)` | ফাইল থেকে nginx-এর PID পড়ে kill-কে দেয় |
| `pkill -f` | `-f` = পুরো কমান্ড লাইনে মেলাও, শুধু নামে না |
| `killall -u` | নির্দিষ্ট user-এর সব প্রসেস |

> 💡 **প্রো টিপ:** সবসময় আগে SIGTERM দাও। SIGKILL-এ lock ফাইল থেকে যেতে পারে, data corrupt হতে পারে বা child process অনাথ হয়ে যেতে পারে।

### pgrep

`🟢 বেসিক`

**পূর্ণরূপ:** `pgrep` = **P**rocess **GREP** → প্রসেস খোঁজো

**কী করে:** নাম বা pattern দিয়ে PID খোঁজে।

> **বাস্তব পরিস্থিতি:** তোমার health check script-কে নিশ্চিত হতে হবে অ্যাপ প্রসেস চলছে কিনা, আর তার PID লাগবে।

**sudo লাগবে?** লাগে না।

```bash
pgrep -a java
pgrep -u myapp -f "app.jar" || echo "app is DOWN"
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-a` | `a` = all (list full) → পুরো কমান্ডসহ দেখাও |
| `-u` | `u` = user → এই user-এর |
| `-f` | `f` = full → পুরো কমান্ড লাইনে খোঁজো |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-a` | PID-এর সাথে পুরো কমান্ডও দেখাও |
| `-u myapp` | শুধু myapp user-এর প্রসেস |
| `-f` | পুরো কমান্ড লাইনে খোঁজো |
| `\|\| echo ...` | কিছু না পেলে (fail হলে) মেসেজ দেখাও |

> 💡 **প্রো টিপ:** কিছু না মিললে pgrep exit code 1 দেয়, script-এর if-condition-এর জন্য একদম উপযুক্ত।

### nohup / & / disown

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `nohup` = **NO** **H**ang **UP** → terminal বন্ধ হলেও চলবে · `disown` = DISOWN → shell-এর মালিকানা থেকে মুক্ত করো

**কী করে:** Logout করার পরও প্রসেস চালু রাখে।

> **বাস্তব পরিস্থিতি:** একটা database migration-এ ২ ঘণ্টা লাগবে। SSH session কেটে গেলে (Wi-Fi, VPN) সাধারণ কমান্ডও সাথে মরে যাবে।

**sudo লাগবে?** লাগে না।

```bash
nohup ./migrate.sh > migrate.log 2>&1 &
jobs; disown %1         # detach a job already started with &
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `&` | background → পেছনে চালাও |
| `%1` | job number → ১ নম্বর job |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `> migrate.log 2>&1` | output আর error দুটোই log ফাইলে |
| `&` | কমান্ড background-এ চালাও, terminal সাথে সাথে ফেরত পাবে |
| `jobs` | এই shell-এর background job-এর তালিকা |
| `disown %1` | ১ নম্বর job-কে shell থেকে আলাদা করো |

> 💡 **প্রো টিপ:** লম্বা আর interactive কাজের জন্য tmux বা screen আরও ভালো (Shell সেকশন দেখো)।

### jobs / bg / fg

`🟢 বেসিক`

**পূর্ণরূপ:** `jobs` = JOBS → কাজের তালিকা · `bg` = **B**ack**G**round → পেছনে চালাও · `fg` = **F**ore**G**round → সামনে আনো

**কী করে:** বর্তমান shell-এর job ম্যানেজ করে।

> **বাস্তব পরিস্থিতি:** বড় একটা tar backup foreground-এ শুরু করেছ, এখন backup না থামিয়ে terminal ফেরত চাও।

**sudo লাগবে?** লাগে না।

```bash
# press Ctrl+Z to suspend it
bg          # continue it in the background
jobs        # list
fg %1       # bring it back
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `Ctrl+Z` | `Z` = suspend → থামিয়ে রাখো |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `Ctrl+Z` | চলমান কমান্ড থামিয়ে (suspend) রাখো |
| `bg` | থামানো কাজটা background-এ চালু করো |
| `fg %1` | ১ নম্বর job-কে আবার সামনে আনো |

> 💡 **প্রো টিপ:** Background job-ও shell বন্ধ হলে মরে যায়, যদি না disown করো।

### nice / renice / ionice

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `nice` = NICE → ভদ্র হও, কম priority · `renice` = RE-NICE → চলমান প্রসেসের priority বদলাও · `ionice` = I/O NICE → disk I/O-এর priority

**কী করে:** CPU আর I/O scheduling-এর priority বদলায়।

> **বাস্তব পরিস্থিতি:** রাতের backup compression চলার সময় ওয়েবসাইট ধীর হয়ে যায়। Backup-এর priority কমাচ্ছ যাতে গ্রাহকের traffic অগ্রাধিকার পায়।

**sudo লাগবে?** Priority কমাতে লাগে না। বাড়াতে (মাইনাস মান) আর অন্যের প্রসেসে লাগে।

```bash
nice -n 19 tar -czf /backup/site.tgz /var/www
renice +10 -p 8812
ionice -c3 -p 8812                         # idle I/O class
nice -n 19 ionice -c3 rsync -a /data /backup
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `nice -n 19` | `n` = niceness → কতটা ভদ্র (19 = সবচেয়ে কম priority) |
| `tar -czf` | `c` = create → বানাও · `z` = gzip → সংকুচিত · `f` = file → ফাইলের নাম |
| `renice -p` | `p` = PID → কোন প্রসেস |
| `ionice -c3` | `c` = class → শ্রেণি, 3 = idle (অবসরে) |
| `rsync -a` | `a` = archive → সব কিছু হুবহু |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-n 19` | সবচেয়ে কম priority |
| `renice +10 -p 8812` | PID 8812-এর priority 10 কমাও |
| `ionice -c3` | class 3 = idle: disk অবসর থাকলেই শুধু I/O করবে |

> 💡 **প্রো টিপ:** Priority -20 (সর্বোচ্চ) থেকে 19 (সর্বনিম্ন)। শুধু root priority বাড়াতে পারে।

### lsof

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `lsof` = **L**i**S**t **O**pen **F**iles → খোলা ফাইলের তালিকা

**কী করে:** খোলা ফাইল, socket আর কোন প্রসেস সেগুলো ধরে রেখেছে দেখায়।

> **বাস্তব পরিস্থিতি:** অ্যাপ চালু হচ্ছে না: "Address already in use :8080"। আরেক ক্ষেত্রে df বলছে disk full কিন্তু du জায়গা খুঁজে পাচ্ছে না, কারণ মুছে ফেলা একটা log এখনও খোলা আছে।

**sudo লাগবে?** অন্য user-এর প্রসেস দেখতে লাগে, তাই প্রায়ই `sudo lsof` চালাতে হয়।

```bash
lsof -i :8080            # who uses port 8080
lsof -u myapp            # files opened by a user
lsof +L1                 # deleted files still held open
lsof -p 1234 | wc -l     # how many fds a process has
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-i` | `i` = internet → network connection/port |
| `-u` | `u` = user → এই user-এর |
| `+L1` | `L` = Link count → link সংখ্যা ১-এর কম (মুছে ফেলা) |
| `-p` | `p` = PID → এই প্রসেসের |
| `wc -l` | `l` = lines → লাইন গোনা |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-i :8080` | internet: port 8080-কে কে ব্যবহার করছে |
| `-u myapp` | এই user-এর খোলা ফাইল |
| `+L1` | link count 1-এর কম: মুছে ফেলা কিন্তু এখনও খোলা ফাইল |
| `-p 1234 \| wc -l` | এই প্রসেস কয়টা ফাইল খুলে রেখেছে গোনা |

> 💡 **প্রো টিপ:** মুছে ফেলা কিন্তু খোলা ফাইলের সমাধান: প্রসেস restart করো, অথবা truncate করো: `: > /proc/PID/fd/N`

### strace

`🔴 অ্যাডভান্সড`

**পূর্ণরূপ:** `strace` = **S**ystem call **TRACE** → system call অনুসরণ করো

**কী করে:** প্রসেস কোন system call করছে সেটা trace করে।

> **বাস্তব পরিস্থিতি:** একটা অ্যাপ কোনো দরকারি log ছাড়াই সাথে সাথে বন্ধ হয়ে যায়। Trace করে দেখলে এমন path-এ config ফাইল খুলতে চাইছে যেটা নেই। আরেকবার প্রসেস আটকে আছে, দেখতে চাও কীসের জন্য অপেক্ষা করছে।

**sudo লাগবে?** অন্যের বা চলমান প্রসেসে (`-p`) attach করতে লাগে।

```bash
strace -f -e trace=openat,stat ./myapp 2>&1 | grep ENOENT
strace -p 1234 -f                  # attach to a running process
strace -c -p 1234                  # summary: which syscalls take time
strace -e trace=network -p 1234
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-f` | `f` = follow forks → child প্রসেসও |
| `-e trace=` | `e` = expression → কোন call গুলো দেখবে |
| `-p` | `p` = PID → চলমান প্রসেসে যুক্ত হও |
| `-c` | `c` = count → সারাংশ গণনা |
| `ENOENT` | **E**rror **NO** **ENT**ry → ফাইল/ফোল্ডার নেই |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-f` | follow: child প্রসেসও trace করো |
| `-e trace=openat,stat` | শুধু ফাইল খোলা/দেখার call গুলো |
| `2>&1 \| grep ENOENT` | strace output দেয় stderr-এ, তাই grep-এর জন্য `2>&1`; ENOENT = No such file |
| `-p 1234` | চলমান প্রসেসে যুক্ত হও |
| `-c` | count: কোন call কতবার, কত সময় নিল তার সারাংশ |

> 💡 **প্রো টিপ:** প্রসেস `read()` বা `futex()`-এ আটকে থাকলে সেটা network/IO বা lock-এর অপেক্ষায় আছে, CPU পোড়াচ্ছে না।

## ০৭. সিস্টেম তথ্য ও পারফরম্যান্স মনিটরিং

USE method ব্যবহার করো: প্রতিটি resource-এর **U**tilisation, **S**aturation আর **E**rrors দেখো।

### uname / hostnamectl / lscpu / nproc

`🟢 বেসিক`

**পূর্ণরূপ:** `uname` = **U**nix **NAME** → সিস্টেমের নাম ও তথ্য · `hostnamectl` = HOSTNAME ConTroL → hostname নিয়ন্ত্রণ · `lscpu` = **L**i**S**t **CPU** → CPU তথ্য · `nproc` = **N**umber of **PROC**essing units → কয়টা core

**কী করে:** Kernel, OS, hostname আর CPU-এর তথ্য।

> **বাস্তব পরিস্থিতি:** একটা vendor agent শুধু kernel 5.x বা তার উপরে চলে। আবার এই সার্ভারের জন্য সঠিক সংখ্যক Gunicorn worker ঠিক করতে হবে (2 x core + 1)।

**sudo লাগবে?** দেখতে লাগে না। hostname বদলাতে লাগে।

```bash
uname -r                             # kernel version
uname -m                             # architecture: x86_64 / aarch64
hostnamectl
hostnamectl set-hostname web-prod-01
nproc                                # number of CPU cores
lscpu
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-r` | `r` = kernel release → kernel version |
| `-m` | `m` = machine → hardware architecture |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `uname -r` | release: kernel version |
| `uname -m` | machine: architecture (x86_64 বা aarch64) |
| `set-hostname` | সার্ভারের নাম স্থায়ীভাবে বদলাও |
| `nproc` | কয়টা CPU core আছে |

> 💡 **প্রো টিপ:** aarch64 মানে ARM (যেমন AWS Graviton)। amd64 নয়, ARM binary ডাউনলোড করো।

### uptime

`🟢 বেসিক`

**পূর্ণরূপ:** `uptime` = UP TIME → কতক্ষণ চালু আছে

**কী করে:** Uptime আর ১, ৫, ১৫ মিনিটের load average।

> **বাস্তব পরিস্থিতি:** User রা ধীরগতির অভিযোগ করছে। Load average 12, তোমাকে বুঝতে হবে এটা খারাপ কিনা।

**sudo লাগবে?** লাগে না।

```bash
uptime
# 10:42 up 23 days, load average: 12.10, 8.30, 4.20
nproc      # 4 cores -> load 12 means heavy queueing; trend is increasing
```

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `load average: 12.10, 8.30, 4.20` | যথাক্রমে শেষ ১, ৫, ১৫ মিনিটের গড় |

> 💡 **প্রো টিপ:** Load-কে core সংখ্যার সাথে তুলনা করো। Load > core মানে প্রসেস অপেক্ষা করছে। ১-মিনিট ১৫-মিনিটের চেয়ে বাড়তে থাকলে অবস্থা খারাপ হচ্ছে।

### free

`🟢 বেসিক`

**পূর্ণরূপ:** `free` = FREE memory → খালি memory

**কী করে:** Memory আর swap ব্যবহার।

> **বাস্তব পরিস্থিতি:** একজন জুনিয়র ভয় পেয়ে বলছে: "free-এ মাত্র 200 MB free দেখাচ্ছে!" তুমি "available" কলামটা বুঝিয়ে দিচ্ছ আর swap ব্যবহার হচ্ছে কিনা দেখছ।

**sudo লাগবে?** লাগে না।

```bash
free -h
free -h -s 2        # refresh every 2 seconds
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-h` | `h` = human-readable → পড়ার মতো (Mi, Gi) |
| `-s 2` | `s` = seconds → প্রতি ২ সেকেন্ডে আবার |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-h` | human-readable (Mi, Gi) |
| `-s 2` | প্রতি ২ সেকেন্ডে আবার দেখাও |
| `available` | নতুন প্রোগ্রাম আসলে কত memory পাবে; এই কলামটাই আসল |

> 💡 **প্রো টিপ:** Linux অতিরিক্ত RAM cache হিসেবে ব্যবহার করে। "free" নয়, "available" দেখো। বেশি swap ব্যবহারই আসল বিপদের সংকেত।

### vmstat

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `vmstat` = **V**irtual **M**emory **STAT**istics → memory, CPU, I/O পরিসংখ্যান

**কী করে:** সময়ের সাথে প্রসেস, memory, swap, I/O আর CPU-এর রিপোর্ট দেয়।

> **বাস্তব পরিস্থিতি:** সার্ভার ধীর কিন্তু top দেখে পরিষ্কার বোঝা যাচ্ছে না। কয়েক সেকেন্ডের vmstat বলে দেয় সমস্যা CPU, swap নাকি disk।

**sudo লাগবে?** লাগে না।

```bash
vmstat 1 5
# r     = runnable procs (> cores: CPU saturated)
# si/so = swap in/out (non-zero: memory pressure)
# wa    = I/O wait (high: disk bottleneck)
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `r` / `si` / `so` / `wa` | r = runnable → CPU-এর অপেক্ষায় · si = swap in → swap থেকে RAM-এ · so = swap out → RAM থেকে swap-এ · wa = wait (I/O) → disk-এর অপেক্ষা |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `1 5` | প্রতি ১ সেকেন্ডে, মোট ৫ বার |
| `r` | CPU-এর জন্য অপেক্ষারত প্রসেস |
| `si` / `so` | swap in / swap out |
| `wa` | disk-এর অপেক্ষায় CPU কত % সময় বসে আছে |

> 💡 **প্রো টিপ:** প্রথম লাইনটা উপেক্ষা করো; সেটা boot থেকে এখন পর্যন্ত গড়।

### iostat

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `iostat` = **I**nput/**O**utput **STAT**istics → disk I/O পরিসংখ্যান

**কী করে:** প্রতিটি device-এর disk I/O পরিসংখ্যান (package: sysstat)।

> **বাস্তব পরিস্থিতি:** PostgreSQL সার্ভারে query ধীর। Disk saturated কিনা দেখছ।

**sudo লাগবে?** লাগে না। Package ইনস্টলে লাগে: `sudo apt install sysstat`

```bash
iostat -xz 1 3
# %util near 100      -> device is saturated
# r_await/w_await     -> latency in ms (SSD should be low single digits)
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-xz` | `x` = extended → বিস্তারিত কলাম · `z` = omit zero → অলস device বাদ |
| `%util` / `await` | util = utilization → কত % ব্যস্ত · await = average wait → গড় অপেক্ষার সময় (ms) |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-x` | extended: বিস্তারিত কলাম |
| `-z` | যেসব device অলস সেগুলো বাদ |
| `1 3` | প্রতি সেকেন্ডে, ৩ বার |
| `%util` / `await` | disk কত ব্যস্ত / প্রতি request-এ কত ms লাগছে |

> 💡 **প্রো টিপ:** Cloud VM-এ throughput কম কিন্তু await বেশি হলে প্রায়ই volume-এর IOPS limit-এ পৌঁছে গেছ (যেমন EBS gp2 credit)।

### sar

`🔴 অ্যাডভান্সড`

**পূর্ণরূপ:** `sar` = **S**ystem **A**ctivity **R**eporter → সিস্টেম কার্যকলাপের রিপোর্ট

**কী করে:** sysstat-এর সংগ্রহ করা পুরনো পারফরম্যান্স ডেটা।

> **বাস্তব পরিস্থিতি:** রাত ৩টায় outage হয়েছে, কেউ জেগে ছিল না। পরদিন সকালে দেখছ ঠিক ওই সময় CPU, memory আর disk-এর অবস্থা কী ছিল।

**sudo লাগবে?** সাধারণত লাগে না।

```bash
sar -u -s 02:30:00 -e 03:30:00          # CPU history today
sar -r -f /var/log/sysstat/sa05         # memory, 5th of month (RHEL: /var/log/sa/)
sar -n DEV 1 5                          # live network throughput
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-u` | `u` = utilization (CPU) → CPU ব্যবহার |
| `-s` / `-e` | `s` = start time → শুরুর সময় · `e` = end time → শেষ সময় |
| `-r` | `r` = RAM (memory) → memory ব্যবহার |
| `-f` | `f` = file → কোন ফাইল পড়বে |
| `-n DEV` | `n` = network → network · DEV = device → প্রতিটি interface |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-u` | CPU ব্যবহার |
| `-s` / `-e` | start ও end সময় |
| `-r` | RAM ব্যবহার |
| `-f ফাইল` | কোন দিনের সংরক্ষিত ফাইল পড়বে |
| `-n DEV` | network interface-এর ট্রাফিক |

> 💡 **প্রো টিপ:** Data সংগ্রহ চালু করতে `/etc/default/sysstat`-এ `ENABLED="true"` দাও (Debian/Ubuntu) আর sysstat service চালু করো।

### dmesg

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `dmesg` = **D**isplay **MES**sa**G**e (**D**iagnostic **MES**sa**G**e) → kernel-এর বার্তা দেখাও · `OOM` = **O**ut **O**f **M**emory → memory শেষ

**কী করে:** Kernel ring buffer: hardware error, OOM killer, disk আর network driver-এর বার্তা।

> **বাস্তব পরিস্থিতি:** তোমার Java অ্যাপ নিজের log-এ কোনো error ছাড়াই হারিয়ে গেছে। সম্ভবত Linux OOM killer এটাকে মেরে ফেলেছে।

**sudo লাগবে?** নতুন Ubuntu/Debian-এ লাগে: `sudo dmesg`

```bash
dmesg -T | grep -iE "oom|killed process"
dmesg -T | grep -iE "i/o error|ext4|xfs"     # disk problems
dmesg -Tw                                    # follow live
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-T` | `T` = human Timestamp → পড়ার মতো তারিখ-সময় |
| `-w` | `w` = wait (follow) → নতুন বার্তার অপেক্ষা করো |
| `grep -iE` | `i` = ignore case → বড়/ছোট হাত সমান · `E` = Extended regex → `\|` দিয়ে "অথবা" |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-T` | সময়কে মানুষের পড়ার মতো তারিখে দেখাও |
| `grep -iE "oom\|killed process"` | `-i` case উপেক্ষা, `-E` দিয়ে `\|` মানে "অথবা" |
| `-w` | নতুন বার্তা আসলে live দেখাও |

> 💡 **প্রো টিপ:** "Out of memory: Killed process 1234 (java)" দেখলে নিশ্চিত। Memory limit বা heap size ঠিক করো, বা RAM বাড়াও।

### watch

`🟢 বেসিক`

**পূর্ণরূপ:** `watch` = WATCH → নজর রাখো

**কী করে:** কমান্ড বারবার চালিয়ে full-screen-এ output দেখায়।

> **বাস্তব পরিস্থিতি:** Rolling deploy-এর সময় connection আর disk ব্যবহার বারবার টাইপ না করে live আপডেট দেখতে চাও।

**sudo লাগবে?** যে কমান্ড দেখছ তার উপর নির্ভর করে।

```bash
watch -n 2 'ss -s'
watch -d 'df -h /'                     # -d highlights changes
watch -n 5 'kubectl get pods -o wide'
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-n 2` | `n` = interval → কত সেকেন্ড পরপর |
| `-d` | `d` = differences → পরিবর্তন highlight করো |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-n 2` | প্রতি ২ সেকেন্ডে |
| `-d` | differences: কী বদলেছে highlight করো |
| `'...'` | pipe থাকলে পুরো কমান্ড quote-এ রাখো |

> 💡 **প্রো টিপ:** কমান্ডে pipe থাকলে পুরো কমান্ডটা quote-এর মধ্যে দাও।

## ০৮. ডিস্ক, ফাইলসিস্টেম ও স্টোরেজ

### df

`🟢 বেসিক`

**পূর্ণরূপ:** `df` = **D**isk **F**ree → disk-এ কত খালি

**কী করে:** প্রতিটি filesystem-এ খালি ও ব্যবহৃত জায়গা, inode সহ।

> **বাস্তব পরিস্থিতি:** Alert: deploy fail করছে "No space left on device" দিয়ে। প্রথমে দেখো কোন mount ভরা। `df -h`-এ জায়গা থাকার পরও লেখা fail করলে inode দেখো।

**sudo লাগবে?** লাগে না।

```bash
df -h
df -hT       # include filesystem type
df -i        # inode usage: millions of tiny session/cache files
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-h` | `h` = human-readable → পড়ার মতো size |
| `-hT` | `h` = human-readable → পড়ার মতো · `T` = Type → filesystem type |
| `-i` | `i` = inodes → inode-এর হিসাব |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-h` | human-readable |
| `-T` | filesystem type দেখাও (ext4, xfs) |
| `-i` | inode: ফাইলের "সিট" কতগুলো বাকি |

> 💡 **প্রো টিপ:** জায়গা খালি কিন্তু inode 100% মানে সাধারণত লাখ লাখ ছোট ফাইল (PHP session, mail queue, cache)।

### du

`🟢 বেসিক`

**পূর্ণরূপ:** `du` = **D**isk **U**sage → কে কত জায়গা নিচ্ছে

**কী করে:** ফাইল আর ডিরেক্টরির disk ব্যবহার।

> **বাস্তব পরিস্থিতি:** df বলছে `/` ভরা। কোন ডিরেক্টরি জায়গা খাচ্ছে সেটা খুঁজে বের করতে ভেতরে ঢুকছ।

**sudo লাগবে?** সব ফোল্ডার পড়তে sudo দাও, নইলে কিছু অংশ বাদ যাবে।

```bash
du -sh /var/* 2>/dev/null | sort -rh | head
du -h --max-depth=1 / 2>/dev/null | sort -rh | head
du -sh /var/lib/docker        # docker images often guilty
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-sh` | `s` = summarize → শুধু মোট · `h` = human-readable → পড়ার মতো |
| `--max-depth=1` | max-depth = maximum depth → কত স্তর গভীরে যাবে |
| `sort -rh` | `r` = reverse → বড় থেকে ছোট · `h` = human-numeric → K/M/G বুঝে |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-s` | summary: প্রতিটির মোট মাত্র |
| `-h` | human-readable |
| `/var/*` | `/var`-এর ভেতরের প্রতিটি জিনিস আলাদা করে |
| `sort -rh` | বড় থেকে ছোট, human size বুঝে |
| `--max-depth=1` | শুধু এক স্তর গভীর পর্যন্ত |

> 💡 **প্রো টিপ:** সাধারণ দোষী: `/var/log`, `/var/lib/docker`, `/var/cache/apt`, পুরনো kernel, core dump, journal log।

### ncdu

`🟢 বেসিক`

**পূর্ণরূপ:** `ncdu` = **NC**urses **D**isk **U**sage → মেনু দিয়ে disk usage

**কী করে:** Interactive disk usage ব্রাউজার।

> **বাস্তব পরিস্থিতি:** একই disk-full সমস্যা, কিন্তু বারবার du না চালিয়ে interactive ভাবে ঘুরে ঘুরে মুছতে চাও।

**sudo লাগবে?** পুরো `/` দেখতে sudo দাও। ইনস্টলও করতে হয়।

```bash
ncdu -x /      # -x: stay on one filesystem
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-x` | `x` = one filesystem → অন্য filesystem-এ যাবে না |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-x` | অন্য disk বা mount-এ যাবে না |

> 💡 **প্রো টিপ:** `d` চাপলে মুছে; arrow key দিয়ে নেভিগেট করো।

### lsblk / blkid

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `lsblk` = **L**i**S**t **BL**oc**K** devices → disk/partition-এর তালিকা · `blkid` = **BL**oc**K** **ID** → disk-এর UUID ও type

**কী করে:** Block device, partition, filesystem আর UUID-এর তালিকা।

> **বাস্তব পরিস্থিতি:** EC2 instance-এ নতুন 100 GB EBS volume যুক্ত করেছ, format করার আগে এর device name চিনতে হবে।

**sudo লাগবে?** lsblk-এ লাগে না; blkid-এ সাধারণত লাগে।

```bash
lsblk
lsblk -f                  # show filesystem and UUID
blkid /dev/nvme1n1
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-f` | `f` = filesystems → filesystem ও UUID দেখাও |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-f` | filesystem type আর UUID-ও দেখাও |
| `blkid /dev/nvme1n1` | এই disk-এর UUID আর type |

> 💡 **প্রো টিপ:** Nitro instance-এ EBS দেখায় `/dev/nvme1n1` হিসেবে, AWS console-এর মতো `/dev/xvdf` নয়।

### mkfs / mount / fstab

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `mkfs` = **M**a**K**e **F**ile**S**ystem → filesystem বানাও (format) · `mount` = MOUNT → disk-কে ফোল্ডারে যুক্ত করো · `umount` = **U**n**MOUNT** → আলাদা করো · `fstab` = **F**ile**S**ystem **TAB**le → স্থায়ী mount-এর তালিকা · `UUID` = **U**niversally **U**nique **ID**entifier → অনন্য পরিচয় নম্বর

**কী করে:** Filesystem তৈরি, mount আর স্থায়ী করা।

> **বাস্তব পরিস্থিতি:** আগের ধাপ থেকে: নতুন volume format করে database-এর জন্য `/data`-তে mount করো, আর নিশ্চিত করো reboot-এর পরও থাকবে।

**sudo লাগবে?** সব ধাপেই লাগে: `sudo mkfs...`, `sudo mount...`, fstab এডিট।

```bash
mkfs.ext4 /dev/nvme1n1                  # DANGER: destroys data, check twice
mkdir -p /data && mount /dev/nvme1n1 /data
blkid /dev/nvme1n1                      # copy the UUID

# /etc/fstab:
# UUID=xxxx-xxxx  /data  ext4  defaults,nofail  0  2

umount /data && mount -a                # test fstab before rebooting!
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `mkdir -p` | `p` = parents → দরকারি ফোল্ডারসহ |
| `mount -a` | `a` = all → fstab-এর সব mount করো |
| `ext4` | fourth **ext**ended filesystem → Linux-এর সাধারণ filesystem |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `mkfs.ext4` | ext4 format-এ format করো; ভেতরের সব data মুছে যাবে |
| `mount ডিভাইস ফোল্ডার` | ডিভাইসটা ফোল্ডারে বসাও, এখন ফোল্ডার দিয়ে disk ব্যবহার করা যাবে |
| `UUID=...` | disk-এর স্থায়ী ID; ডিভাইস নাম বদলালেও এটা বদলায় না |
| `defaults,nofail` | সাধারণ option; disk না পেলেও boot আটকাবে না |
| `0 2` | 0 = backup (dump) নয়; 2 = boot-এ root-এর পরে fsck পরীক্ষা |
| `mount -a` | fstab-এর সব entry mount করো; reboot-এর আগে fstab ঠিক আছে কিনা এভাবে পরীক্ষা করো |

> 💡 **প্রো টিপ:** fstab-এ সবসময় UUID আর `nofail` দাও। ভুল fstab entry সার্ভার boot হওয়া আটকে দিতে পারে।

### growpart / resize2fs / xfs_growfs

`🔴 অ্যাডভান্সড`

**পূর্ণরূপ:** `growpart` = GROW PARTition → partition বড় করো · `resize2fs` = RESIZE ext2/3/4 **F**ile**S**ystem → ext filesystem-এর আকার বদলাও · `xfs_growfs` = XFS GROW **F**ile**S**ystem → XFS বড় করো

**কী করে:** Disk বড় করার পর partition আর filesystem online-এ বাড়ায়।

> **বাস্তব পরিস্থিতি:** AWS-এ root EBS volume 20 GB থেকে 50 GB করেছ, কিন্তু `df -h` এখনও 20 GB দেখাচ্ছে।

**sudo লাগবে?** সব কমান্ডে লাগে।

```bash
lsblk                         # disk 50G, partition still 20G
growpart /dev/nvme0n1 1       # grow partition 1
resize2fs /dev/nvme0n1p1      # for ext4
xfs_growfs /                  # for XFS (takes mount point)
```

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `growpart /dev/nvme0n1 1` | disk-এর ১ নম্বর partition-কে যতটা খালি আছে ততটা বাড়াও |
| `resize2fs` | partition বড় হওয়ার পর filesystem-কেও বড় করো |
| `xfs_growfs /` | XFS-এ device নয়, mount point দিতে হয় |

> 💡 **প্রো টিপ:** Reboot বা unmount লাগবে না। আগে `df -T` দিয়ে filesystem type দেখে নাও।

### LVM (pvcreate / vgextend / lvextend)

`🔴 অ্যাডভান্সড`

**পূর্ণরূপ:** `LVM` = **L**ogical **V**olume **M**anager → লজিক্যাল ভলিউম ম্যানেজার · `pv` = **P**hysical **V**olume → আসল disk · `vg` = **V**olume **G**roup → disk-এর পুল · `lv` = **L**ogical **V**olume → পুল থেকে কাটা ভলিউম

**কী করে:** Logical Volume Manager: disk একসাথে করে নমনীয়ভাবে volume resize করা।

> **বাস্তব পরিস্থিতি:** একটা bare-metal সার্ভারে `/var/lib/mysql` একটা LVM volume-এ আছে আর জায়গা ফুরিয়ে আসছে। নতুন disk volume group-এ যোগ করে চলমান অবস্থায় বাড়াচ্ছ।

**sudo লাগবে?** সব কমান্ডে লাগে।

```bash
pvcreate /dev/sdc
vgextend vg_data /dev/sdc
lvextend -r -L +100G /dev/vg_data/lv_mysql     # -r resizes the fs too
pvs; vgs; lvs
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `lvextend -r` | `r` = resizefs → filesystem-ও resize করো |
| `-L +100G` | `L` = Logical size → আকার, +100G = 100 GB বাড়াও |
| `pvs` / `vgs` / `lvs` | `s` = summary (show) → সংক্ষিপ্ত তালিকা |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `pvcreate` | নতুন disk-কে LVM-এ ব্যবহারযোগ্য করো |
| `vgextend` | disk-কে group-এ যোগ করো |
| `lvextend -r -L +100G` | `-L +100G` = ১০০ GB বাড়াও, `-r` = filesystem-ও একসাথে resize |
| `pvs; vgs; lvs` | তিন স্তরের অবস্থা দেখাও; `;` দিয়ে একাধিক কমান্ড এক লাইনে |

> 💡 **প্রো টিপ:** `lvextend -r` দিলে filesystem resize-এর ধাপ ভুলে যাওয়ার ঝুঁকি থাকে না।

### swap (fallocate / mkswap / swapon)

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `fallocate` = **F**ile **ALLOCATE** → ফাইলের জন্য জায়গা বরাদ্দ · `mkswap` = **M**a**K**e **SWAP** → swap বানাও · `swapon` = SWAP ON → swap চালু

**কী করে:** Swap space তৈরি ও চালু করা।

> **বাস্তব পরিস্থিতি:** ছোট 1 GB-এর একটা VM-এ npm install চলার সময় বারবার build OOM-kill হচ্ছে। Swap যোগ করা একটা সস্তা safety net।

**sudo লাগবে?** সব ধাপে লাগে (root shell-এ চালাও বা প্রতিটিতে sudo দাও; fstab-এ লিখতে `sudo tee -a`)।

```bash
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
swapon --show
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `fallocate -l` | `l` = length → আকার (2G) |
| `swapon --show` | show → চালু swap দেখাও |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `fallocate -l 2G` | ২ GB-এর একটা খালি ফাইল বানাও |
| `chmod 600` | শুধু root পড়তে পারবে; নিরাপত্তার জন্য |
| `mkswap` / `swapon` | ফাইলটাকে swap বানাও / চালু করো |
| `&&` | প্রথমটা সফল হলেই দ্বিতীয়টা চলবে |
| `>> /etc/fstab` | `>>` মানে শেষে যোগ করো (`>` দিলে পুরো fstab মুছে যাবে!) |
| `swapon --show` | চালু থাকা swap দেখাও |

> 💡 **প্রো টিপ:** Swap একটা safety net, বাড়তি RAM নয়। Kubernetes node-এ ঐতিহ্যগতভাবে swap বন্ধ রাখা হয়।

### fuser / umount

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `fuser` = **F**ile **USER** → কে ফাইল ব্যবহার করছে · `umount` = **U**n**MOUNT** → mount খোলো

**কী করে:** কোন প্রসেস একটা mount বা ফাইল ব্যবহার করছে খোঁজে; নিরাপদে unmount করে।

> **বাস্তব পরিস্থিতি:** `umount /mnt/backup` দিলে "target is busy" আসছে।

**sudo লাগবে?** umount-এ লাগে; অন্যের প্রসেস দেখতেও লাগে।

```bash
fuser -vm /mnt/backup
lsof +D /mnt/backup
umount /mnt/backup
umount -l /mnt/nfs        # lazy unmount for a hung NFS share
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-vm` | `v` = verbose → বিস্তারিত · `m` = mount → এই mount-এর যেকোনো ফাইল |
| `lsof +D` | `D` = Directory → এই ফোল্ডারের ভেতরে |
| `umount -l` | `l` = lazy → অলস, পরে পুরো আলাদা হবে |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-v` | verbose: বিস্তারিত |
| `-m` | mount point-এর ভেতরের যেকোনো ফাইল ব্যবহারকারী |
| `lsof +D` | এই ফোল্ডারের ভেতরে খোলা সব ফাইল |
| `umount -l` | lazy: এখনই আলাদা করো, ব্যস্ততা শেষ হলে পুরো পরিষ্কার হবে |

> 💡 **প্রো টিপ:** প্রায়ই দোষী তোমার নিজের shell, যেটা ওই ডিরেক্টরির ভেতরে বসে আছে। আগে cd করে বের হও।

## ০৯. নেটওয়ার্কিং ও কানেক্টিভিটি

বেশিরভাগ "অ্যাপ ভেঙে গেছে" টিকিট আসলে DNS, firewall, port বা routing-এর সমস্যা।

### ip

`🟢 বেসিক`

**পূর্ণরূপ:** `ip` = **I**nternet **P**rotocol → IP ঠিকানা ও route ম্যানেজ

**কী করে:** IP address, interface আর route দেখায় ও configure করে (ifconfig/route-এর বদলে)।

> **বাস্তব পরিস্থিতি:** নতুন একটা VM internet-এ যেতে পারছে না। দেখছ এর IP আছে কিনা, interface চালু কিনা, আর default route আছে কিনা।

**sudo লাগবে?** দেখতে লাগে না। কিছু বদলাতে (link set, address add) লাগে।

```bash
ip a                      # addresses
ip -br a                  # brief one-line-per-interface view
ip r                      # routing table (look for 'default via')
ip route get 10.0.5.20    # which interface/gateway will be used
ip link set eth0 up
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `a` | `a` = address → IP ঠিকানা |
| `-br` | `br` = brief → সংক্ষেপে, এক লাইনে |
| `r` | `r` = route → routing table |
| `route get` | get → এই IP-তে কোন পথে যাবে বের করো |
| `link set ... up` | link → network interface · up → চালু করো |
| `eth0` | ethernet 0 → প্রথম network card |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `ip a` | a = address: প্রতিটি interface-এর IP |
| `-br` | brief: প্রতি interface এক লাইনে |
| `ip r` | r = route: routing table |
| `route get 10.0.5.20` | এই IP-তে যেতে কোন রাস্তা (gateway, interface) ব্যবহার হবে |
| `link set eth0 up` | eth0 নামের network card চালু করো |

> 💡 **প্রো টিপ:** `ip r`-এ "default via" লাইন না থাকা মানে internet-এ যাওয়ার route নেই। DHCP বা cloud subnet-এর route table দেখো।

### ss

`🟢 বেসিক`

**পূর্ণরূপ:** `ss` = **S**ocket **S**tatistics → socket/port-এর পরিসংখ্যান

**কী করে:** Socket পরিসংখ্যান: কোন port listen করছে, connection (netstat-এর বদলে)।

> **বাস্তব পরিস্থিতি:** Load balancer অ্যাপকে unhealthy দেখাচ্ছে। দেখছ অ্যাপ প্রত্যাশিত port-এ listen করছে কিনা, আর কোন address-এ।

**sudo লাগবে?** অন্য user-এর প্রসেসের নাম (`-p`) দেখতে লাগে: `sudo ss -tulnp`

```bash
ss -tulnp                                       # TCP/UDP listening + process
ss -tlnp | grep 8080
# 127.0.0.1:8080 -> only local! LB can't reach. Need 0.0.0.0:8080
ss -tan state established | wc -l               # active connections
ss -s                                           # summary
ss -tan | awk '{print $1}' | sort | uniq -c     # TIME-WAIT storms
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-tulnp` | `t` = TCP → TCP socket · `u` = UDP → UDP socket · `l` = listening → যেগুলো অপেক্ষায় আছে · `n` = numeric → port নম্বরে দেখাও · `p` = process → কোন প্রোগ্রাম |
| `-tlnp` | `t` = TCP · `l` = listening · `n` = numeric → সংখ্যায় · `p` = process → প্রোগ্রামের নাম |
| `-tan` | `t` = TCP · `a` = all → সব (listening + connected) · `n` = numeric → সংখ্যায় |
| `-s` | `s` = summary → মোট সারাংশ |
| `wc -l` / `uniq -c` | `l` = lines → লাইন গোনা · `c` = count → কতবার |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-t` / `-u` | TCP / UDP socket |
| `-l` | listening: যেগুলো connection-এর অপেক্ষায় আছে |
| `-n` | numeric: port নাম (http) নয়, সংখ্যা (80) দেখাও |
| `-p` | process: কোন প্রোগ্রাম port টা খুলেছে |
| `-a` | all: listening আর connected সব |
| `state established` | শুধু চালু connection গুলো |
| `-s` | summary: মোট হিসাব |

> 💡 **প্রো টিপ:** `0.0.0.0`-এর বদলে `127.0.0.1`-এ bind করা Docker/Node/Flask-এর খুব কমন ভুল।

### ping

`🟢 বেসিক`

**পূর্ণরূপ:** `ping` = PING (sonar-এর শব্দ) → সংকেত পাঠিয়ে উত্তর দেখো · `ICMP` = **I**nternet **C**ontrol **M**essage **P**rotocol → ping-এর protocol

**কী করে:** সাধারণ ICMP reachability আর latency।

> **বাস্তব পরিস্থিতি:** User রা বলছে সাইট down। প্রথম দ্রুত যাচাই: host-এ পৌঁছানো যাচ্ছে কিনা, packet loss আছে কিনা।

**sudo লাগবে?** লাগে না।

```bash
ping -c 4 10.0.1.15
ping -c 4 google.com      # also tests DNS resolution
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-c 4` | `c` = count → কতবার পাঠাবে |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-c 4` | count: ৪ বার পাঠিয়ে থামো; না দিলে Linux-এ অনন্তকাল চলে (Ctrl+C দিয়ে থামাও) |

> 💡 **প্রো টিপ:** Cloud security group প্রায়ই ICMP ব্লক করে। ping-এর উত্তর না আসা মানেই host down নয়; nc বা curl দিয়ে port যাচাই করো।

### traceroute / mtr

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `traceroute` = TRACE ROUTE → পথ অনুসরণ করো · `mtr` = **M**y **T**race**R**oute (Matt's TraceRoute) → traceroute + ping একসাথে

**কী করে:** Network path দেখায় আর কোথায় latency বা loss হচ্ছে।

> **বাস্তব পরিস্থিতি:** Singapore region থেকে Frankfurt-এর database-এ API call ধীর আর মাঝে মাঝে timeout হচ্ছে। কোন hop-এ loss হচ্ছে খুঁজছ।

**sudo লাগবে?** সাধারণত লাগে না।

```bash
traceroute db.example.com
mtr -rwc 100 db.example.com      # report mode, 100 probes
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-rwc` | `r` = report → শেষে রিপোর্ট · `w` = wide → পুরো hostname · `c` = count → কতবার পরীক্ষা |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-r` | report mode: শেষে একটা রিপোর্ট দেয় |
| `-w` | wide: পুরো hostname দেখাও |
| `-c 100` | প্রতি hop-এ ১০০ বার পরীক্ষা |

> 💡 **প্রো টিপ:** মাঝের কোনো hop-এ loss কিন্তু শেষ hop-এ নয়, এটা সাধারণত ICMP rate limiting, আসল loss নয়।

### dig / nslookup / host

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `dig` = **D**omain **I**nformation **G**roper → DNS তথ্য খোঁজো · `nslookup` = **N**ame **S**erver **LOOKUP** → DNS server-কে জিজ্ঞেস করো · `DNS` = **D**omain **N**ame **S**ystem → নাম থেকে IP বের করার ব্যবস্থা · `TTL` = **T**ime **T**o **L**ive → কতক্ষণ cache থাকবে

**কী করে:** DNS record query করে।

> **বাস্তব পরিস্থিতি:** ওয়েবসাইট নতুন সার্ভারে নিয়ে DNS আপডেট করেছ, কিন্তু কিছু user এখনও পুরনো সার্ভারে যাচ্ছে। বিভিন্ন resolver কী দিচ্ছে আর TTL কত, দেখছ।

**sudo লাগবে?** লাগে না।

```bash
dig example.com +short
dig @8.8.8.8 example.com A        # ask a specific resolver
dig example.com MX                # বা TXT / CNAME
dig +trace example.com            # follow delegation from root
nslookup api.internal
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `+short` | short → শুধু উত্তর |
| `@8.8.8.8` | `@` = at server → এই DNS server-কে জিজ্ঞেস করো |
| `A` / `MX` / `TXT` / `CNAME` | A = Address → IPv4 ঠিকানা · MX = Mail eXchange → mail server · TXT = TeXT → টেক্সট রেকর্ড · CNAME = Canonical NAME → অন্য নামের alias |
| `+trace` | trace → root থেকে ধাপে ধাপে |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `+short` | শুধু উত্তর (IP), বিস্তারিত না |
| `@8.8.8.8` | Google-এর DNS server-কে জিজ্ঞেস করো |
| `A` / `MX` / `TXT` / `CNAME` | record type: A = IPv4, MX = mail, TXT = টেক্সট (verification), CNAME = অন্য নামের alias |
| `+trace` | root DNS থেকে শুরু করে ধাপে ধাপে উত্তর |

> 💡 **প্রো টিপ:** Migration-এর একদিন আগে TTL কমিয়ে দাও (যেমন 60s), তারপর record বদলাও।

### curl

`🟢 বেসিক`

**পূর্ণরূপ:** `curl` = **C**lient **URL** → URL-এ request পাঠাও · `URL` = **U**niform **R**esource **L**ocator → web ঠিকানা

**কী করে:** HTTP(S) request পাঠায়; API আর health check-এর সব-কাজের টুল।

> **বাস্তব পরিস্থিতি:** DNS নতুন সার্ভারে নেওয়ার আগে আসল domain নাম দিয়ে নতুন সার্ভার টেস্ট করছ। Response time মাপছ আর SSL handshake ডিবাগ করছ।

**sudo লাগবে?** লাগে না।

```bash
curl -I https://example.com                         # headers only
curl -v https://example.com                         # verbose, TLS details
curl -s -o /dev/null -w "%{http_code} %{time_total}s\n" https://example.com
curl --resolve example.com:443:203.0.113.10 https://example.com    # test new IP
curl -X POST -H "Content-Type: application/json" \
  -d '{"name":"test"}' http://localhost:8080/api/users
curl -fsSL https://get.docker.com -o get-docker.sh
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-I` | `I` = head (Info) → শুধু header |
| `-v` | `v` = verbose → বিস্তারিত |
| `-s` | `s` = silent → চুপচাপ, progress নেই |
| `-o` | `o` = output → কোথায় save (`/dev/null` = ফেলে দাও) |
| `-w` | `w` = write-out → শেষে নিজের মতো তথ্য লেখো |
| `--resolve` | resolve → এই domain-কে এই IP-তে পাঠাও |
| `-X` | `X` = request method → HTTP method (GET, POST) |
| `-H` | `H` = Header → header যোগ |
| `-d` | `d` = data → পাঠানোর data |
| `-fsSL` | `f` = fail → HTTP error-এ fail · `s` = silent → চুপচাপ · `S` = Show error → তবু error দেখাও · `L` = Location (follow redirect) → redirect মানো |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-I` | শুধু header (status code, server) দেখাও |
| `-v` | verbose: connection, TLS, header সব বিস্তারিত |
| `-s` | silent: progress bar লুকাও |
| `-o /dev/null` | পেজের body ফেলে দাও |
| `-w "%{http_code} %{time_total}s"` | write-out: শেষে status code আর মোট সময় দেখাও |
| `--resolve host:443:IP` | DNS উপেক্ষা করে এই domain-কে এই IP-তে পাঠাও |
| `-X POST` | HTTP method POST |
| `-H` | header যোগ করো |
| `-d` | পাঠানোর data (body) |
| `\` (লাইনের শেষে) | কমান্ড পরের লাইনে চলছে; লম্বা কমান্ড ভাঙার জন্য |
| `-fsSL` | `-f` = error হলে fail, `-s` = silent, `-S` = তবু error দেখাও, `-L` = redirect মানো |

> 💡 **প্রো টিপ:** `-f` দিলে HTTP error-এ curl non-zero exit code দেয়; CI health check-এ এটা অপরিহার্য।

### wget

`🟢 বেসিক`

**কী করে:** ইন্টারঅ্যাকশন ছাড়া ফাইল ডাউনলোড করে।

> **বাস্তব পরিস্থিতি:** তোমার provisioning script সার্ভারে Node Exporter-এর একটা নির্দিষ্ট release ডাউনলোড করে।

```bash
wget -q https://github.com/.../node_exporter-1.8.2.linux-amd64.tar.gz

wget -c bigfile.iso                  # continue a broken download
```

> 💡 **প্রো টিপ:** Automation-এ সবসময় নির্দিষ্ট version pin করো। "latest" URL build-কে অপুনরুৎপাদনযোগ্য করে।

### nc (netcat)

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `nc` = **N**et**C**at → network-এর cat

**কী করে:** TCP/UDP port টেস্ট, সাধারণ listener।

> **বাস্তব পরিস্থিতি:** অ্যাপ RDS PostgreSQL database-এ connect করতে পারছে না। সমস্যা security group/firewall নাকি অ্যাপের credential?

**sudo লাগবে?** 1024-এর নিচের port-এ listen করতে লাগে।

```bash
nc -zv db.xxxx.rds.amazonaws.com 5432
# 'succeeded' -> network OK, check credentials/config
# 'timed out' -> firewall / security group / NACL
# 'refused'   -> host reachable but nothing listening
nc -l 9000          # quick listener to test from the other side
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-zv` | `z` = zero I/O → data না পাঠিয়ে শুধু port পরীক্ষা · `v` = verbose → ফলাফল দেখাও |
| `-l` | `l` = listen → অপেক্ষা করো |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-z` | zero I/O: শুধু port খোলা কিনা দেখো, data পাঠিও না |
| `-v` | verbose: ফলাফল লিখে দেখাও |
| `-l 9000` | listen: 9000 port-এ অপেক্ষা করো |

> 💡 **প্রো টিপ:** Timeout বনাম refused দেখে ঠিক বোঝা যায় কোন টিমকে ডাকতে হবে: network নাকি application।

### tcpdump

`🔴 অ্যাডভান্সড`

**পূর্ণরূপ:** `tcpdump` = TCP DUMP → network packet ধরে ঢেলে দেখাও · `pcap` = **P**acket **CAP**ture → packet সংরক্ষণের ফাইল

**কী করে:** Network packet capture আর পরীক্ষা করে।

> **বাস্তব পরিস্থিতি:** Load balancer বলছে health check fail, কিন্তু অ্যাপ log-এ কিছুই নেই। দেখছ health check-এর packet সার্ভারে আসলেই পৌঁছাচ্ছে কিনা।

**sudo লাগবে?** সবসময় লাগে: `sudo tcpdump ...`

```bash
tcpdump -i eth0 -nn port 8080
tcpdump -i any -nn host 10.0.2.33 and port 5432
tcpdump -i eth0 -w /tmp/capture.pcap         # open later in Wireshark
tcpdump -A -s0 port 80 | grep -i "host:"      # see HTTP headers
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-i` | `i` = interface → কোন network card |
| `-nn` | `n` = numeric host → IP-কে নামে বদলাবে না · `n` = numeric port → port-কে নামে বদলাবে না |
| `-w` | `w` = write → ফাইলে লেখো |
| `-A` | `A` = ASCII → packet-এর ভেতরের লেখা দেখাও |
| `-s0` | `s` = snaplength → packet-এর কতটা ধরবে (0 = পুরোটা) |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-i eth0` / `any` | interface: কোন network card-এ শুনবে; any = সবগুলো |
| `-nn` | IP আর port-কে নামে রূপান্তর করো না (দ্রুত হয়) |
| `port 8080` / `host IP` | filter: শুধু এই port বা এই host-এর packet |
| `and` | দুটো শর্তই মিলতে হবে |
| `-w file.pcap` | ফাইলে save করো, পরে Wireshark-এ খোলো |
| `-A -s0` | `-A` = packet-এর ভেতরের লেখা দেখাও, `-s0` = পুরো packet ধরো |

> 💡 **প্রো টিপ:** SYN packet আসছে কিন্তু উত্তর যাচ্ছে না মানে অ্যাপ listen করছে না বা local firewall drop করছে।

### ufw / firewall-cmd / iptables

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `ufw` = **U**ncomplicated **F**ire**W**all → সহজ firewall · `firewall-cmd` = FIREWALL **C**o**M**man**D** → firewalld-এর কমান্ড · `iptables` = IP TABLES → IP নিয়মের টেবিল

**কী করে:** Host firewall-এর rule ম্যানেজ করে।

> **বাস্তব পরিস্থিতি:** নতুন service port 8443-এ deploy করেছ, ss দেখাচ্ছে listen করছে, তবুও পৌঁছানো যাচ্ছে না। Host firewall ব্লক করছে।

**sudo লাগবে?** সবসময় লাগে।

```bash
# Ubuntu
ufw status verbose
ufw allow 8443/tcp
ufw allow from 10.0.0.0/16 to any port 5432

# RHEL/CentOS
firewall-cmd --add-port=8443/tcp --permanent && firewall-cmd --reload

# Raw iptables
iptables -L -n -v --line-numbers
iptables -A INPUT -p tcp --dport 8443 -j ACCEPT
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `--add-port` | add port → port যোগ করো |
| `--permanent` / `--reload` | permanent → স্থায়ী · reload → নতুন নিয়ম চালু |
| `-L` | `L` = List → নিয়মের তালিকা |
| `-n` / `-v` | `n` = numeric → সংখ্যায় · `v` = verbose → বিস্তারিত |
| `--line-numbers` | line numbers → লাইন নম্বর |
| `-A` | `A` = Append → শেষে নিয়ম যোগ (INPUT chain-এ) |
| `-p` | `p` = protocol → protocol (tcp) |
| `--dport` | dport = destination port → গন্তব্য port |
| `-j` | `j` = jump → কী করবে (ACCEPT = মেনে নাও, DROP = ফেলে দাও) |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `allow 8443/tcp` | 8443 নম্বর TCP port খোলো |
| `from 10.0.0.0/16 to any port 5432` | শুধু ভেতরের network থেকে database port-এ ঢুকতে দাও |
| `--permanent` / `--reload` | স্থায়ীভাবে সেভ করো / নতুন নিয়ম চালু করো |
| `-L -n -v --line-numbers` | সব নিয়মের তালিকা, সংখ্যায়, বিস্তারিত, লাইন নম্বরসহ |
| `-A INPUT` | INPUT chain (ভেতরে আসা traffic)-এর শেষে নিয়ম যোগ করো |
| `-p tcp --dport 8443 -j ACCEPT` | TCP, গন্তব্য port 8443 হলে, ACCEPT-এ jump (মেনে নাও) |

> 💡 **প্রো টিপ:** Remote সার্ভারে ufw চালুর আগে `ufw allow OpenSSH` চালাও, নইলে নিজেই লক হয়ে যাবে।

### nmap

`🔴 অ্যাডভান্সড`

**পূর্ণরূপ:** `nmap` = **N**etwork **MAP**per → network-এর মানচিত্র

**কী করে:** Port scan আর service খোঁজা (শুধু তোমার নিজের বা অনুমোদিত সিস্টেমে)।

> **বাস্তব পরিস্থিতি:** Security review: নিশ্চিত হতে চাও তোমার public web সার্ভারে শুধু 22, 80 আর 443 port খোলা।

**sudo লাগবে?** কিছু scan type-এ লাগে।

```bash
nmap -Pn -p- your-server.example.com
nmap -sV -p 22,80,443 your-server.example.com
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-Pn` | `P` = Ping → ping · `n` = no → করো না (সরাসরি scan) |
| `-p-` | `p` = ports → port, `-` মানে সব (১-৬৫৫৩৫) |
| `-sV` | `s` = scan → scan · `V` = Version → সফটওয়্যারের version বের করো |
| `-p 22,80,443` | `p` = ports → এই port গুলো |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-Pn` | ping না করে সরাসরি scan (ICMP বন্ধ থাকলেও কাজ করে) |
| `-p-` | সব 65535 port |
| `-sV` | খোলা port-এ কোন সফটওয়্যার আর version চলছে |

> 💡 **প্রো টিপ:** অনুমতি ছাড়া অন্যের সিস্টেম scan করা বেআইনি হতে পারে। শুধু নিজের infrastructure audit করো।

## ১০. রিমোট অ্যাক্সেস ও ফাইল ট্রান্সফার

SSH দিয়েই তুমি প্রতিটি সার্ভারে পৌঁছাও। Key, config, jump host আর tunnel আয়ত্ত করো।

### ssh

`🟢 বেসিক`

**পূর্ণরূপ:** `ssh` = **S**ecure **SH**ell → নিরাপদ remote terminal

**কী করে:** নিরাপদ remote shell।

> **বাস্তব পরিস্থিতি:** একটা EC2 instance-এ connect করছ, তারপর এমন একটা connection ডিবাগ করছ যেটা আটকে যায় বা বাতিল হয়।

**sudo লাগবে?** লাগে না। Server-এ ঢোকার পর দরকার হলে সেখানে sudo চালাও।

```bash
ssh -i ~/.ssh/prod.pem ubuntu@203.0.113.10
ssh -v user@host                    # verbose: see which key is tried, where it fails
ssh user@host 'df -h; uptime'       # run a remote command
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-i` | `i` = identity file → কোন private key |
| `-v` | `v` = verbose → বিস্তারিত (সমস্যা খুঁজতে) |
| `df -h` | `h` = human-readable → পড়ার মতো size |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-i ~/.ssh/prod.pem` | identity file: কোন private key দিয়ে login করবে |
| `ubuntu@203.0.113.10` | user@server_ip |
| `-v` | verbose: connection-এর প্রতিটি ধাপ দেখাও |
| `'df -h; uptime'` | login না করে শুধু এই কমান্ড চালিয়ে ফল আনো |

> 💡 **প্রো টিপ:** `ssh -v` বলে দেয় সমস্যা network (connection হচ্ছে না), host key, নাকি authentication।

### ~/.ssh/config ও ProxyJump

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `ProxyJump` = PROXY JUMP → মধ্যবর্তী সার্ভার হয়ে লাফ · `bastion` = bastion host → দুর্গের মতো একমাত্র প্রবেশদ্বার সার্ভার

**কী করে:** Connection setting সংরক্ষণ; bastion host-এর মধ্য দিয়ে যাওয়া।

> **বাস্তব পরিস্থিতি:** Private সার্ভারগুলোতে শুধু একটা bastion-এর মধ্য দিয়ে যাওয়া যায়। প্রতিবার লম্বা কমান্ড টাইপ করলে ভুল হয়।

**sudo লাগবে?** লাগে না; এটা তোমার নিজের ফাইল।

```text
# ~/.ssh/config
Host bastion
    HostName 203.0.113.5
    User ubuntu
    IdentityFile ~/.ssh/prod.pem

Host app-*
    User ubuntu
    ProxyJump bastion

Host app-1
    HostName 10.0.2.11
```

```bash
ssh app-1                            # goes through bastion automatically
ssh -J bastion ubuntu@10.0.2.11      # one-off equivalent
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-J` | `J` = Jump host → এই সার্ভার হয়ে যাও |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `Host bastion` | একটা ডাকনাম; এখন শুধু `ssh bastion` লিখলেই হবে |
| `HostName` | আসল IP বা domain |
| `User` / `IdentityFile` | কোন user আর কোন key |
| `Host app-*` | `app-` দিয়ে শুরু সব নামের জন্য এই নিয়ম |
| `ProxyJump bastion` | আগে bastion-এ যাও, তারপর সেখান থেকে আসল সার্ভারে |
| `-J` | এককালীন ProxyJump, config ছাড়া |

> 💡 **প্রো টিপ:** Agent forwarding (`-A`)-এর চেয়ে ProxyJump নিরাপদ, কারণ `-A` তোমার key bastion-এর কাছে উন্মুক্ত করে।

### ssh-keygen / ssh-copy-id

`🟢 বেসিক`

**পূর্ণরূপ:** `ssh-keygen` = SSH KEY **GEN**erator → SSH key বানাও · `ssh-copy-id` = SSH COPY **ID**entity → public key সার্ভারে কপি করো

**কী করে:** Key pair তৈরি আর সার্ভারে public key বসানো।

> **বাস্তব পরিস্থিতি:** Jenkins-এর deploy সার্ভারে password ছাড়া SSH দরকার। পরে একটা সার্ভার rebuild হয়েছে আর SSH সতর্ক করছে "REMOTE HOST IDENTIFICATION HAS CHANGED"।

**sudo লাগবে?** লাগে না।

```bash
ssh-keygen -t ed25519 -C "jenkins@ci" -f ~/.ssh/jenkins_deploy
ssh-copy-id -i ~/.ssh/jenkins_deploy.pub deploy@10.0.2.11
ssh-keygen -R 10.0.2.11          # remove old host key after rebuild
ssh-keygen -lf key.pub           # fingerprint
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-t` | `t` = type → key-এর ধরন (ed25519) |
| `-C` | `C` = Comment → মন্তব্য |
| `-f` | `f` = file → ফাইলের নাম |
| `ssh-copy-id -i` | `i` = identity → কোন key |
| `-R` | `R` = Remove → known_hosts থেকে সরাও |
| `-lf` | `l` = list fingerprint → fingerprint দেখাও · `f` = file → কোন ফাইলের |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-t ed25519` | type: আধুনিক, ছোট আর নিরাপদ key |
| `-C "jenkins@ci"` | comment: key টা কার/কিসের তা চেনার জন্য |
| `-f` | file: কোন নামে key save হবে |
| `.pub` | public key: সার্ভারে দেওয়া যায়; `.pub` ছাড়াটা private, কাউকে দেবে না |
| `-R IP` | remove: known_hosts থেকে পুরনো host key সরাও |
| `-lf` | `-l` = fingerprint দেখাও, `-f` = কোন ফাইলের |

> 💡 **প্রো টিপ:** পুরনো host key তখনই সরাবে যখন নিশ্চিত জানো সার্ভার rebuild হয়েছে। নইলে ওই সতর্কবার্তা attack-এর ইঙ্গিত হতে পারে।

### SSH tunnels (-L / -R)

`🔴 অ্যাডভান্সড`

**পূর্ণরূপ:** `ssh -L` = **L**ocal port forward → নিজের port থেকে দূরে · `ssh -R` = **R**emote port forward → দূরের port থেকে নিজের কাছে

**কী করে:** SSH দিয়ে নিরাপদে port forward করা।

> **বাস্তব পরিস্থিতি:** ল্যাপটপ থেকে একটা private RDS database-এ query চালাতে হবে। DB শুধু VPC-এর ভেতর থেকে পৌঁছানো যায়।

**sudo লাগবে?** লাগে না (1024-এর নিচের local port ছাড়া)।

```bash
ssh -N -L 5433:mydb.xxxx.rds.amazonaws.com:5432 bastion
# now on your laptop:
psql -h localhost -p 5433 -U admin mydb

ssh -N -R 9000:localhost:3000 user@public-host     # expose local port remotely
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-N` | `N` = No command → কমান্ড চালাবে না, শুধু tunnel |
| `-L` | `L` = Local forward → local port দূরে পাঠাও |
| `-R` | `R` = Remote forward → দূরের port নিজের কাছে আনো |
| `psql -h -p -U` | `h` = host → সার্ভার · `p` = port → port · `U` = User → database user |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-N` | কোনো কমান্ড চালাবে না, শুধু tunnel |
| `-L 5433:db:5432` | Local: আমার 5433 port-এ যা আসবে, bastion হয়ে db-এর 5432-তে যাবে |
| `-R 9000:localhost:3000` | Remote: দূরের সার্ভারের 9000 port আমার 3000 port-এ আসবে |

> 💡 **প্রো টিপ:** `-N` মানে "কোনো remote কমান্ড নয়", শুধু tunnel খোলা রাখো।

### scp

`🟢 বেসিক`

**পূর্ণরূপ:** `scp` = **S**ecure **C**o**P**y → নিরাপদে কপি

**কী করে:** SSH দিয়ে ফাইল কপি।

> **বাস্তব পরিস্থিতি:** Production সার্ভার থেকে একটা heap dump দ্রুত ল্যাপটপে এনে বিশ্লেষণ করতে হবে।

**sudo লাগবে?** দূরের সার্ভারে root-এর ফোল্ডারে লিখতে সেখানে অনুমতি লাগে। সাধারণত `/tmp`-এ কপি করে পরে `sudo mv` করা হয়।

```bash
scp app-1:/tmp/heapdump.hprof ./
scp -r ./config deploy@10.0.2.11:/opt/app/
scp -J bastion file.txt ubuntu@10.0.2.11:/tmp/
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-r` | `r` = recursive → ফোল্ডারসহ |
| `-J` | `J` = Jump host → এই সার্ভার হয়ে |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `app-1:/tmp/heapdump.hprof ./` | `সার্ভার:path` থেকে বর্তমান ফোল্ডারে (`./`) আনো |
| `-r` | পুরো ফোল্ডার |
| `-J bastion` | bastion হয়ে কপি করো |

> 💡 **প্রো টিপ:** বড় বা বারবার ট্রান্সফারের জন্য rsync ভালো। এটা resume করে আর শুধু পরিবর্তন পাঠায়।

### rsync

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `rsync` = **R**emote **SYNC** → দূরে মিলিয়ে রাখো (sync)

**কী করে:** Local বা SSH-এ ফাইল দক্ষভাবে sync করে (শুধু পার্থক্য পাঠায়)।

> **বাস্তব পরিস্থিতি:** Static website build ৩টা সার্ভারে deploy করছ, প্রতি রাতে `/var/www` backup সার্ভারে নিচ্ছ। আবার 200 GB আপলোড নতুন সার্ভারে migrate করছ।

**sudo লাগবে?** গন্তব্যে লেখার অনুমতি লাগে। দূরে root হিসেবে চালাতে: `--rsync-path="sudo rsync"`

```bash
rsync -avz --delete ./dist/ deploy@web1:/var/www/html/
rsync -avz --dry-run --delete ./dist/ web1:/var/www/html/      # preview first!
rsync -aP --exclude='node_modules' --exclude='.git' src/ host:/opt/app/
rsync -aP -e "ssh -i ~/.ssh/backup" /var/www/ backup@bk1:/backups/www/
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-avz` | `a` = archive → সব হুবহু, ফোল্ডারের ভেতরেও · `v` = verbose → বিস্তারিত · `z` = compress (zip) → সংকুচিত করে পাঠাও |
| `--delete` | delete → উৎসে নেই এমন ফাইল গন্তব্য থেকে মুছো |
| `--dry-run` | dry-run = শুকনো চালানো → কিছু না করে শুধু দেখাও |
| `-aP` | `a` = archive → হুবহু · `P` = Partial + Progress → অর্ধেক ফাইল রাখো আর অগ্রগতি দেখাও |
| `--exclude` | exclude → বাদ দাও |
| `-e` | `e` = remote shell (execute) → কোন ssh কমান্ড ব্যবহার করবে |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-a` | archive: permission, সময়, symlink সব রাখো, ফোল্ডারের ভেতরেও যাও |
| `-v` | verbose |
| `-z` | compress: network-এ পাঠানোর সময় সংকুচিত করো |
| `--delete` | উৎসে নেই এমন ফাইল গন্তব্য থেকে মুছে দাও |
| `--dry-run` | আসলে কিছু না করে কী হবে তা দেখাও |
| `-P` | `--partial` + `--progress`: অর্ধেক ফাইল রেখে দাও আর progress দেখাও |
| `--exclude` | এই ফাইল/ফোল্ডার বাদ |
| `-e "ssh -i ..."` | কোন ssh কমান্ড ও key দিয়ে connect করবে |

> 💡 **প্রো টিপ:** Source-এর শেষে slash (`dist/`) থাকলে ভেতরের কনটেন্ট কপি হয়; না থাকলে ফোল্ডারটাই কপি হয়। `--delete`-এর সাথে ভুল path মানে data হারানো, তাই সবসময় আগে `--dry-run`।

## ১১. সার্ভিস, লগ ও শিডিউলিং (systemd, cron)

আধুনিক distro-তে সবকিছু systemd-এর অধীনে চলে। Service ম্যানেজ করা আর তাদের log পড়তে জানো।

### systemctl

`🟢 বেসিক`

**পূর্ণরূপ:** `systemctl` = **SYSTEM** **C**on**T**ro**L** → systemd service নিয়ন্ত্রণ · `systemd` = **SYSTEM** **D**aemon → সিস্টেমের মূল service ম্যানেজার

**কী করে:** systemd service নিয়ন্ত্রণ করে।

> **বাস্তব পরিস্থিতি:** nginx config বদলানোর পর যাচাই করছ, connection না কেটে reload করছ, আর নিশ্চিত করছ boot-এ চালু হবে। Reboot-এর পর দেখছ কোনটা চালু হতে fail করেছে।

**sudo লাগবে?** দেখতে (`status`, `cat`) লাগে না। চালু/বন্ধ/restart/enable করতে লাগে।

```bash
nginx -t && systemctl reload nginx
systemctl status nginx
systemctl restart myapp
systemctl enable --now myapp         # start now + on boot
systemctl is-active myapp
systemctl list-units --failed
systemctl cat myapp                  # show the unit file
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `nginx -t` | `t` = test → config পরীক্ষা |
| `--now` | now → এখনই চালু করো |
| `--failed` | failed → fail করা unit গুলো |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `nginx -t &&` | `-t` = config পরীক্ষা করো; ঠিক থাকলেই (`&&`) reload হবে |
| `reload` / `restart` | reload = শুধু config আবার পড়ো; restart = পুরো বন্ধ করে চালু |
| `status` | চলছে কিনা, শেষ কয়েকটা log |
| `enable --now` | boot-এ চালু হবে, আর এখনই চালু করো |
| `is-active` | শুধু active/inactive উত্তর; script-এর জন্য |
| `list-units --failed` | যেসব service fail করেছে |
| `cat` | service-এর unit ফাইল দেখাও |

> 💡 **প্রো টিপ:** reload = downtime ছাড়া config আবার পড়া (যদি সাপোর্ট করে)। restart = পুরো stop/start।

### systemd unit file

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `unit` = systemd UNIT → systemd-এর একটা কাজের বর্ণনা · `Exec` = **EXEC**ute → চালাও

**কী করে:** নিজের অ্যাপ্লিকেশন managed service হিসেবে চালানো।

> **বাস্তব পরিস্থিতি:** একটা Node.js API হাতে `node server.js` দিয়ে চালানো হয়, crash করলে বা সার্ভার reboot হলে বন্ধ হয়ে যায়। Auto-restart সহ সঠিক service বানাচ্ছ।

**sudo লাগবে?** `/etc/systemd/system`-এ লিখতে আর daemon-reload করতে লাগে।

```ini
# /etc/systemd/system/myapp.service
[Unit]
Description=My API
After=network-online.target

[Service]
User=myapp
WorkingDirectory=/opt/myapp/current
EnvironmentFile=/etc/myapp/app.env
ExecStart=/usr/bin/node server.js
Restart=on-failure
RestartSec=5
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now myapp
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `ExecStart` | ExecStart = EXECute at START → শুরুতে এটা চালাও |
| `LimitNOFILE` | NOFILE = Number Of FILEs → কয়টা ফাইল খোলা যাবে |
| `enable --now` | enable → boot-এ চালু · now → এখনই |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `[Unit] After=` | network চালু হওয়ার পরে শুরু হবে |
| `User=` | কোন user হিসেবে চলবে (root নয়) |
| `WorkingDirectory=` | কোন ফোল্ডার থেকে চলবে |
| `EnvironmentFile=` | environment variable কোন ফাইল থেকে আসবে |
| `ExecStart=` | আসল চালানোর কমান্ড (পুরো path সহ) |
| `Restart=on-failure` / `RestartSec=5` | crash করলে ৫ সেকেন্ড পর আবার চালু |
| `LimitNOFILE` | সর্বোচ্চ কয়টা ফাইল খুলতে পারবে |
| `WantedBy=multi-user.target` | সাধারণ boot-এ চালু হবে |
| `daemon-reload` | systemd-কে বলো unit ফাইল আবার পড়তে |

> 💡 **প্রো টিপ:** Unit ফাইল এডিটের পর `systemctl daemon-reload` ভুলে যাওয়া ক্লাসিক ভুল।

### journalctl

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `journalctl` = **JOURNAL** **C**on**T**ro**L** → systemd log পড়ো

**কী করে:** systemd-এর journal log query করে।

> **বাস্তব পরিস্থিতি:** myapp বারবার restart হচ্ছে। গত এক ঘণ্টার log, শুধু error, আর live follow করছ। এদিকে journal নিজেই 8 GB disk খাচ্ছে।

**sudo লাগবে?** নিজের user-এর log ছাড়া বাকিগুলো দেখতে লাগে (বা user-কে `adm`/`systemd-journal` group-এ রাখো)।

```bash
journalctl -u myapp -f
journalctl -u myapp --since "1 hour ago"
journalctl -u myapp --since "2026-10-06 02:00" --until "2026-10-06 03:00"
journalctl -p err -b                 # errors since last boot
journalctl -b -1                     # previous boot (why did it crash?)
journalctl --disk-usage
journalctl --vacuum-size=500M
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-u` | `u` = unit → কোন service |
| `-f` | `f` = follow → live |
| `--since` / `--until` | since → কখন থেকে · until → কখন পর্যন্ত |
| `-p err` | `p` = priority → গুরুত্ব (err = error) |
| `-b` | `b` = boot → এই boot (`-1` = আগের boot) |
| `--disk-usage` / `--vacuum-size` | disk usage → কত জায়গা নিচ্ছে · vacuum to size → ঝেড়ে এই আকারে নামাও |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-u myapp` | unit: শুধু এই service-এর log |
| `-f` | follow: live |
| `--since` / `--until` | কখন থেকে / কখন পর্যন্ত |
| `-p err` | priority: শুধু error ও তার চেয়ে গুরুতর |
| `-b` / `-b -1` | এবারের boot থেকে / আগের boot-এর log |
| `--disk-usage` / `--vacuum-size` | journal কত জায়গা নিচ্ছে / পুরনো log মুছে এই size-এ নামাও |

> 💡 **প্রো টিপ:** `/etc/systemd/journald.conf`-এ `SystemMaxUse=1G` দিলে journal-এর size স্থায়ীভাবে সীমিত থাকে।

### crontab

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `crontab` = **CRON** **TAB**le → সময়সূচির টেবিল · `cron` = **CHRON**os (গ্রিক: সময়) → সময়মতো কাজ চালানোর service

**কী করে:** নিয়মিত কাজ শিডিউল করে।

> **বাস্তব পরিস্থিতি:** প্রতি রাত ২টায় database backup আর প্রতি রবিবার temp ফাইল পরিষ্কার দরকার, output log সহ।

**sudo লাগবে?** নিজের crontab-এ লাগে না। অন্যের (`-u`) বা root-এর কাজের জন্য: `sudo crontab -e`

```bash
crontab -e
# m h dom mon dow  command
0 2 * * *    /opt/scripts/db_backup.sh >> /var/log/db_backup.log 2>&1
30 3 * * 0   find /tmp -mtime +7 -delete
*/5 * * * *  /opt/scripts/healthcheck.sh

crontab -l                  # list
crontab -l -u jenkins       # another user's crontab
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-e` | `e` = edit → এডিট |
| `-l` | `l` = list → দেখাও |
| `-u` | `u` = user → কোন user-এর |
| `m h dom mon dow` | m = minute → মিনিট · h = hour → ঘণ্টা · dom = day of month → মাসের দিন · mon = month → মাস · dow = day of week → সপ্তাহের দিন |
| `find -mtime` / `-delete` | mtime = modification time → কত দিন আগে বদলেছে · delete → মুছো |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-e` | edit: crontab খুলে এডিট করো |
| `m h dom mon dow` | মিনিট, ঘণ্টা, মাসের দিন, মাস, সপ্তাহের দিন (0 = রবিবার) |
| `0 2 * * *` | প্রতিদিন রাত ২:০০টায়; `*` মানে "যেকোনো" |
| `*/5 * * * *` | প্রতি ৫ মিনিটে |
| `>> log 2>&1` | output আর error দুটোই log-এর শেষে যোগ |
| `-l` / `-u` | list / অন্য user-এর |

> 💡 **প্রো টিপ:** Cron খুব ছোট PATH নিয়ে আর profile ছাড়া চলে। Absolute path দাও। Script হাতে চলে কিন্তু cron-এ চলে না? প্রায় সবসময় এটাই কারণ।

### logrotate

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `logrotate` = **LOG** **ROTATE** → log ঘোরাও

**কী করে:** পুরনো log ফাইল স্বয়ংক্রিয়ভাবে rotate, compress আর মুছে ফেলে।

> **বাস্তব পরিস্থিতি:** অ্যাপ `/var/log/myapp/app.log`-এ লেখে, ফাইলটা 30 GB হয়ে disk ভরিয়ে দিয়েছে।

**sudo লাগবে?** `/etc/logrotate.d`-এ লিখতে আর চালাতে লাগে।

```text
# /etc/logrotate.d/myapp
/var/log/myapp/*.log {
    daily
    rotate 14
    compress
    delaycompress
    missingok
    notifempty
    copytruncate
}
```

```bash
logrotate -d /etc/logrotate.d/myapp     # dry run / debug
logrotate -f /etc/logrotate.d/myapp     # force now
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-d` | `d` = debug → শুধু পরীক্ষা, আসলে কিছু করবে না |
| `-f` | `f` = force → এখনই জোর করে চালাও |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `daily` / `rotate 14` | প্রতিদিন ঘোরাও, ১৪টা পুরনো কপি রাখো |
| `compress` / `delaycompress` | পুরনো log gzip করো, তবে সবচেয়ে নতুনটা এক দিন পরে |
| `missingok` / `notifempty` | ফাইল না থাকলে error নয় / খালি হলে ঘোরাবে না |
| `copytruncate` | কপি রেখে মূল ফাইল খালি করে দাও |
| `-d` / `-f` | debug (শুকনো পরীক্ষা) / force (এখনই চালাও) |

> 💡 **প্রো টিপ:** `copytruncate` সেই অ্যাপের জন্য যেগুলো log ফাইল আবার খুলতে পারে না। নইলে `postrotate` signal ব্যবহার করো (যেমন `kill -USR1`)।

### timedatectl / chronyc

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `timedatectl` = **TIME** **DATE** **C**on**T**ro**L** → সময় ও তারিখ নিয়ন্ত্রণ · `chronyc` = **CHRONY** **C**lient → chrony service-এর কমান্ড · `NTP` = **N**etwork **T**ime **P**rotocol → internet দিয়ে সময় মেলানো · `UTC` = **C**oordinated **U**niversal **T**ime → বিশ্ব মান সময়

**কী করে:** সময়, timezone আর NTP sync ম্যানেজ করে।

> **বাস্তব পরিস্থিতি:** বিভিন্ন সার্ভারের log-এর সময় মিলছে না, আর JWT token মাঝে মাঝে "not yet valid" বলে বাতিল হচ্ছে। ঘড়ি সরে যাচ্ছে।

**sudo লাগবে?** দেখতে লাগে না, বদলাতে লাগে।

```bash
timedatectl
timedatectl set-timezone Asia/Dhaka
timedatectl set-ntp true
chronyc tracking            # offset from the NTP source
chronyc sources -v
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `sources -v` | `v` = verbose → বিস্তারিত |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `set-timezone Asia/Dhaka` | সময় অঞ্চল বাংলাদেশ |
| `set-ntp true` | internet-এর সময় server-এর সাথে স্বয়ংক্রিয় মিল চালু |
| `tracking` / `sources -v` | সময় কতটা পিছিয়ে/এগিয়ে / কোন server থেকে সময় নিচ্ছে |

> 💡 **প্রো টিপ:** অনেক টিম সার্ভার UTC-তে রাখে, শুধু dashboard-এ local time-এ রূপান্তর করে।

## ১২. প্যাকেজ ম্যানেজমেন্ট

Debian/Ubuntu আর RHEL-পরিবারের সিস্টেমে সফটওয়্যার install, pin আর audit করা।

### apt

`🟢 বেসিক`

**পূর্ণরূপ:** `apt` = **A**dvanced **P**ackage **T**ool → উন্নত package টুল

**কী করে:** Debian/Ubuntu-এর package manager।

> **বাস্তব পরিস্থিতি:** nginx install করছ, কোন version পাওয়া যায় দেখছ, আর docker-ce pin করছ যাতে unattended upgrade production-এ Docker restart না করে।

**sudo লাগবে?** install, update, remove-এ সবসময় লাগে। শুধু দেখতে (`apt list`, `apt-cache`) লাগে না।

```bash
apt update && apt install -y nginx
apt-cache policy nginx               # installed vs candidate versions
apt install nginx=1.24.0-1ubuntu1
apt-mark hold docker-ce              # freeze version
apt list --upgradable
apt autoremove --purge               # clean unused packages & old kernels
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-y` | `y` = yes → সব প্রশ্নে হ্যাঁ |
| `--upgradable` | upgradable → যেগুলোর নতুন version আছে |
| `--purge` | purge → config সহ পুরো মুছো |
| `apt-mark hold` | hold → আটকে রাখো, upgrade হবে না |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `update` | কোন package-এর কোন version আছে, সেই তালিকা আপডেট করো; কিছু install করে না |
| `install -y` | install করো, `-y` = সব প্রশ্নে yes |
| `apt-cache policy` | installed আর পাওয়া যায় এমন version |
| `nginx=1.24.0-1ubuntu1` | নির্দিষ্ট version install |
| `apt-mark hold` | এই package আর upgrade হবে না |
| `autoremove --purge` | অপ্রয়োজনীয় package আর তাদের config মুছে দাও |

> 💡 **প্রো টিপ:** Dockerfile-এ `apt-get` ব্যবহার করো (stable CLI), আর update + install একই `RUN` লাইনে চালাও।

### dnf / yum

`🟢 বেসিক`

**পূর্ণরূপ:** `dnf` = **D**a**N**di**F**ied yum → উন্নত yum · `yum` = **Y**ellowdog **U**pdater **M**odified → RHEL-এর পুরনো package টুল

**কী করে:** RHEL / CentOS / Rocky / Amazon Linux-এর package manager।

> **বাস্তব পরিস্থিতি:** Amazon Linux-এ একটা কমান্ড নেই, আর জানো না কোন package এটা দেয়। খারাপ update-এর পর rollback করতে হবে।

**sudo লাগবে?** install/undo-তে লাগে।

```bash
dnf install -y git
dnf provides '*/semanage'     # which package has this file?
dnf history                   # list transactions
dnf history undo 15           # roll back transaction 15
dnf check-update
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-y` | `y` = yes → সব প্রশ্নে হ্যাঁ |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `provides` | কোন package এই ফাইল দেয় |
| `history` | আগের সব install/update-এর তালিকা |
| `history undo 15` | ১৫ নম্বর পরিবর্তন উল্টে দাও |
| `check-update` | কোনগুলোর update আছে |

> 💡 **প্রো টিপ:** নতুন সিস্টেমে `yum` আসলে `dnf`-এর একটা alias।

### dpkg / rpm

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `dpkg` = **D**ebian **P**ac**K**a**G**e → Debian package টুল · `rpm` = **R**PM **P**ackage **M**anager (আগে **R**ed hat **P**ackage **M**anager) → Red Hat package টুল

**কী করে:** Low-level package query।

> **বাস্তব পরিস্থিতি:** একটা vulnerability (CVE) নির্দিষ্ট version-এর নিচের openssl-কে প্রভাবিত করে। অনেক সার্ভারে ঠিক কোন version install আছে দেখছ, আর একটা ফাইল কোন package-এর সেটা খুঁজছ।

**sudo লাগবে?** query-তে লাগে না।

```bash
dpkg -l | grep openssl
dpkg -S /usr/bin/curl         # package owning a file
dpkg -L nginx                 # files installed by a package
rpm -qa | grep openssl
rpm -qf /usr/bin/curl
rpm -qi openssl
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `dpkg -l` | `l` = list → তালিকা |
| `dpkg -S` | `S` = Search → কোন package-এর ফাইল |
| `dpkg -L` | `L` = List files → package-এর ফাইলগুলো |
| `rpm -qa` | `q` = query → জিজ্ঞাসা · `a` = all → সব |
| `rpm -qf` | `q` = query → জিজ্ঞাসা · `f` = file → এই ফাইল কার |
| `rpm -qi` | `q` = query → জিজ্ঞাসা · `i` = info → বিস্তারিত তথ্য |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `dpkg -l` | list: সব installed package |
| `-S` | search: এই ফাইল কোন package-এর |
| `-L` | এই package কোন কোন ফাইল বসিয়েছে |
| `rpm -qa` | query all: সব package |
| `-qf` / `-qi` | query file (কার ফাইল) / query info (বিস্তারিত) |

> 💡 **প্রো টিপ:** xargs/ssh বা Ansible ad-hoc-এর সাথে মিলিয়ে পুরো fleet audit করো।

## ১৩. আর্কাইভ ও কম্প্রেশন

Backup, artifact আর log shipping সবই এগুলোর উপর নির্ভর করে।

### tar

`🟢 বেসিক`

**পূর্ণরূপ:** `tar` = **T**ape **AR**chive → টেপ আর্কাইভ, ফাইল বান্ডেল করো

**কী করে:** ফাইল একসাথে বাঁধে (চাইলে compress সহ)।

> **বাস্তব পরিস্থিতি:** ঝুঁকিপূর্ণ upgrade-এর আগে ফাইলনামে তারিখসহ অ্যাপ ফোল্ডারের backup নিচ্ছ, পরে restore করছ। আবার local disk ব্যবহার না করে অন্য সার্ভারে backup stream করছ।

**sudo লাগবে?** root-এর ফাইল backup নিতে বা সব permission সহ extract করতে লাগে।

```bash
tar -czvf app-backup-$(date +%F).tar.gz /opt/app
tar -tzvf app-backup.tar.gz | head          # list without extracting
tar -xzvf app-backup.tar.gz -C /opt/restore
tar -czf - --exclude='*.log' /opt/app | ssh backup 'cat > app.tgz'
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-czvf` | `c` = create → নতুন archive বানাও · `z` = gzip → gzip দিয়ে সংকুচিত · `v` = verbose → কোন ফাইল যাচ্ছে দেখাও · `f` = file → archive-এর নাম (f সবসময় শেষে) |
| `-tzvf` | `t` = list (table of contents) → ভেতরে কী আছে দেখাও · `z` = gzip · `v` = verbose · `f` = file → কোন archive |
| `-xzvf` | `x` = extract → খোলো · `z` = gzip · `v` = verbose · `f` = file → কোন archive |
| `-C` | `C` = Change directory → এই ফোল্ডারে খোলো |
| `-czf -` | `c` = create · `z` = gzip · `f -` = file (stdout) → ফাইলের নাম `-` মানে ফাইলের বদলে pipe-এ পাঠাও |
| `--exclude` | exclude → বাদ দাও |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-c` | create: নতুন archive |
| `-z` | gzip দিয়ে সংকুচিত (`.tar.gz`) |
| `-v` | verbose: কোন ফাইল যাচ্ছে দেখাও |
| `-f নাম` | file: archive-এর নাম; f সবসময় শেষে, তারপরই নাম |
| `-t` | list: ভেতরে কী আছে দেখাও, extract না করে |
| `-x` / `-C` | extract / কোন ফোল্ডারে extract হবে |
| `$(date +%F)` | আজকের তারিখ (2026-10-06) ফাইলনামে বসাও |
| `-f -` | ফাইলের বদলে stdout-এ লেখো, যাতে pipe দিয়ে পাঠানো যায় |
| `\| ssh backup 'cat > app.tgz'` | data সরাসরি অন্য সার্ভারে গিয়ে ফাইল হয়ে যায় |

> 💡 **প্রো টিপ:** মনে রাখো: c = create, x = extract, t = list, z = gzip, v = verbose, f = file।

### gzip / zcat / zgrep

`🟢 বেসিক`

**পূর্ণরূপ:** `gzip` = **G**NU **ZIP** → GNU-এর compression টুল · `zcat` = **Z**ip + **CAT** → .gz ফাইল পড়ো · `zgrep` = **Z**ip + **GREP** → .gz ফাইলে খোঁজো · `gunzip` = **G**NU **UNZIP** → খোলো

**কী করে:** ফাইল compress করে আর extract ছাড়াই compressed log পড়ে।

> **বাস্তব পরিস্থিতি:** ৩ দিন আগের একটা incident-এর তথ্য `app.log.3.gz`-এর মতো rotate হওয়া log-এ আছে। সরাসরি সেগুলোতে খুঁজছ।

**sudo লাগবে?** root-এর log হলে লাগে।

```bash
zgrep "ERROR" /var/log/myapp/app.log.*.gz
zcat access.log.2.gz | awk '{print $1}' | sort | uniq -c | sort -nr | head
gzip -9 big.sql          # max compression
gunzip big.sql.gz
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-9` | `9` = best compression → সর্বোচ্চ সংকোচন |
| `uniq -c` / `sort -nr` | `c` = count → গোনো · `n` = numeric → সংখ্যায় · `r` = reverse → বড় থেকে ছোট |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `zgrep` | .gz ফাইল না খুলেই ভেতরে grep |
| `zcat` | .gz ফাইলের ভেতরের লেখা দেখাও |
| `-9` | সর্বোচ্চ compression (ধীর) |
| `gunzip` | decompress |

> 💡 **প্রো টিপ:** .gz ফাইল পাতায় পাতায় দেখতে `zless`-ও কাজ করে।

### zip / unzip

`🟢 বেসিক`

**পূর্ণরূপ:** `zip` = ZIP → সংকুচিত archive বানাও · `unzip` = UN-ZIP → zip খোলো

**কী করে:** .zip ফাইল তৈরি ও extract করে।

> **বাস্তব পরিস্থিতি:** AWS-এর জন্য Lambda function package করছ, আর একটা vendor-এর release zip খুলছ।

**sudo লাগবে?** system ফোল্ডারে extract করতে লাগে।

```bash
zip -r function.zip handler.py lib/
unzip -l release.zip                 # list contents
unzip -o release.zip -d /opt/vendor
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `zip -r` | `r` = recursive → ফোল্ডারসহ |
| `unzip -l` | `l` = list → ভেতরে কী আছে |
| `unzip -o` | `o` = overwrite → জিজ্ঞেস ছাড়া overwrite |
| `unzip -d` | `d` = destination directory → কোন ফোল্ডারে |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-r` | ফোল্ডারসহ |
| `-l` | list |
| `-o` | overwrite, জিজ্ঞেস ছাড়া |
| `-d` | destination: কোন ফোল্ডারে |

> 💡 **প্রো টিপ:** `-o` প্রশ্ন না করেই overwrite করে, non-interactive script-এ কাজের।

## ১৪. সিকিউরিটি, সার্টিফিকেট ও হার্ডেনিং

TLS, integrity যাচাই, secret আর intrusion শনাক্তকরণ।

### openssl

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `openssl` = **OPEN** **S**ecure **S**ockets **L**ayer → TLS/SSL টুলকিট · `TLS` = **T**ransport **L**ayer **S**ecurity → এনক্রিপ্টেড connection · `CSR` = **C**ertificate **S**igning **R**equest → certificate-এর আবেদন · `x509` = **X.509** standard → certificate-এর মান · `SNI` = **S**erver **N**ame **I**ndication → কোন domain চাই জানানো

**কী করে:** TLS/SSL টেস্ট, certificate পরীক্ষা, key আর CSR তৈরি।

> **বাস্তব পরিস্থিতি:** User রা "certificate expired" error পাচ্ছে। Live সাইটে মেয়াদ দেখছ, তারপর নতুন key/CSR তৈরি করে নিশ্চিত হচ্ছ নতুন cert আর key মিলছে।

**sudo লাগবে?** সাধারণত লাগে না; `/etc/ssl/private`-এর key পড়তে লাগে।

```bash
echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null \
  | openssl x509 -noout -dates -subject -issuer
openssl x509 -in cert.pem -noout -text | less
openssl req -new -newkey rsa:2048 -nodes -keyout ex.key -out ex.csr
openssl x509 -noout -modulus -in cert.pem | md5sum     # must match ...
openssl rsa -noout -modulus -in ex.key | md5sum        # ... this
openssl rand -base64 32                                # strong random secret
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `s_client` | s_client = SSL client → TLS client হিসেবে connect |
| `-connect` | connect → এই host:port-এ যুক্ত হও |
| `-servername` | server name (SNI) → কোন domain-এর cert |
| `-noout` | no output → পুরো cert প্রিন্ট করো না |
| `-dates` / `-subject` / `-issuer` | dates → মেয়াদের তারিখ · subject → cert কার · issuer → কে দিয়েছে |
| `-in` / `-text` | in = input → কোন ফাইল · text → পুরো তথ্য পড়ার মতো করে |
| `req -new -newkey rsa:2048` | req = request → CSR সংক্রান্ত · new → নতুন · newkey → নতুন key, RSA 2048-bit |
| `-nodes` | nodes = No DES → key-এ password (DES encryption) দেবে না |
| `-keyout` / `-out` | key output → key কোথায় save · out = output → CSR কোথায় save |
| `-modulus` | modulus → key-এর গাণিতিক অংশ (মেলানোর জন্য) |
| `rand -base64 32` | rand = random → এলোমেলো · base64 → base64-এ লেখো · 32 = 32 bytes → ৩২ বাইট |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `echo \|` | খালি input দেওয়া হয় যাতে s_client কাজ শেষে নিজে বন্ধ হয় |
| `s_client -connect host:443` | সার্ভারের সাথে TLS connection বানাও |
| `-servername` | SNI: এক IP-তে অনেক সাইট থাকলে কোন সাইটের cert চাই |
| `x509 -noout -dates` | certificate পড়ো; `-noout` = পুরো cert প্রিন্ট নয়; `-dates` = শুরু ও শেষ তারিখ |
| `-subject` / `-issuer` | cert কার জন্য / কে দিয়েছে |
| `req -new -newkey rsa:2048` | নতুন CSR আর ২০৪৮-bit RSA key বানাও |
| `-nodes` | no DES: key-এ password থাকবে না (সার্ভার নিজে পড়তে পারবে) |
| `-modulus \| md5sum` | cert আর key-এর একটা চিহ্ন বের করো; দুটো মিললে জোড়া ঠিক |
| `rand -base64 32` | ৩২ byte এলোমেলো secret |

> 💡 **প্রো টিপ:** Certificate মেয়াদ শেষ হওয়ার ৩০ দিন আগে alert দেবে এমন একটা cron/monitoring check যোগ করো।

### sha256sum / md5sum

`🟢 বেসিক`

**পূর্ণরূপ:** `sha256sum` = **S**ecure **H**ash **A**lgorithm 256 **SUM** → ২৫৬-bit hash checksum · `md5sum` = **M**essage **D**igest 5 **SUM** → MD5 checksum (পুরনো)

**কী করে:** Checksum দিয়ে ফাইলের integrity যাচাই।

> **বাস্তব পরিস্থিতি:** CI pipeline-এ Terraform binary ডাউনলোড করছ, নিশ্চিত হতে হবে এটা নষ্ট বা পরিবর্তিত হয়নি।

**sudo লাগবে?** লাগে না।

```bash
sha256sum terraform_1.9.5_linux_amd64.zip
sha256sum -c SHA256SUMS --ignore-missing
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-c` | `c` = check → তালিকার সাথে মিলিয়ে দেখো |
| `--ignore-missing` | ignore missing → না থাকা ফাইল উপেক্ষা |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `sha256sum ফাইল` | ফাইলের ফিঙ্গারপ্রিন্ট (hash) বের করো |
| `-c SHA256SUMS` | check: তালিকার সাথে মিলিয়ে দেখো |
| `--ignore-missing` | তালিকায় আছে কিন্তু তোমার কাছে নেই এমন ফাইল উপেক্ষা |

> 💡 **প্রো টিপ:** Automation-এ ডাউনলোড করা binary-এর checksum সবসময় যাচাই করো।

### base64

`🟢 বেসিক`

**পূর্ণরূপ:** `base64` = **BASE** **64** → ৬৪টা অক্ষর দিয়ে data লেখা

**কী করে:** base64 encode/decode (এটা encryption নয়)।

> **বাস্তব পরিস্থিতি:** একটা Kubernetes Secret-এর value দুর্বোধ্য দেখাচ্ছে। DB password ঠিক আছে কিনা দেখতে decode করছ।

**sudo লাগবে?** লাগে না।

```bash
kubectl get secret db-secret -o jsonpath='{.data.password}' | base64 -d
echo -n 'mypassword' | base64
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-d` | `d` = decode → আসল রূপে ফেরাও |
| `echo -n` | `n` = no newline → শেষে নতুন লাইন দেবে না |
| `kubectl -o jsonpath` | `o` = output → output format (jsonpath = নির্দিষ্ট field) |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `-d` | decode: আসল লেখায় ফেরাও |
| `echo -n` | শেষে newline যোগ করবে না |
| `-o jsonpath='{...}'` | kubectl output থেকে নির্দিষ্ট field |

> 💡 **প্রো টিপ:** `echo -n` ব্যবহার করো, নইলে secret-এর সাথে একটা newline-ও encode হয়ে যায় আর রহস্যজনকভাবে auth fail করে।

### auth log analysis

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `auth.log` = **AUTH**entication **LOG** → login-এর রেকর্ড · `NF` = **N**umber of **F**ields → লাইনে মোট কলাম

**কী করে:** Brute-force আর সন্দেহজনক login শনাক্ত করা।

> **বাস্তব পরিস্থিতি:** সার্ভার ধীর আর SSH brute force সন্দেহ হচ্ছে। সবচেয়ে বেশি ব্যর্থ login কোন IP থেকে, খুঁজছ।

**sudo লাগবে?** লাগে: `/var/log/auth.log` শুধু root/adm পড়তে পারে।

```bash
grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' \
  | sort | uniq -c | sort -nr | head
# RHEL: /var/log/secure
journalctl -u ssh --since today | grep -c "Failed"
fail2ban-client status sshd
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `uniq -c` | `c` = count → গোনো |
| `sort -nr` | `n` = numeric → সংখ্যায় · `r` = reverse → বড় থেকে ছোট |
| `journalctl -u --since` | `u` = unit → কোন service · since → কখন থেকে |
| `grep -c` | `c` = count → সংখ্যা |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `"Failed password"` | ব্যর্থ login-এর লাইন |
| `$(NF-3)` | NF = মোট কলাম সংখ্যা; শেষ থেকে ৪ নম্বর কলাম = attacker-এর IP |
| `\` (লাইনের শেষে) | কমান্ড পরের লাইনে চলছে |
| `journalctl -u ssh --since today` | আজকের ssh service-এর log |
| `fail2ban-client status sshd` | কোন IP গুলো ban হয়েছে |

> 💡 **প্রো টিপ:** Password auth বন্ধ করো (`PasswordAuthentication no`), root login বন্ধ করো, আর fail2ban ব্যবহার করো।

### SELinux (getenforce / restorecon / setsebool)

`🔴 অ্যাডভান্সড`

**পূর্ণরূপ:** `SELinux` = **S**ecurity-**E**nhanced **Linux** → উন্নত নিরাপত্তার Linux · `restorecon` = **RESTORE** **CON**text → সঠিক label ফিরিয়ে দাও · `setsebool` = **SET** **SE**linux **BOOL**ean → SELinux-এর একটা সুইচ · `AVC` = **A**ccess **V**ector **C**ache → SELinux-এর অনুমতি সিদ্ধান্ত

**কী করে:** RHEL-পরিবারের সিস্টেমে SELinux denial ঠিক করা।

> **বাস্তব পরিস্থিতি:** Rocky Linux-এ file permission একদম ঠিক থাকার পরও nginx 403 / 502 দিচ্ছে। SELinux ব্লক করছে।

**sudo লাগবে?** `getenforce` আর `ls -Z` ছাড়া বাকি সবগুলোতে লাগে।

```bash
getenforce
ausearch -m avc -ts recent                    # see denials
restorecon -Rv /var/www/html                  # fix file contexts
setsebool -P httpd_can_network_connect 1      # allow nginx -> upstream
ls -Z /var/www/html
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `ausearch -m` | `m` = message type → কোন ধরনের বার্তা (avc) |
| `-ts recent` | `ts` = time start → কখন থেকে (recent = সাম্প্রতিক) |
| `restorecon -Rv` | `R` = Recursive → ভেতরের সব · `v` = verbose → বিস্তারিত |
| `setsebool -P` | `P` = Persistent → স্থায়ী |
| `ls -Z` | `Z` = SELinux context → SELinux label দেখাও |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `getenforce` | Enforcing / Permissive / Disabled |
| `ausearch -m avc -ts recent` | সাম্প্রতিক SELinux denial (AVC) গুলো খোঁজো |
| `restorecon -Rv` | ফাইলের SELinux label ঠিক করো; `-R` ভেতরে সব, `-v` বিস্তারিত |
| `setsebool -P` | একটা নিয়ম চালু/বন্ধ; `-P` = স্থায়ী |
| `ls -Z` | ফাইলের SELinux context দেখাও |

> 💡 **প্রো টিপ:** SELinux বন্ধ করে দিও না। Context বা boolean ঠিক করো; `setenforce 0` শুধু দ্রুত টেস্টের জন্য।

## ১৫. শেল প্রোডাক্টিভিটি ও স্ক্রিপ্টিং-এর মূল বিষয়

DevOps engineer রা automate করে। নির্ভরযোগ্য script-এর ভিত্তি এগুলো।

### export / env / printenv

`🟢 বেসিক`

**পূর্ণরূপ:** `export` = **EXPORT** → child প্রসেসেও পাঠাও · `env` = **ENV**ironment → environment variable · `printenv` = **PRINT** **ENV**ironment → variable দেখাও

**কী করে:** Environment variable সেট ও পরীক্ষা করা।

> **বাস্তব পরিস্থিতি:** অ্যাপ `DATABASE_URL` পড়ে। Local-এ চলে, CI-তে fail করে। Environment-এ আসলে কী আছে দেখছ।

**sudo লাগবে?** লাগে না। মনে রাখো: sudo সাধারণত তোমার variable মুছে দেয়; রাখতে `sudo -E`।

```bash
export DATABASE_URL="postgres://app@db:5432/app"
env | grep -i database
printenv PATH
cat /proc/$(pgrep -f app.jar)/environ | tr '\0' '\n'     # env of running process
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `grep -i` | `i` = ignore case → বড়/ছোট হাতের অক্ষর সমান |
| `pgrep -f` | `f` = full → পুরো কমান্ডে খোঁজো |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `export X="..."` | `=`-এর দুপাশে space দেবে না |
| `env \| grep -i database` | সব variable থেকে database খোঁজো |
| `printenv PATH` | শুধু PATH-এর মান |
| `$(pgrep -f app.jar)` | app.jar-এর PID বসাও |
| `tr '\0' '\n'` | null অক্ষরকে newline বানাও, যাতে প্রতিটি variable আলাদা লাইনে আসে |

> 💡 **প্রো টিপ:** `export` ছাড়া সেট করা variable child process দেখতে পায় না।

### Redirection, pipes ও exit codes

`🟢 বেসিক`

**পূর্ণরূপ:** `stdin` / `stdout` / `stderr` = **ST**an**D**ard **IN**put / **OUT**put / **ERR**or → সাধারণ input / output / error স্রোত

**কী করে:** stdout/stderr নিয়ন্ত্রণ আর সফলতা/ব্যর্থতার ভিত্তিতে কমান্ড জোড়া।

> **বাস্তব পরিস্থিতি:** Deploy script-এ শুধু build সফল হলেই service restart করতে চাও, আর অপ্রয়োজনীয় output চুপ রেখে error log রাখতে চাও।

**sudo লাগবে?** লাগে না।

```bash
make build && systemctl restart myapp || echo "build failed"
command > out.log 2>&1      # both stdout and stderr to file
command 2>/dev/null         # discard errors
command >> app.log          # append
echo $?                     # exit code of last command (0 = success)
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `1` / `2` | 1 = stdout → সাধারণ output · 2 = stderr → error output |
| `$?` | `?` = exit status → শেষ কমান্ডের ফলাফল কোড |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `&&` | আগেরটা সফল হলে পরেরটা |
| `\|\|` | আগেরটা ব্যর্থ হলে পরেরটা |
| `> out.log 2>&1` | output ফাইলে, error-ও সেখানে |
| `2>/dev/null` | error ফেলে দাও |
| `>>` | শেষে যোগ করো |
| `$?` | শেষ কমান্ডের exit code |

> 💡 **প্রো টিপ:** ক্রম গুরুত্বপূর্ণ: `> file 2>&1` কাজ করে, `2>&1 > file` stderr-কে ফাইলে পাঠায় না।

### set -euo pipefail ও trap

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `set` = **SET** shell options → shell-এর আচরণ ঠিক করো · `trap` = **TRAP** → ঘটনা ধরো (ফাঁদ) · `mktemp` = **M**a**K**e **TEMP**orary → অস্থায়ী ফাইল/ফোল্ডার বানাও

**কী করে:** Bash script-কে দ্রুত fail করানো আর নির্ভরযোগ্যভাবে পরিষ্কার করা।

> **বাস্তব পরিস্থিতি:** একটা backup script একটা ধাপ fail করার পরও চলতে থাকে আর খালি ফাইল upload করে দিয়েছিল। এখন যেকোনো error-এ থামবে আর temp ফাইল সবসময় মুছবে।

**sudo লাগবে?** লাগে না।

```bash
#!/usr/bin/env bash
set -euo pipefail                    # exit on error, unset var, pipe failure

TMP=$(mktemp -d)
trap 'rm -rf "$TMP"' EXIT            # cleanup no matter how the script ends

pg_dump mydb | gzip > "$TMP/db.sql.gz"
aws s3 cp "$TMP/db.sql.gz" "s3://backups/db-$(date +%F).sql.gz"
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-euo` | `e` = errexit → error-এ বের হয়ে যাও · `u` = nounset → undefined variable-এ error · `o` = option → পরের নামের option চালু করো |
| `pipefail` | pipe fail → pipe-এর যেকোনো অংশ fail হলে পুরোটা fail |
| `mktemp -d` | `d` = directory → ফোল্ডার বানাও |
| `EXIT` | exit → script শেষ হওয়ার মুহূর্ত |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `#!/usr/bin/env bash` | shebang: এই script bash দিয়ে চালাও |
| `-e` | কোনো কমান্ড fail করলেই script থামাও |
| `-u` | undefined variable ব্যবহার করলে error |
| `-o pipefail` | pipe-এর মাঝের কোনো কমান্ড fail করলেও পুরোটা fail ধরো |
| `mktemp -d` | নিরাপদ অস্থায়ী ফোল্ডার বানাও |
| `trap '...' EXIT` | script যেভাবেই শেষ হোক, এটা চলবেই |
| `"$TMP"` | variable-কে quote-এ রাখো যাতে space থাকলেও না ভাঙে |

> 💡 **প্রো টিপ:** প্রতিটি script-এ shellcheck চালাও; production-এর আগেই quoting-এর bug ধরে ফেলে।

### history / alias / Ctrl+R

`🟢 বেসিক`

**পূর্ণরূপ:** `history` = **HISTORY** → কমান্ডের ইতিহাস · `alias` = **ALIAS** → ছদ্মনাম

**কী করে:** বারবার ব্যবহৃত কমান্ড পুনরায় ব্যবহার আর ছোট করা।

> **বাস্তব পরিস্থিতি:** গতকাল একটা লম্বা kubectl কমান্ড চালিয়েছিলে, আবার দরকার; আর শেষ কমান্ডে sudo দিতে ভুলে গেছ।

**sudo লাগবে?** লাগে না।

```bash
history | grep kubectl
!1052                 # rerun history entry 1052
sudo !!               # rerun last command with sudo
# Ctrl+R then type part of the command to search
alias k='kubectl'
alias ll='ls -lah'
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `!!` | `!!` = bang bang → আগের কমান্ড |
| `Ctrl+R` | `R` = Reverse search → উল্টো দিকে খোঁজো |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `!1052` | ইতিহাসের ১০৫২ নম্বর কমান্ড আবার চালাও |
| `!!` | ঠিক আগের কমান্ড |
| `sudo !!` | আগের কমান্ডটা sudo দিয়ে আবার চালাও (sudo দিতে ভুলে গেলে) |
| `Ctrl+R` | ইতিহাসে খোঁজো; টাইপ করতে থাকো |
| `alias k='kubectl'` | এখন `k` লিখলেই kubectl |

> 💡 **প্রো টিপ:** Alias গুলো `~/.bashrc`-এ রাখো যাতে সব session-এ থাকে।

### tmux / screen

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `tmux` = **T**erminal **MU**ltiple**X**er → এক terminal-এ অনেক session · `screen` = **SCREEN** → পুরনো terminal multiplexer

**কী করে:** Connection কেটে গেলেও টিকে থাকে এমন terminal session।

> **বাস্তব পরিস্থিতি:** অস্থির VPN-এ database upgrade করছ। SSH কেটে গেলেও upgrade চলতে হবে আর তুমি আবার যুক্ত হতে পারবে।

**sudo লাগবে?** লাগে না।

```bash
tmux new -s upgrade
# run commands; detach with Ctrl+b then d
tmux ls
tmux attach -t upgrade
screen -S upgrade ; screen -r upgrade
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `tmux new -s` | `s` = session name → session-এর নাম |
| `attach -t` | `t` = target → কোন session |
| `screen -S` / `-r` | `S` = Session name → নাম দাও · `r` = reattach → আবার যুক্ত হও |
| `Ctrl+b d` | `d` = detach → আলাদা হও |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `new -s upgrade` | upgrade নামে নতুন session |
| `Ctrl+b` তারপর `d` | detach: session চলতে থাকবে, তুমি বের হয়ে আসবে |
| `ls` / `attach -t` | session তালিকা / আবার যুক্ত হও |
| `screen -S` / `-r` | নতুন session / আবার যুক্ত হও |

> 💡 **প্রো টিপ:** অভ্যাস করে নাও: production-এ কয়েক মিনিটের বেশি লাগে এমন সবকিছু tmux-এ চালাবে।

### timeout

`🟡 ইন্টারমিডিয়েট`

**পূর্ণরূপ:** `timeout` = **TIME** **OUT** → সময় শেষ হলে থামাও

**কী করে:** নির্দিষ্ট সময়ের বেশি চললে কমান্ড বন্ধ করে দেয়।

> **বাস্তব পরিস্থিতি:** কোনো dependency সাড়া না দিলে তোমার health-check script চিরকাল আটকে থাকে, পুরো CI pipeline ব্লক হয়ে যায়।

**sudo লাগবে?** যে কমান্ড চালাচ্ছ তার উপর নির্ভর করে।

```bash
timeout 10 curl -fs http://localhost:8080/health || echo "unhealthy"
timeout -s KILL 300 ./long_migration.sh
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `curl -fs` | `f` = fail → HTTP error-এ fail · `s` = silent → চুপচাপ |
| `timeout -s KILL` | `s` = signal → কোন signal পাঠাবে (KILL) |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `timeout 10` | ১০ সেকেন্ডের বেশি চললে বন্ধ |
| `-s KILL 300` | ৩০০ সেকেন্ড পরে SIGKILL পাঠাও |

> 💡 **প্রো টিপ:** Exit code 124 মানে timeout কমান্ডটা মেরে ফেলেছে।

## ১৬. অ্যাডভান্সড: কার্নেল টিউনিং, লিমিট ও কন্টেইনারের ভেতরের কথা

সিনিয়র-লেভেলের troubleshooting: যা intermediate আর advanced engineer-কে আলাদা করে।

### ulimit ও limits

`🔴 অ্যাডভান্সড`

**পূর্ণরূপ:** `ulimit` = **U**ser **LIMIT** → user/প্রসেসের সীমা · `nofile` = **N**umber **O**f **FILE**s → খোলা ফাইলের সংখ্যা · `fd` = **F**ile **D**escriptor → খোলা ফাইলের নম্বর

**কী করে:** প্রতি প্রসেসের resource limit, যেমন open file আর process সংখ্যা।

> **বাস্তব পরিস্থিতি:** বেশি load-এ অ্যাপ log করছে "Too many open files" আর নতুন connection নেওয়া বন্ধ করে দিচ্ছে।

**sudo লাগবে?** সীমা কমাতে লাগে না; বাড়াতে (hard limit পর্যন্ত) আর limits.conf এডিটে লাগে।

```bash
ulimit -n                                                # current shell's limit
cat /proc/$(pgrep -f app.jar)/limits | grep "open files"
ls /proc/$(pgrep -f app.jar)/fd | wc -l                  # currently used
```

```text
# /etc/security/limits.conf (login sessions)
myapp  soft  nofile  65535
myapp  hard  nofile  65535

# For systemd services: LimitNOFILE=65535 in the unit file
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `ulimit -n` | `n` = number of open files → কয়টা ফাইল খোলা যাবে |
| `pgrep -f` | `f` = full → পুরো কমান্ডে খোঁজো |
| `wc -l` | `l` = lines → লাইন গোনো |
| `soft` / `hard` | soft limit → সাধারণ সীমা · hard limit → সর্বোচ্চ সীমা |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `ulimit -n` | সর্বোচ্চ কয়টা ফাইল একসাথে খোলা যাবে |
| `/proc/PID/limits` | চলমান প্রসেসের আসল limit |
| `ls /proc/PID/fd \| wc -l` | এখন কয়টা ফাইল খোলা |
| `myapp soft nofile 65535` | user, soft (সাধারণ) / hard (সর্বোচ্চ), কোন জিনিস, মান |

> 💡 **প্রো টিপ:** limits.conf systemd service-এ প্রযোজ্য নয়। Unit ফাইলে `LimitNOFILE` দাও আর daemon-reload করো।

### sysctl

`🔴 অ্যাডভান্সড`

**পূর্ণরূপ:** `sysctl` = **SYS**tem **C**on**T**ro**L** → kernel সেটিং নিয়ন্ত্রণ · `somaxconn` = **SO**cket **MAX** **CONN**ections → connection-এর সর্বোচ্চ queue

**কী করে:** চলমান অবস্থায় kernel parameter পড়া ও টিউন করা।

> **বাস্তব পরিস্থিতি:** বেশি traffic-এর nginx সার্ভার load-এ connection drop করছে; Kubernetes node-এ IP forwarding-ও লাগবে। Kernel setting টিউন করে স্থায়ী করছ।

**sudo লাগবে?** দেখতে লাগে না, বদলাতে লাগে।

```bash
sysctl net.core.somaxconn
sysctl -w net.core.somaxconn=65535
sysctl -w vm.swappiness=10
sysctl --system                      # reload all config files
```

```text
# persist: /etc/sysctl.d/99-tuning.conf
net.core.somaxconn = 65535
net.ipv4.ip_forward = 1
fs.file-max = 2097152
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `-w` | `w` = write → লেখো (বদলাও) |
| `--system` | system → সব config ফাইল লোড করো |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `sysctl নাম` | বর্তমান মান দেখাও |
| `-w` | write: এখনই বদলাও (reboot-এ হারাবে) |
| `/etc/sysctl.d/99-tuning.conf` | স্থায়ী রাখার ফাইল |
| `--system` | সব config ফাইল আবার লোড |
| `somaxconn` / `swappiness` / `ip_forward` | connection-এর queue / swap কতটা ব্যবহার / packet forward করা |

> 💡 **প্রো টিপ:** একবারে একটা parameter বদলাও আর মেপে দেখো। Blog থেকে অন্ধভাবে "tuning" অবস্থা আরও খারাপ করতে পারে।

### /proc filesystem

`🔴 অ্যাডভান্সড`

**পূর্ণরূপ:** `/proc` = **PROC**ess filesystem → প্রসেসের নকল ফাইলসিস্টেম · `VmRSS` = **V**irtual **M**emory **R**esident **S**et **S**ize → আসলে RAM-এ কতটা আছে · `cwd` = **C**urrent **W**orking **D**irectory → বর্তমান ফোল্ডার

**কী করে:** ফাইল আকারে live kernel আর process-এর তথ্য।

> **বাস্তব পরিস্থিতি:** Minimal container image-এ ps, top বা free নেই। তবুও process আর memory-এর বিস্তারিত দরকার।

**sudo লাগবে?** অন্য user-এর প্রসেসের অনেক তথ্য দেখতে লাগে।

```bash
cat /proc/loadavg
cat /proc/meminfo | head
cat /proc/1234/status | grep -E "VmRSS|Threads"
cat /proc/1234/cmdline | tr '\0' ' '
ls -l /proc/1234/cwd          # working directory of the process
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `grep -E` | `E` = Extended regex → `\|` দিয়ে অথবা |
| `ls -l` | `l` = long → বিস্তারিত |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `loadavg` / `meminfo` | load আর memory-এর কাঁচা তথ্য |
| `status \| grep VmRSS` | প্রসেস আসলে কত RAM নিচ্ছে |
| `cmdline \| tr '\0' ' '` | প্রসেস কোন কমান্ড দিয়ে চালু হয়েছিল |
| `cwd` | প্রসেস কোন ফোল্ডারে বসে আছে |

> 💡 **প্রো টিপ:** ps আর free-এর মতো সব টুল আসলে ভেতরে ভেতরে `/proc`-ই পড়ে।

### systemd-cgtop / cgroups

`🔴 অ্যাডভান্সড`

**পূর্ণরূপ:** `cgroup` = **C**ontrol **GROUP** → নিয়ন্ত্রণ দল · `systemd-cgtop` = systemd **C**ontrol **G**roup **TOP** → cgroup অনুযায়ী top

**কী করে:** প্রতিটি control group (service, container)-এর resource ব্যবহার।

> **বাস্তব পরিস্থিতি:** সার্ভার overloaded, কিন্তু এতে অনেক container আর service চলে। কোন cgroup (service) সবচেয়ে বেশি CPU আর memory খাচ্ছে দেখছ।

**sudo লাগবে?** systemd-cgtop-এ পুরো তথ্য দেখতে sudo দাও।

```bash
systemd-cgtop
systemctl status myapp        # shows its cgroup and memory
cat /sys/fs/cgroup/system.slice/myapp.service/memory.current
```

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `systemd-cgtop` | top-এর মতো, তবে প্রতি service/container ধরে |
| `memory.current` | এই service এখন কত byte RAM ব্যবহার করছে |

> 💡 **প্রো টিপ:** Container আসলে cgroup (resource limit) আর namespace (isolation)-এর ভেতরে চলা সাধারণ process।

### nsenter

`🔴 অ্যাডভান্সড`

**পূর্ণরূপ:** `nsenter` = **N**ame**S**pace **ENTER** → namespace-এ প্রবেশ করো

**কী করে:** অন্য process-এর namespace-এর ভেতরে কমান্ড চালায়।

> **বাস্তব পরিস্থিতি:** একটা container অন্য service-এ পৌঁছাতে পারছে না, আর এর image-এ কোনো networking টুল নেই। Host থেকে শুধু এর network namespace-এ ঢুকে host-এর টুল ব্যবহার করছ।

**sudo লাগবে?** সবসময় লাগে।

```bash
PID=$(docker inspect -f '{{.State.Pid}}' my_container)
nsenter -t $PID -n ss -tlnp
nsenter -t $PID -n ip a
nsenter -t $PID -n curl -v http://other-service:8080
```

**অপশনের পূর্ণরূপ (অক্ষরে অক্ষরে)**

| অপশন | অক্ষর = পূর্ণরূপ → মানে |
|---|---|
| `docker inspect -f` | `f` = format → output-এর format (Go template) |
| `-t` | `t` = target → কোন PID-এর namespace |
| `-n` | `n` = network namespace → শুধু network জগতে |
| `ss -tlnp` | `t` = TCP · `l` = listening · `n` = numeric → সংখ্যায় · `p` = process → প্রোগ্রাম |
| `curl -v` | `v` = verbose → বিস্তারিত |

**আরও ব্যাখ্যা (চিহ্ন, মান ও কৌশল)**

| চিহ্ন / অংশ | মানে |
|---|---|
| `docker inspect -f '{{.State.Pid}}'` | container-এর মূল প্রসেসের host PID |
| `-t $PID` | target: কোন প্রসেসের namespace |
| `-n` | শুধু network namespace-এ ঢোকো; বাকি টুল host-এর |

> 💡 **প্রো টিপ:** Distroless বা minimal image Docker/Kubernetes node-এ ডিবাগ করতে দারুণ শক্তিশালী।

## ১৭. বাস্তব Incident Playbook

আসল outage-এর সময় কমান্ডগুলো কীভাবে একসাথে কাজে লাগে। উপর থেকে নিচে যাও; প্রতিটি ধাপ কারণটা আরও সংকীর্ণ করে আনে।

### 🚨 ওয়েবসাইট down (HTTP 502/504)

```bash
systemctl status nginx myapp                     # are services running?
ss -tlnp | grep -E ':80|:443|:8080'              # are they listening?
curl -I http://localhost:8080/health             # does the app answer locally?
journalctl -u myapp --since "15 min ago" | tail -50
tail -n 100 /var/log/nginx/error.log             # 'connect() failed', 'upstream timed out'
df -h; free -h; uptime                           # disk full? out of memory? overloaded?
dmesg -T | grep -i oom                           # was the app OOM killed?
```

### 🚨 Disk 100% ভরা

```bash
df -h ; df -i                                    # space or inodes?
du -h --max-depth=1 / 2>/dev/null | sort -rh | head
find / -xdev -type f -size +500M 2>/dev/null
lsof +L1                                         # deleted files still held open
journalctl --vacuum-size=500M
docker system df ; docker system prune -f        # if Docker is used
apt clean                                        # package cache
```

### 🚨 বেশি CPU / load average

```bash
uptime ; nproc                                   # load vs cores
top                                              # press P, then 1: which process, which core
ps -eo pid,user,%cpu,etime,cmd --sort=-%cpu | head
vmstat 1 5                                       # r column, wa column
pidstat 1 5                                      # per-process CPU over time (sysstat)
strace -c -p <PID>                               # what is it doing?
```

### 🚨 অ্যাপ database-এ connect করতে পারছে না

```bash
dig +short db.internal                           # DNS resolves?
nc -zv db.internal 5432                          # port reachable? timeout vs refused
ip route get <db-ip>                             # correct route/interface?
ss -tan | grep 5432 | awk '{print $1}' | sort | uniq -c    # pool exhausted?
grep -i "connection" /var/log/myapp/app.log | tail
# then: security groups / NACL / pg_hba.conf / credentials
```

### 🚨 সার্ভার ধীর, memory-এর চাপ

```bash
free -h                                          # look at 'available' and swap
vmstat 1 5                                       # si/so > 0 = swapping
ps aux --sort=-%mem | head
dmesg -T | grep -iE "oom|killed"
cat /proc/<PID>/status | grep VmRSS
sar -r                                           # memory trend history
```

## ১৮. কমন ইন্টারভিউ প্রশ্ন

**প্রশ্ন ১. Hard link আর soft link-এর পার্থক্য কী?**
Hard link একই inode-এর আরেকটা নাম; মূল ফাইল মুছলেও টিকে থাকে, তবে অন্য filesystem-এ যেতে পারে না। Symlink একটা path-কে নির্দেশ করে; target মুছলে ভেঙে যায়, আর অন্য filesystem-এও যেতে পারে।

**প্রশ্ন ২. df বলছে disk ভরা কিন্তু du অনেক কম দেখাচ্ছে। কেন?**
কোনো process এখনও একটা মুছে ফেলা ফাইল খুলে রেখেছে। `lsof +L1` দিয়ে খুঁজে সেই process restart করো (বা `/proc/PID/fd` দিয়ে truncate করো)।

**প্রশ্ন ৩. SIGTERM আর SIGKILL-এর পার্থক্য কী?**
SIGTERM (15) process-কে বন্ধ হতে বলে আর পরিষ্কার করার সুযোগ দেয়; এটা catch করা যায়। SIGKILL (9) kernel সাথে সাথে কার্যকর করে, catch বা উপেক্ষা করা যায় না।

**প্রশ্ন ৪. Load average মানে কী?**
১, ৫ আর ১৫ মিনিটে গড়ে কতগুলো process চলছে বা অপেক্ষা করছে (CPU বা uninterruptible I/O-এর জন্য)। CPU core সংখ্যার সাথে তুলনা করো।

**প্রশ্ন ৫. কোন process port 8080 ব্যবহার করছে কীভাবে খুঁজবে?**
`ss -tlnp | grep 8080` অথবা `lsof -i :8080`।

**প্রশ্ন ৬. Inode কী?**
একটা data structure যেটা ফাইলের metadata (owner, permission, size, block pointer) রাখে, কিন্তু নাম রাখে না। Inode ফুরিয়ে গেলে জায়গা খালি থাকলেও নতুন ফাইল বানানো যায় না।

**প্রশ্ন ৭. chmod 755 আর 640 ব্যাখ্যা করো।**
755 = owner rwx, group r-x, others r-x। 640 = owner rw-, group r--, others-এর কোনো access নেই।

**প্রশ্ন ৮. Script হাতে চালালে চলে কিন্তু cron-এ fail করে। কেন?**
Cron খুব সীমিত environment-এ চলে: আলাদা PATH, profile নেই, আলাদা working directory আর user। Absolute path দাও আর `>> log 2>&1` দিয়ে output log করো।

**প্রশ্ন ৯. Zombie process কী?**
এমন process যেটা শেষ হয়ে গেছে কিন্তু parent এখনও তার exit status পড়েনি। একটা PID entry ছাড়া কোনো resource খায় না। Parent ঠিক করো বা মেরে ফেলো, তখন init দত্তক নিয়ে zombie পরিষ্কার করবে।

**প্রশ্ন ১০. "connection timed out" আর "connection refused" কীভাবে troubleshoot করবে?**
Timed out: packet drop হচ্ছে, সাধারণত firewall, security group বা routing। Refused: host উত্তর দিয়েছে কিন্তু ওই port-এ কেউ listen করছে না, তাই service আর তার bind address দেখো।
